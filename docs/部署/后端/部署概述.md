### 一、概述

> 📖 [Spring Boot 官方文档 - 部署](https://docs.spring.io/spring-boot/reference/packaging.html) ｜ [Oracle - Java 平台安装](https://docs.oracle.com/en/java/javase/17/install/overview-jdk-installation.html)

后端部署，指的是把**打包好的 Java 应用（通常是一个 Jar 包）放到服务器上，让它作为一个持续运行的进程对外提供服务**，用户通过域名或 IP 访问它背后的接口。

大白话：前端部署是「搬静态文件」，后端部署是「**养一个活的程序**」——这个程序要有人管它的死活（崩了自动拉起）、开机自启、日志落盘、平滑升级，这些正是后端部署比前端多出来的事。

| 你将学到 | 说明 |
| --- | --- |
| 后端部署的本质 | 让 Jar 包变成受监管的常驻服务 |
| 部署前的准备 | 服务器、JDK、安全、配置分离 |
| 标准流程 | 打包 → 上传 → 启动 → 验证 → 守护 |
| 常见方式 | systemd / Docker / K8s |

> 💡 **提示：** 本系列是一份完整的「Java 上服务器」路线图。每一篇解决一个环节，可按顺序通读，也可按需查阅。

### 二、后端部署的本质：常驻服务

#### 1. 与前端部署的本质区别

| 对比项 | 前端部署 | 后端部署 |
| --- | --- | --- |
| 产物 | 静态文件（HTML/CSS/JS） | 可执行 Jar 包 |
| 本质 | 托管文件，请求来了返回文件 | 运行程序，请求来了执行逻辑 |
| 运行环境 | 不需要（浏览器执行） | 需要 JDK/JRE |
| 生命周期 | 文件放好即完成 | 进程要持续存活、崩了要拉起 |
| 关心的点 | 路由、缓存、跨域、HTTPS | 进程守护、内存、日志、端口、安全 |

#### 2. 一图看懂后端部署全景

```
本地开发机                          云服务器
┌────────────────┐    上传 Jar   ┌─────────────────────────────┐
│ mvn clean      │ ────────────▶ │ ① 开放端口（安全组+防火墙）    │
│ package        │    (scp)      │ ② 安装 JDK                   │
└────────────────┘               │ ③ 创建专用用户/目录            │
                                 │ ④ systemd 托管 Jar 进程       │
                                 │ ⑤ 日志/备份/监控               │
                                 │ ⑥ Nginx 反向代理（可选）       │
                                 └─────────────────────────────┘
```

> 💡 **提示：** 后端部署的核心难点不在「把 Jar 传上去」，而在**进程的生老病死**：崩了谁拉起？重启后谁启动？停机怎么不丢请求？本系列的核心就是回答这三问。

### 三、标准部署流程总览

```
① 准备服务器          买云服务器、配安全组、SSH 免密登录
        ↓
② 安装运行环境        JDK 版本与项目一致、配置 JAVA_HOME
        ↓
③ 安全加固            专用用户、密钥登录、最小端口开放
        ↓
④ 打包               mvn clean package，多环境配置分离
        ↓
⑤ 上传               scp / rsync
        ↓
⑥ 启动               java -jar 验证能跑 → 再交给 systemd
        ↓
⑦ 验证               健康检查、日志确认、外部访问
        ↓
⑧ 守护               systemd 开机自启 + 崩溃自动重启
        ↓
⑨ 后续运维           日志轮转、监控告警、平滑发布
```

### 五、总结

后端部署 = **一次打包 + 一条上传命令 + 一个 systemd 服务**。把流程跑通只要半小时，但生产级部署需要把每一环做扎实：安全上「最小开放」，进程上「交给守护」，日志上「落盘可查」，发布上「可回滚」。后续各篇逐一展开。
