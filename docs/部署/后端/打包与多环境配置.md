### 一、概述

> 📖 [Spring Boot Maven Plugin 官方文档](https://docs.spring.io/spring-boot/maven-plugin/index.html) ｜ [Spring Boot - Externalized Configuration](https://docs.spring.io/spring-boot/reference/features/external-config.html)

部署前的最后一道本地工序是**打包**：把项目编译成服务器能直接运行的 Jar。而配套的**多环境配置**决定了同一个 Jar 能否在开发、测试、生产之间「一键切换」——这是部署质量高低的第一道分水岭。

大白话：打包就像**把整头骆驼打包成一只旅行箱**——Spring Boot 的「Fat Jar」把你的代码和所有依赖（几百个 jar）都塞进一个文件，服务器上有 Java 就能跑。多环境配置则是「**同一只箱子，到不同地方开不同的夹层**」：开发连本地库，生产连线上库，箱子不用换。

| 你将学到 | 说明 |
| --- | --- |
| Fat Jar 是什么 | 一个 Jar 装下所有依赖 |

| 多环境 Profile | dev/test/prod 一套代码多套配置 |
| 打包检查清单 | 上传前确认什么 |

### 二、Fat Jar：Spring Boot 的打包产物

#### 1. 为什么需要它

传统 Java 项目部署要：上传你的代码 jar + 几百个依赖 jar + 手动拼 `classpath`。Spring Boot 用 `spring-boot-maven-plugin` 的 `repackage` 能力，把所有依赖**嵌进一个可执行 Jar**：

```
myapp-1.0.0.jar（Fat Jar）
├── META-INF/                      ← 清单：Main-Class 指向启动器
├── BOOT-INF/
│   ├── classes/                   ← 你写的代码、配置文件
│   └── lib/                       ← 全部依赖 jar（几百个）
└── org/springframework/boot/loader/   ← Spring Boot 类加载器
```

#### 2. 生成它

```xml
<!-- pom.xml 确认有这个插件（spring-boot-starter-parent 默认已绑定 repackage） -->
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
```

```bash
# 标准打包命令：清理 → 编译 → 测试 → repackage
mvn clean package

# 生产部署常用：跳过测试加快速度（⚠️ 测试应在 CI 阶段跑过）
mvn clean package -DskipTests
```

打包完成后，`target/` 下：

```
target/
├── myapp-1.0.0.jar            ← ✅ 上传这个（可执行 Fat Jar）
└── myapp-1.0.0.jar.original   ← 原始薄 Jar，repackage 改名而来，不用管
```

> 💡 **提示：** `-DskipTests` 只跳过**执行**测试（代码仍编译）；`-Dmaven.test.skip=true` 连编译都跳。紧急修复想最快出包用后者，但**别让跳过测试成为习惯**。

### 三、多环境配置（Profile）

#### 1. 问题：一套配置走天下必然出事

数据库地址、Redis 密码、第三方密钥——开发环境和生产环境必然不同。把生产配置硬编码在 `application.yml` 里，要么本地跑不起来，要么生产配错库。

#### 2. 方案：按环境拆分配置文件

```
src/main/resources/
├── application.yml               ← 公共配置（各环境相同的）
└── application-dev.yml           ← 开发环境差异项
└── application-prod.yml          ← 生产环境差异项
```

```yaml
# application.yml（公共）
spring:
  application:
    name: myapp
  profiles:
    active: dev        # 本地默认 dev；生产用启动参数覆盖

# 通用项：数据源驱动、MyBatis 配置、线程池大小……
```

```yaml
# application-prod.yml（生产差异项）
spring:
  datasource:
    url: jdbc:mysql://prod-db-host:3306/mydb?useSSL=true
    username: ${DB_USER}      # ✅ 敏感信息用环境变量注入，不写死在 Jar 里
    password: ${DB_PASSWORD}
server:
  port: 8080
```

#### 3. 三种激活方式（优先级从低到高）

```bash
# 方式一：配置文件里写死（适合本地开发）
spring.profiles.active=dev

# 方式二：命令行参数（部署常用）
java -jar myapp.jar --spring.profiles.active=prod

# 方式三：环境变量（systemd/Docker 场景推荐）
export SPRING_PROFILES_ACTIVE=prod
java -jar myapp.jar
```

> ⚠️ **注意：** Jar 包里的 `application.yml` 是**打包时快照**，生产上想改配置必须重新打包。补救办法：Spring Boot 会自动读取 **Jar 所在目录**下的 `config/application.yml` 和 `application.yml`（外部配置优先于包内），生产上可以把可变配置抽到外部文件，改完重启即生效。

### 四、生产配置的额外建议

```yaml
# application-prod.yml 中的生产级配置示例
server:
  port: 8080
  shutdown: graceful                      # ✅ 优雅停机：停机时先处理完存量请求（Spring Boot 2.3+）
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s      # 优雅停机最长等待时间，默认 30s
logging:
  file:
    name: /var/log/myapp/app.log         # ✅ 日志落盘，别只打控制台
  logback:
    rollingpolicy:
      max-file-size: 50MB                # 单文件上限，防止日志撑爆磁盘
      max-history: 30                    # 保留 30 天
      total-size-cap: 5GB                # ✅ 日志总量保险丝，必配（与 max-history 配合生效）
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics     # Actuator 默认只暴露 health，按需补充
  endpoint:
    health:
      show-details: never                # 健康详情不对外展示（默认行为，显式声明更清晰）
```

> ⚠️ **注意：** Actuator 的 `env`、`heapdump` 等端点会泄露敏感信息，**永远不要**配置 `include: "*"` 暴露到公网。需要监控指标时，配合认证与内网访问使用。

### 五、打包检查清单（上传前过一遍）

| 检查项 | 命令/方法 |
| --- | --- |
| 版本号对不对 | `pom.xml` 的 `<version>` 是否本次发布的版本 |
| 编译目标版本 | `java.version` 与服务器 JDK 匹配 |
| 生产 Profile 无硬编码密码 | `application-prod.yml` 敏感项用 `${ENV}` 占位 |
| 本地跑一遍 prod 配置 | `--spring.profiles.active=prod` 连测试库验证 |
| 产物存在且完整 | `target/*.jar` 存在，大小合理（几十 MB 量级） |
| 记录构建信息 | 留存 git commit id，出问题能对上版本 |

### 六、注意事项汇总

| 类别 | 注意事项 |
| --- | --- |
| 🔴 别把生产密码打进 Jar | 反编译 Fat Jar 即可看到明文；用环境变量或配置中心 |
| 上传 `.jar` 而非 `.jar.original` | 前者是可执行 Fat Jar，后者是没有依赖的薄 Jar |
| 外部配置覆盖包内配置 | 生产可变配置放 Jar 同级 `config/` 目录，免重打包 |
| 优雅停机要显式开启 | `server.shutdown=graceful` 非默认值，不配则直接掐断请求 |
| 日志必须落盘 | 只输出到控制台时，systemd 场景看 `journalctl`，但文件更利于轮转与采集 |

### 七、总结

打包环节的要点：**一个命令**（`mvn clean package -DskipTests`）、**一个产物**（Fat Jar）、**一套环境隔离**（Profile + 外部配置 + 环境变量注入敏感信息）。箱子打包好了，接下来把它运上服务器：[[上传与启动]]。
