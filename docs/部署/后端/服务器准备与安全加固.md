### 一、概述

> 📖 [OpenSSH 官方文档](https://www.openssh.com/manual.html) ｜ [UFW - Ubuntu 官方文档](https://help.ubuntu.com/community/UFW)

服务器是 Java 应用的「家」。部署第一步不是写代码，而是**准备好一台安全、可远程管理的服务器**：买机器、配安全组、SSH 免密登录、建专用用户、关掉多余的门。

大白话：服务器就是你在云上的「**独栋房子**」，安全组是「小区门禁」，SSH 是「你家大门」，root 用户是「万能钥匙」。门禁不放行，钥匙再好也进不来；大门只用密码锁，早晚被撬。这一篇就是把「门禁、大门、钥匙」都配好。

| 你将学到 | 说明 |
| --- | --- |
| 购买与选型 | 云服务器配置怎么选 |
| 安全组 | 云平台层面的端口门禁 |
| SSH 免密登录 | 密钥对、禁用密码登录 |
| 安全加固 | 专用用户、防火墙、fail2ban |

> ⚠️ **注意：** 云主机的安全是**双层门禁**：云平台安全组 + 操作系统防火墙，两层都要放行，缺一不可。这是新手部署「连不上」的最常见原因。

### 二、购买云服务器与选型

#### 1. 配置怎么选

| 场景 | 参考配置 | 说明 |
| --- | --- | --- |
| 学习/测试 | 1 核 2G | 跑一个 Spring Boot 单体足够（JVM 限制在 512m~1g） |
| 小型生产 | 2 核 4G | 单体应用 + MySQL + Nginx 同机可撑，但建议拆分 |
| 正规生产 | 4 核 8G 起 | 应用与数据库分机部署，留出余量 |

> 💡 **提示：** JVM 是内存大户，`-Xmx` 给多大，堆外内存、元空间还要再吃 30%~50%。**2G 内存的机器不要把堆开到 1.5g**，容易被系统 OOM 杀掉进程。

#### 2. 系统选择

主流选择是 **Ubuntu 22.04 LTS** 或 **AlmaLinux / Rocky Linux**（CentOS 替代品）。本系列命令以 Ubuntu（apt + ufw）为主，CentOS 系（yum/dnf + firewalld）给出对应写法。

### 三、配置安全组（云平台门禁）

安全组是云平台提供的**虚拟防火墙**，在流量到达你的服务器**之前**就过滤。以开放 SSH（22 端口）为例：

**阿里云**：ECS 控制台 → 实例 → 安全组 → 配置规则 → 入方向添加：

| 授权策略 | 协议类型 | 端口范围 | 授权对象 |
| :---: | :---: | :---: | :---: |
| 允许 | 自定义 TCP | 22/22 | 你的 IP/32（推荐）或 0.0.0.0/0（不安全） |

**腾讯云**：CVM 控制台 → 安全组 → 修改规则 → 入站规则添加「来源 + 协议端口（TCP:22）+ 允许」。

规则立即生效，无需重启服务器。

> ⚠️ **注意：** 安全组规则是**立即生效**的，改错了会把自己锁在门外。开放 22 端口时授权对象尽量填**自己的出口 IP**，不要图省事填 `0.0.0.0/0`——全网都可以尝试连你的 SSH。

### 四、SSH 免密登录

#### 1. 原理

SSH 支持两种认证：**密码**（可被暴力破解）和**密钥对**（私钥在本地、公钥放服务器，数学上无法伪造）。生产服务器应只用密钥登录。

```
本地生成一对钥匙：
  id_ed25519      私钥（留在本地，绝不外传）
  id_ed25519.pub  公钥（贴到服务器的 ~/.ssh/authorized_keys）

登录时：服务器出一张"数学考题"，能用私钥答出来的就是主人本人。
```

#### 2. 操作步骤

```bash
# ① 本地生成密钥对（-t 指定算法，ed25519 更现代更安全）
ssh-keygen -t ed25519 -C "dyc@laptop"
# 一路回车即可；给私钥设置 passphrase 更安全（每次使用需输入）

# ② 把公钥追加到服务器的 authorized_keys（一条命令搞定）
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@服务器IP

# ③ 验证：不输密码直接登进去
ssh user@服务器IP
```

#### 3. 关键权限（最容易踩的坑）

SSH 对权限有**硬校验**（StrictModes），权限不对会**静默拒绝密钥登录**：

| 路径 | 权限 | 归属 |
| --- | :---: | :---: |
| `~/.ssh` | `700` | 该用户 |
| `~/.ssh/authorized_keys` | `600` | 该用户 |
| 私钥（本地 `id_ed25519`） | `600` | 自己 |

```bash
# 服务器上修复权限（root 执行）
chown -R user:user /home/user/.ssh
chmod 700 /home/user/.ssh
chmod 600 /home/user/.ssh/authorized_keys
```

> ⚠️ **注意：** 密钥登录失败且不提示密码时，九成是权限问题。用 `ssh -v user@host` 看详细握手过程定位；服务器端看 `sudo tail /var/log/auth.log`（Ubuntu）。

#### 4. 禁用密码登录（加固完成后再做）

```bash
# 编辑服务器上的 /etc/ssh/sshd_config
PasswordAuthentication no
PermitRootLogin no          # 禁止 root 直接登录，统一走普通用户 + sudo

# 重启 SSH 服务（Ubuntu 服务名是 ssh，CentOS 是 sshd）
sudo systemctl restart ssh    # Ubuntu/Debian
# sudo systemctl restart sshd   # CentOS/RHEL
```

> 🔴 **严重警告：** 改这一步之前，**务必先开另一个终端验证密钥登录正常**。配置错了又禁了密码，谁也登不上去了（云控制台的 VNC 救援通道是最后的后悔药）。

### 五、创建专用用户（最小权限原则）

应用**不要用 root 跑**。root 下的应用一旦被打穿（如反序列化漏洞），攻击者直接拿到整台机器。

```bash
# ① 创建专用用户（-m 建家目录，-s 指定 shell；不给 sudo 权限）
sudo useradd -m -s /bin/bash appuser
sudo passwd appuser   # 设置密码备用（也可锁掉密码登录）

# ② 创建应用目录并归属该用户
sudo mkdir -p /opt/myapp
sudo chown -R appuser:appuser /opt/myapp
```

| 原则 | 做法 | 为什么 |
| --- | --- | --- |
| 应用跑在专用用户下 | systemd 里 `User=appuser` | 被攻破只影响该用户能碰的文件 |
| 登录用个人账号 | 每人一个账号 + sudo 提权 | 操作可追溯，出事能定位到人 |
| 应用目录最小授权 | 只有 `appuser` 可写 `/opt/myapp` | 其他用户（含 www-data）改不了 Jar |

### 六、操作系统防火墙

安全组之外，系统内部再设一道墙。只放行确定需要的端口。

```bash
# Ubuntu（ufw）
sudo ufw allow 22/tcp       # SSH，必须先放行再 enable，否则把自己锁外面
sudo ufw allow 80/tcp       # HTTP（Nginx 用）
sudo ufw allow 443/tcp      # HTTPS
sudo ufw enable             # 启用
sudo ufw status verbose     # 查看规则

# CentOS / RHEL（firewalld）
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
sudo firewall-cmd --list-all
```

> 💡 **提示：** 注意 **8080 这种应用端口不需要对公网开放**——通常由 Nginx 监听 80/443 再转发给本机的 8080。应用端口只暴露在内网（`127.0.0.1:8080`），公网面越小越安全。

### 七、可选：fail2ban 防暴力破解

```bash
sudo apt install fail2ban -y    # Ubuntu
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd   # 查看被封 IP
```

fail2ban 监控 SSH 登录日志，**多次失败的 IP 自动封禁**一段时间，是密码登录时代的救星；纯密钥登录后风险大减，可按需安装。

### 八、注意事项汇总

| 类别 | 注意事项 |
| --- | --- |
| 🔴 锁门之前先确认有钥匙 | 禁用密码/root 登录**前**，先验证密钥可登录 |
| 双层门禁 | 云安全组 + 系统防火墙**都要**放行，少一层就不通 |
| 最小开放 | 只开 22/80/443；应用端口走内网或反代 |
| 密钥权限 | `.ssh` 700、`authorized_keys` 600、私钥 600，权限错则登录静默失败 |
| 别用 root 跑应用 | 专用用户 + 最小授权，爆炸半径可控 |
| 留后路 | 云控制台的 VNC/WebShell 是锁门后的救援通道，先确认能用 |
