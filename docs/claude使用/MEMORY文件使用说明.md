# MEMORY.md 使用说明

> 📚 **官方文档**：[Claude Code Memory](https://code.claude.com/docs/en/memory)

## 什么是 MEMORY.md

`MEMORY.md` 是**记忆系统的索引文件**，你可以把它理解为"记忆目录"或"知识清单"。它记录了所有记忆文件的入口，让 Claude 能够快速找到之前存储的重要信息。

> **通俗理解**：就像一本书的目录，告诉你每一章在哪一页。`MEMORY.md` 告诉 Claude 各种记忆（用户偏好、项目背景、反馈记录等）存储在哪些文件中。

## 文件位置

```
~/.claude/projects/<项目路径编码>/memory/MEMORY.md
```

- 该索引随记忆目录在每次会话开始时**自动加载**进上下文
- 具体记忆文件只有在 Claude 判断相关时才会读取
- 记忆文件的详细格式见 [memory/ 目录使用说明](./memory目录使用说明.md)

## 为什么需要 MEMORY.md

### 问题场景

在与 Claude 的长期协作中，会产生大量需要记住的信息：
- 用户的角色和偏好
- 项目背景和目标
- 用户的反馈和指导
- 外部资源链接

这些信息分散在不同的文件中，`MEMORY.md` 提供了一个集中管理的入口。

### 解决方案

通过 `MEMORY.md`，Claude 可以：
1. 快速找到相关的记忆文件
2. 了解有哪些可用的记忆
3. 在需要时查阅具体信息

## 文件格式

### 基本结构

```markdown
# 记忆索引

## 用户记忆
<!-- 关于用户的信息 -->

## 反馈记忆
<!-- 用户的反馈和指导 -->

## 项目记忆
<!-- 项目相关的信息 -->

## 参考记忆
<!-- 外部资源链接 -->
```

### 索引条目格式

每行一条，格式为 `- [标题](文件名.md) — 一句话描述`：

```markdown
- [记忆标题](文件名.md) — 简短描述
```

> **注意**：索引描述要简洁（一句话以内），它的作用是让 Claude 快速判断"要不要去读这个文件"。

## 索引分类说明

`MEMORY.md` 通常按记忆类型分为四组，与记忆文件的 `metadata.type` 字段对应：

| 分类 | type 值 | 记录内容 | 文件命名 |
|------|---------|----------|----------|
| 用户记忆 | `user` | 角色、技术栈、偏好 | `user_*.md` |
| 反馈记忆 | `feedback` | 对工作方式的纠正与确认 | `feedback_*.md` |
| 项目记忆 | `project` | 目标、约束、进行中的工作 | `project_*.md` |
| 参考记忆 | `reference` | 外部链接、文档、面板 | `reference_*.md` |

## 完整示例

```markdown
# 记忆索引

## 用户记忆

- [用户角色](user_role.md) — 前端工程师，5 年经验
- [技术栈](user_stack.md) — 精通 Vue/TypeScript，正在学习 Rust
- [文档结构偏好](doc-structure-preference.md) — 生成文档时按知识点分类成单独文件

## 反馈记忆

- [测试要求](feedback_testing.md) — 必须为所有功能编写测试
- [提交规范](feedback_commit.md) — 使用 Conventional Commits 格式

## 项目记忆

- [项目目标](project_goals.md) — 电商管理后台重构

## 参考记忆

```

## 编写规范

### 1. 分类清晰

将记忆按类型分组，便于查找：

```markdown
## 分类名称
- [记忆标题](文件.md) — 描述
```

### 2. 描述简洁

描述控制在一句话以内：

```markdown
# ✅ 好的描述
- [测试要求](testing.md) — 覆盖率不低于 80%，使用 Vitest

# ❌ 不好的描述
- [测试要求](testing.md) — 这个文档记录了我们项目对测试的所有要求，包括单元测试、集成测试和端到端测试，覆盖率要求是不低于百分之八十，使用的测试框架是 Vitest，还有...
```

### 3. 链接准确

确保链接指向正确的文件，使用相对于 memory 目录的文件名：

```markdown
# ✅ 正确
- [角色](user_role.md)

# ❌ 错误
- [角色](./memory/user_role.md)
```

### 4. 索引与文件保持同步

新增、更新、删除记忆文件时，同步维护索引条目。索引中出现指向不存在文件的链接是常见问题，需要定期检查。

## 工作流程

### 创建新记忆

```
1. 创建记忆文件
   → 在 memory/ 目录创建新的 .md 文件（含 frontmatter）

2. 编写记忆内容
   → 按照记忆模板编写内容

3. 更新索引
   → 在 MEMORY.md 中添加索引条目
```

### 删除记忆

```
1. 删除记忆文件
   → 删除对应的 .md 文件

2. 更新索引
   → 从 MEMORY.md 中移除条目

3. 检查引用
   → 确保没有其他记忆引用该文件
```

### 更新记忆

```
1. 直接修改记忆文件
   → 更新过时的信息

2. 检查索引
   → 确认索引描述是否准确
```

## 最佳实践

### 1. 及时记录

当以下情况发生时，立即创建记忆：
- 用户说"记住这个"
- 用户纠正某个做法
- 了解到重要的项目背景
- 发现有价值的外部资源

### 2. 定期清理

定期（如每月）检查记忆：
- 删除过时的记忆
- 更新不再准确的信息
- 合并重复的记忆

### 3. 一文件一事

每个记忆文件只记录一个事实，方便单独更新和删除，避免"大而全"的记忆文件难以维护。

## 与 memory/ 目录的关系

```
~/.claude/projects/<项目>/memory/
├── MEMORY.md              # 索引/目录（每次会话自动加载）
├── user_role.md           # 实际记忆内容
├── user_stack.md          # 实际记忆内容
└── feedback_testing.md    # 实际记忆内容
```

- **MEMORY.md**：是目录，告诉你有什么记忆
- **各 .md 文件**：是记忆的实际内容

记忆文件本身的 frontmatter 格式与编写规范见 [memory/ 目录使用说明](./memory目录使用说明.md)。

## 常见问题

### Q：MEMORY.md 和各记忆文件有什么区别？

**A**：`MEMORY.md` 是索引，记录"有哪些记忆"；各 `.md` 文件是记忆内容，记录"记忆的具体信息"。就像书本的目录和正文。

### Q：哪些信息应该记忆？

**A**：应该记忆的是：
- 跨会话需要的信息（用户偏好、项目背景）
- 不容易从代码中获取的信息（团队约定、业务规则）
- 需要长期保存的反馈（编码风格、工作流程）

不需要记忆：
- 可以从代码分析出的信息（目录结构、技术栈）
- 临时性的信息（当前的 bug、待办事项）

### Q：记忆可以更新吗？

**A**：可以。当信息变化时，直接更新对应的记忆文件，同时检查 `MEMORY.md` 中的描述是否仍然准确。

### Q：如何避免记忆过多导致混乱？

**A**：
1. 定期清理过时的记忆
2. 使用清晰的分类和命名
3. 保持描述简洁
4. 合并相似的记忆
