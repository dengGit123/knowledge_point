### 一、概述

**浏览器串口通信（Web Serial API）** 是一种让网页直接与串口设备（如 Arduino、传感器、工业控制器等）进行数据交换的 Web 标准 API。以前这类操作必须依赖原生应用或浏览器插件，而现在通过 Web Serial API，纯 JavaScript 就能在浏览器中**读取和写入串口数据**，无需安装任何额外软件。

> 📖 [Web Serial API - MDN](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Serial_API) | [Web Serial API 规范 - W3C](https://wicg.github.io/serial/)

### 二、基本概念与核心原理

#### 1. 什么是串口通信

**串口通信（Serial Communication）** 是一种设备间**逐位（bit by bit）** 传输数据的方式。想象一条单行道，数据车辆一辆接一辆地依次通过——与之对应的是"并行通信"，相当于多车道同时通行。

常见的串口设备：

- **Arduino / 单片机** —— 物联网开发板
- **传感器模块** —— 温湿度、气压、GPS 等
- **工业控制器** —— PLC、数控机床
- **老式外设** —— 调制解调器、串口打印机

#### 2. 串口通信的关键参数

| 参数 | 含义 | 常见值 |
| --- | --- | --- |
| **波特率（Baud Rate）** | 每秒传输的比特数，决定通信速度 | 9600、115200 |
| **数据位（Data Bits）** | 每个数据帧包含的数据位数 | 7 或 8 |
| **停止位（Stop Bits）** | 标志数据帧结束的位数 | 1 或 2 |
| **校验位（Parity）** | 用于错误检测的校验方式 | `none`、`even`、`odd` |

> 💡 **提示：** 通信双方（浏览器 ↔ 设备）的这些参数必须**完全一致**，否则会收到乱码，就像两个人用不同语言对话。

#### 3. Web Serial API 的工作原理

```
┌─────────────────────────────────────────────────────────┐
│                      浏览器环境                          │
│                                                         │
│  JavaScript  ←--→  Web Serial API  ←--→  浏览器底层驱动  │
└───────────────────────────┬─────────────────────────────┘
                            │ USB 串口芯片（如 CH340、CP2102）
                            ▼
                     ┌──────────────┐
                     │  串口设备     │
                     │ （Arduino等） │
                     └──────────────┘
```

**工作流程**：

1. **请求权限**：用户点击按钮，调用 `navigator.serial.requestPort()` 触发浏览器弹出设备选择器
2. **打开端口**：调用 `port.open()` 配置波特率等参数，建立连接
3. **读写数据**：通过 `port.readable` 读取设备发来的数据，通过 `port.writable` 向设备发送数据
4. **关闭端口**：通信完成后调用 `port.close()` 释放资源

#### 4. 浏览器兼容性

| 浏览器 | 支持版本 |
| --- | --- |
| Chrome | 89+ |
| Edge | 89+ |
| Opera | 75+ |
| Safari | ❌ 不支持 |
| Firefox | ❌ 不支持 |

> ⚠️ **注意：** Web Serial API 仅在**安全上下文**中可用（HTTPS 或 localhost），且需要**用户手势**（如点击按钮）才能触发设备选择器，无法自动静默连接。

### 三、API 核心对象速览

| 对象 | 作用 | 获取方式 |
| --- | --- | --- |
| `navigator.serial` | 串口通信的入口 | 全局对象 |
| `SerialPort` | 代表一个串口设备 | `requestPort()` 或 `getPorts()` |
| `SerialPort.readable` | 可读流（设备 → 浏览器） | `port.readable` |
| `SerialPort.writable` | 可写流（浏览器 → 设备） | `port.writable` |
| `SerialOptions` | 打开端口的配置参数 | `port.open(options)` |

#### 4.1 navigator.serial（入口对象）

**作用**：串口通信的总入口，提供请求设备、获取已授权设备、监听插拔事件的能力。通过 `navigator.serial` 访问，无需实例化。

| 方法/事件 | 作用 | 返回值 |
| --- | --- | --- |
| `requestPort(options)` | 弹出系统设备选择器，让用户选择一个串口设备 | `Promise<SerialPort>` |
| `getPorts()` | 返回之前已授权访问的设备列表（不弹选择器） | `Promise<SerialPort[]>` |
| `addEventListener('connect', cb)` | 监听**新设备插入**事件 | — |
| `addEventListener('disconnect', cb)` | 监听**设备拔出**事件 | — |

**`requestPort(options)` 参数详解**：

| 参数 | 类型 | 必填 | 默认值 | 作用 |
| --- | --- | --- | --- | --- |
| `options.filters` | `Array<{usbVendorId, usbProductId}>` | 否 | 不过滤 | 在设备选择器中**只显示匹配的 USB 设备**，避免用户选错 |

**`filters` 字段说明**：

| 字段 | 类型 | 作用 | 获取方式 |
| --- | --- | --- | --- |
| `usbVendorId` | `number` | USB 厂商 ID（十六进制） | 设备管理器 / `lsusb` / 设备文档 |
| `usbProductId` | `number` | USB 产品 ID（十六进制） | 同上 |

```javascript
// 示例：只显示 Arduino Uno 设备
const port = await navigator.serial.requestPort({
  filters: [{ usbVendorId: 0x2341, usbProductId: 0x0043 }]
});
```

> ⚠️ **注意**：
> - `requestPort()` **必须由用户手势触发**（如点击事件的回调中调用），否则浏览器会抛出 `SecurityError`。这是安全设计，防止网页未经用户同意就连接硬件。
> - 用户取消选择时抛出 `DOMException`，名称为 `NotFoundError`。
> - 仅在安全上下文（HTTPS 或 localhost）中可用，HTTP 页面上 `navigator.serial` 为 `undefined`。

**`getPorts()` 返回值说明**：

| 场景 | 返回值 |
| --- | --- |
| 用户之前授权过设备，且设备仍插着 | `SerialPort[]`（可能包含多个） |
| 没有授权记录 / 设备已拔空 | `[]`（空数组） |

> 💡 **提示**：利用 `getPorts()` 可以实现"记住设备"——页面加载时自动连接上次授权过的设备，无需用户重复选择。

**事件回调参数**：

```javascript
navigator.serial.addEventListener('connect', (event) => {
  // event.target 就是新插入设备对应的 SerialPort 对象
  const port = event.target;
  const info = port.getInfo();
  console.log('新设备插入:', info.usbVendorId, info.usbProductId);
});

navigator.serial.addEventListener('disconnect', (event) => {
  // event.target 是已拔出的 SerialPort 对象
  const port = event.target;
  console.log('设备已拔出');
});
```

> ⚠️ **注意**：`connect` 事件触发时，端口**尚未打开**，需要手动调用 `port.open()` 才能通信。是否自动打开取决于业务需求——自动打开适合单设备场景，手动打开（等用户确认）适合多设备场景。

#### 4.2 SerialPort（串口对象）

**作用**：代表一个物理串口设备。通过 `requestPort()` 或 `getPorts()` 获取实例，生命周期内负责打开、读写、关闭。

##### 4.2.1 实例属性

| 属性 | 类型 | 只读 | 作用 | 何时可用 |
| --- | --- | --- | --- | --- |
| `readable` | `ReadableStream` | 是 | 从设备**读取数据**的通道（设备 → 浏览器） | 端口打开后（`open()` 完成） |
| `writable` | `WritableStream` | 是 | 向设备**写入数据**的通道（浏览器 → 设备） | 端口打开后（`open()` 完成） |

> ⚠️ **注意**：`readable` 和 `writable` 只在 `port.open()` **成功之后**才可用。端口未打开时，这两个属性的值是 `null`——此时对它们调用 `getReader()` / `getWriter()` 会抛出 `TypeError`。

##### 4.2.2 实例方法

| 方法 | 作用 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `open(options)` | 打开端口，建立连接 | `SerialOptions`（见下表） | `Promise<void>` |
| `close()` | 关闭端口，释放资源 | 无 | `Promise<void>` |
| `getInfo()` | 获取设备的 USB 标识信息 | 无 | `{usbVendorId, usbProductId}` |
| `getSignals()` | 读取控制信号状态（CTS、DSR 等） | 无 | `Promise<SerialInputSignals>` |
| `setSignals(options)` | 设置控制信号（RTS、DTR、Break） | `SerialOutputSignals`（见下文） | `Promise<void>` |
| `forget()` | 撤销对此设备的访问授权 | 无 | `Promise<void>` |

**`open(options)` — `SerialOptions` 参数详解**：

| 参数 | 类型 | 必填 | 默认值 | 作用 | 常见值 |
| --- | --- | --- | --- | --- | --- |
| `baudRate` | `number` | **是** | 无（必须显式传入） | **波特率**——每秒传输的比特数，决定通信速度 | `9600`、`19200`、`38400`、`57600`、`115200` |
| `dataBits` | `number` | 否 | `8` | **数据位**——每个数据帧中承载数据的数据位数 | `7`、`8` |
| `stopBits` | `number` | 否 | `1` | **停止位**——标志数据帧结束的位数 | `1`、`2` |
| `parity` | `string` | 否 | `'none'` | **校验位**——用于检测传输错误的校验方式 | `'none'`（无校验）、`'even'`（偶校验）、`'odd'`（奇校验） |
| `bufferSize` | `number` | 否 | `255` | **读取缓冲区大小**——内部接收缓冲区的字节数 | 根据数据量调整，一般 255~4096 |
| `flowControl` | `string` | 否 | `'none'` | **流控方式**——防止数据溢出的流量控制机制 | `'none'`（无流控）、`'hardware'`（硬件流控 RTS/CTS） |

**参数详细说明**：

- **`baudRate`（波特率）**：**唯一必填的参数**——省略它会直接抛出 `TypeError`。通信双方的波特率必须**完全一致**，否则收到的是乱码。常见单片机默认 `9600`，高速通信用 `115200`。波特率越高速度越快，但对线缆质量和距离要求也越高。
- **`dataBits`（数据位）**：现代设备几乎都用 `8`。`7` 位仅用于老式设备（只能传输 ASCII 字符）。
- **`stopBits`（停止位）**：绝大多数设备用 `1`。少数老式设备用 `2`。
- **`parity`（校验位）**：
  - `'none'`：不校验，**最常用**，靠上层协议保证数据正确性。
  - `'even'`（偶校验）：数据位 + 校验位中 `1` 的个数为偶数。
  - `'odd'`（奇校验）：数据位 + 校验位中 `1` 的个数为奇数。
- **`bufferSize`（缓冲区）**：如果单次接收数据量超过此值，可能丢失数据。高速大数据量场景可适当调大。
- **`flowControl`（流控）**：
  - `'none'`：无流控，适合低速、单向通信。
  - `'hardware'`：通过 RTS/CTS 硬件信号线控制流速，适合高速双向通信（如工业设备）。

> ⚠️ **注意**：
> - `open()` 失败时抛出 `DOMException`，常见错误名：`InvalidStateError`（端口已打开）、`NetworkError`（端口被占用或设备无响应）。
> - `close()` 会**终止所有正在进行的读写操作**，并释放操作系统层面的端口占用。关闭后需重新 `open()` 才能再次通信。
> - `close()` 前建议先调用 `reader.cancel()` 取消读取器，避免流管道异常。

**`getInfo()` 返回值**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `usbVendorId` | `number \| undefined` | USB 厂商 ID（十六进制），如 Arduino 为 `0x2341` |
| `usbProductId` | `number \| undefined` | USB 产品 ID（十六进制），如 Arduino Uno 为 `0x0043` |

> 💡 **提示**：并非所有设备都返回 USB ID。某些内置串口（非 USB 转串口）可能返回 `undefined`。

##### 4.2.3 控制信号（`getSignals()` / `setSignals()`）

串口除了数据线（TX/RX），还有一组**控制信号线**，用于硬件层面的握手、复位等操作：

| 信号 | 方向 | 全称 | 典型用途 |
| --- | --- | --- | --- |
| `clearToSend` | 输入 | CTS（允许发送） | 硬件流控：对方示意"可以发" |
| `dataCarrierDetect` | 输入 | DCD（载波检测） | 调制解调器指示有载波 |
| `dataSetReady` | 输入 | DSR（数据设备就绪） | 对方示意"我准备好了" |
| `ringIndicator` | 输入 | RI（振铃指示） | 调制解调器来电提示 |
| `dataTerminalReady` | 输出 | DTR（数据终端就绪） | 很多开发板用它自动复位 / 进入烧录模式 |
| `requestToSend` | 输出 | RTS（请求发送） | 硬件流控 / 部分模块复位 |
| `break` | 输出 | Break（中止信号） | 持续发送低电平，某些设备用它进入配置模式 |

```javascript
// 读取输入信号（判断设备是否就绪）
const signals = await port.getSignals();
console.log('CTS:', signals.clearToSend);   // 对方是否允许发送
console.log('DSR:', signals.dataSetReady);  // 对方是否就绪

// 设置输出信号（典型：用 DTR/RTS 复位 ESP32 等开发板）
await port.setSignals({
  dataTerminalReady: false,  // 拉低 DTR
  requestToSend: false       // 拉低 RTS
});
```

> ⚠️ **注意**：
> - `setSignals(options)` 的所有字段都是**可选**——只传想改变的信号，其余保持不变。
> - 只有打开端口时配置了 `flowControl: 'hardware'`，CTS/RTS 才真正参与流控；否则它们只是普通的高低电平。
> - 控制信号是否起作用取决于设备的接线——很多简易 USB 转串口线根本没有引出这些信号。

##### 4.2.4 `forget()`（撤销授权）

`getPorts()` 能"记住"授权过的设备，与之对应，`forget()` 用来**撤销授权**——撤销后 `getPorts()` 不再返回该设备，下次使用必须重新通过 `requestPort()` 选择。

```javascript
const ports = await navigator.serial.getPorts();

// 用户在界面上点击"忘记此设备"
await ports[0].forget();
```

> ⚠️ **注意**：调用 `forget()` 前端口必须处于**关闭**状态，否则抛出 `InvalidStateError`。该 API 较新（Chrome 103+），使用前建议做特性检测：`if ('forget' in port) { ... }`。

#### 4.3 ReadableStream（可读流）

**作用**：`port.readable` 就是一个 `ReadableStream`，代表从设备流向浏览器的数据通道。通过**读取器（Reader）** 消费数据。

| 方法 | 作用 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `getReader()` | 获取一个读取器，用于读取流中的数据 | 无 | `ReadableStreamDefaultReader` |
| `pipeTo(destination)` | 把当前流**管道连接**到可写流 | 目标 `WritableStream` | `Promise<void>`（流关闭时完成） |
| `pipeThrough(transform)` | 流经一个**转换流**再输出 | `TransformStream` | 转换后的 `ReadableStream` |
| `cancel()` | 取消读取，主动关闭流 | 无 | `Promise<void>` |

> ⚠️ **注意**：
> - `getReader()` 会给流**加锁**——在调用 `reader.releaseLock()` 之前，不能再对这个流调用 `getReader()`、`pipeTo()`、`pipeThrough()`。忘记释放锁会抛出 `TypeError`。
> - `pipeTo()` 返回的 Promise 只在**流关闭时**才会完成（resolve）。所以通常不会 await 它，而是把它存起来，在需要知道"流已关闭"时再 await。
> - `pipeTo()` 会给流的**两端都加锁**（源流的读端、目标流的写端）。

##### 4.3.1 ReadableStreamDefaultReader（读取器）

| 方法/属性 | 作用 | 返回值 |
| --- | --- | --- |
| `read()` | 从流中读取**下一个数据块** | `Promise<{value: Uint8Array, done: boolean}>` |
| `releaseLock()` | 释放读取器的锁，允许其他读取器接管 | `void` |
| `closed` | Promise，在流关闭时完成 | `Promise<void>` |
| `cancel()` | 取消读取 | `Promise<void>` |

**`read()` 返回值详解**：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `value` | `Uint8Array` | 读取到的字节数据（注意是**字节**，不是字符串，需要 `TextDecoder` 解码） |
| `done` | `boolean` | `true` 表示流已关闭，不再有数据；`false` 表示还有更多数据 |

> 💡 **提示**：`read()` 在没有数据时**不会返回**，而是挂起等待（`await` 让出控制权），直到有数据到达或流关闭。这就是 `while(true)` 循环能持续监听的原理——不是忙等待，而是异步等待。

---

#### 4.4 WritableStream（可写流）

**作用**：`port.writable` 就是一个 `WritableStream`，代表从浏览器流向设备的数据通道。通过**写入器（Writer）** 写入数据。

| 方法 | 作用 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `getWriter()` | 获取一个写入器，用于向流写入数据 | 无 | `WritableStreamDefaultWriter` |

> ⚠️ **注意**：和读取器一样，`getWriter()` 会给流**加锁**。必须调用 `writer.releaseLock()` 释放锁后，才能再次获取写入器或关闭端口。

##### 4.4.1 WritableStreamDefaultWriter（写入器）

| 方法/属性 | 作用 | 返回值 |
| --- | --- | --- |
| `write(chunk)` | 向流写入一块数据 | `Promise<void>` |
| `close()` | 关闭写入流（表示不再写入） | `Promise<void>` |
| `releaseLock()` | 释放写入器的锁 | `void` |
| `closed` | Promise，在流关闭时完成 | `Promise<void>` |
| `desiredSize` | 当前缓冲区空间（正数表示还可写） | `number` |

**`write(chunk)` 参数**：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `chunk` | `ArrayBuffer`、`TypedArray`（如 `Uint8Array`）或 `DataView` | 要写入的**字节数据**。注意：写入的是**字节**，字符串需要先 `TextEncoder.encode()` 编码 |

> ⚠️ **注意**：
> - `write()` 是**异步**的——返回的 Promise 在数据真正写入（或进入缓冲区）后才完成。大量写入时应 await，避免缓冲区溢出。
> - `write()` 在缓冲区满时也会挂起等待，这是背压机制的一部分。

#### 4.5 TextEncoder / TextDecoder（文本编解码）

**作用**：字符串与 UTF-8 字节之间的互相转换。

| API | 作用 | 常用方法 |
| --- | --- | --- |
| `TextEncoder` | 字符串 → UTF-8 字节 | `encoder.encode(input)` |
| `TextDecoder` | UTF-8 字节 → 字符串 | `decoder.decode(input)` |

**`TextEncoder.encode(input)`**：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `input` | `string` | `''` | 要编码的字符串 |
| 返回值 | `Uint8Array` | — | UTF-8 编码后的字节数组 |

**`TextDecoder.decode(input, options)`**：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `input` | `ArrayBuffer`、`TypedArray` 或 `DataView` | — | 要解码的字节数据 |
| `options` | `{stream: boolean}` | `{stream: false}` | `stream: true` 表示分块解码（用于流式场景，不完整的字符会等下一块再解码） |
| 返回值 | `string` | — | 解码后的字符串 |

> 💡 **提示**：
> - `TextDecoder` 构造时可指定编码：`new TextDecoder('utf-8')`。默认就是 UTF-8，通常不用显式指定。
> - 遇到非法 UTF-8 字节序列时，`TextDecoder` 默认用 `U+FFFD`（�）替换错误字节。可通过 `new TextDecoder('utf-8', {fatal: true})` 改为抛出错误。

---

#### 4.6 TextDecoderStream / TextEncoderStream（流式编解码）

**作用**：把字节流和文本流互相转换的**转换流（TransformStream）**，是 `TextDecoder` 和 `TextEncoder` 的流版本。在串口通信中极为常用——`port.readable` 是字节流，用 `TextDecoderStream` 一转，上层读到的就是文本。

| API | 方向 | 作用 |
| --- | --- | --- |
| `TextDecoderStream` | 字节流 → 文本流 | 自动把流入的 `Uint8Array` 解码成 `string` |
| `TextEncoderStream` | 文本流 → 字节流 | 自动把流入的 `string` 编码成 `Uint8Array` |

```javascript
// 典型用法：字节流转文本流
const textDecoder = new TextDecoderStream(); // 默认 UTF-8
// port.readable (字节) → textDecoder → 上层读到 (文本)
port.readable.pipeTo(textDecoder.writable);
const reader = textDecoder.readable.getReader();
const { value } = await reader.read(); // value 已经是字符串
```

> 💡 **提示**：`TextDecoderStream` 内部自动处理**跨块的半个字符**——如果某个 UTF-8 多字节字符被切成了两半，它会等下一块数据到达后再解码。这就是 `TextDecoder.decode()` 中 `stream: true` 选项的流版本，无需手动处理。

---

#### 4.7 DataView（多字节数据编解码）

**作用**：在 `ArrayBuffer` 上按指定字节序读写多字节数值（16 位整数、32 位浮点数等）。用于构建/解析二进制协议帧。

| 方法 | 作用 | 参数 |
| --- | --- | --- |
| `setUint8(offset, value)` | 在 offset 位置写入 1 字节无符号整数 | 偏移量、数值 |
| `getUint8(offset)` | 从 offset 位置读取 1 字节无符号整数 | 偏移量 |
| `setUint16(offset, value, littleEndian)` | 写入 2 字节无符号整数 | 偏移量、数值、是否小端序 |
| `getUint16(offset, littleEndian)` | 读取 2 字节无符号整数 | 偏移量、是否小端序 |
| `setUint32(offset, value, littleEndian)` | 写入 4 字节无符号整数 | 偏移量、数值、是否小端序 |
| `getUint32(offset, littleEndian)` | 读取 4 字节无符号整数 | 偏移量、是否小端序 |
| `setFloat32(offset, value, littleEndian)` | 写入 4 字节浮点数 | 偏移量、数值、是否小端序 |
| `getFloat32(offset, littleEndian)` | 读取 4 字节浮点数 | 偏移量、是否小端序 |
| `setFloat64(offset, value, littleEndian)` | 写入 8 字节浮点数 | 偏移量、数值、是否小端序 |
| `getFloat64(offset, littleEndian)` | 读取 8 字节浮点数 | 偏移量、是否小端序 |

> ⚠️ **注意**：**`littleEndian` 参数非常关键**。`false` = 大端序（高位字节在前，网络协议标准），`true` = 小端序（低位字节在前，x86 CPU 标准）。读写双方必须使用**相同的字节序**，否则数值完全错误。

##### 基础读取（带详细注释）

```javascript
/**
 * 持续读取串口数据
 * 使用 ReadableStream 逐字节读取设备发来的数据
 * @param {SerialPort} port - 已打开的串口对象
 */
async function startReading(port) {
  // 从 port.readable 获取文本解码流
  // 将原始字节数据自动转换为字符串
  const textDecoder = new TextDecoderStream();
  // 将解码流连接到串口的可读流
  const readableStreamClosed = port.readable.pipeTo(textDecoder.writable);

  // 获取解码后的读取器
  const reader = textDecoder.readable.getReader();

  // 循环读取数据
  while (true) {
    try {
      // read() 返回 { value, done }
      // value: 读取到的数据（字符串）
      // done: 流是否已关闭
      const { value, done } = await reader.read();

      if (done) {
        // 读取器被释放，退出循环
        console.log('串口读取已关闭');
        break;
      }

      // 处理接收到的数据
      console.log('收到数据:', value);
      handleReceivedData(value);
    } catch (error) {
      // 读取出错（如设备断开连接）
      console.error('读取串口数据出错:', error);
      break;
    }
  }

  // 清理：释放读取器锁
  reader.releaseLock();

  try {
    // 等待流关闭完成
    await readableStreamClosed;
  } catch (error) {
    console.error('串口流关闭出错:', error);
  }
}

/**
 * 处理接收到的数据
 * @param {string} data - 设备发来的字符串数据
 */
function handleReceivedData(data) {
  // 示例：假设设备发送温度数据 "TEMP:25.6"
  if (data.startsWith('TEMP:')) {
    const temperature = parseFloat(data.replace('TEMP:', ''));
    document.getElementById('temperature').textContent = `${temperature}°C`;
  }

  // 在日志区域显示原始数据
  const logArea = document.getElementById('serial-log');
  logArea.textContent += `[接收] ${data}\n`;
  // 自动滚动到底部
  logArea.scrollTop = logArea.scrollHeight;
}
```

##### 为什么读取数据必须用 `while` 循环——详细解析

这是 Web Serial API 中最容易让新手困惑的点。下面从**底层原理**到**实际场景**逐层解释。

**第一层：串口数据是"流"，不是一次性响应**

普通 HTTP 请求是"一问一答"——发一个请求，收一个响应，结束。但串口通信完全不同：

```
HTTP 请求：  客户端 ——请求——→ 服务器
            客户端 ←——响应—— 服务器  （结束）

串口通信：   设备 ——数据1————→ 浏览器
            设备 ——数据2————→ 浏览器  （不知道什么时候结束）
            设备 ——数据3————→ 浏览器
            设备 ——数据4————→ 浏览器
            ...可能持续几小时、几天...
```

设备会**持续地、不可预测地**发送数据。传感器每秒采集一次、用户按下按钮时发送指令、设备报警时主动上报——你**永远不知道下一条数据什么时候来**。

**第二层：`reader.read()` 的本质是"阻塞等待"**

```javascript
const { value, done } = await reader.read();
```

这行代码的执行逻辑是：

| 情况 | `reader.read()` 的行为 |
| --- | --- |
| 缓冲区有数据 | 立即返回最前面的数据 |
| 缓冲区没有数据 | **挂起等待**（不消耗 CPU），直到有数据到达 |
| 设备断开 / 端口关闭 | 返回 `{ done: true }` |

> 💡 **关键理解**：`while` 循环不是"疯狂轮询"，而是"**数据来了就处理，没数据就安静等待**"。`await reader.read()` 在没有数据时会让出控制权，不会阻塞主线程，也不会浪费 CPU。

**第三层：不用 `while` 会怎样**

```javascript
// ❌ 错误示范：只读一次
async function readOnce(port) {
  const reader = port.readable.getReader();
  const { value } = await reader.read();

  console.log('收到:', value);  // 只收到第一条
  // 函数执行完毕，后续数据全部丢失
}
```

假设设备在 10 秒内发了 5 条数据：

```
时间轴：
0s ── 1s ── 2s ── 3s ── 4s ── 5s ── 6s ── 7s ── 8s ── 9s ── 10s
     ↑                        ↑
   第一条数据              read() 只读到这一条
                                后面 4 条数据全部丢失 ❌
```

**第四层：用 `while` 的完整时间线**

```javascript
// ✅ 正确示范：持续读取
async function readContinuously(port) {
  const reader = port.readable.getReader();

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log('收到:', value);
  }
}
```

```
时间轴：
0s     1s     2s     3s     4s     5s     6s     7s     8s     9s     10s
      ↓      ↓                    ↓                    ↓
   read()  read()              read()              read()
   等待中  收到数据1            收到数据2            收到数据3
   不耗CPU  处理并继续等待        处理并继续等待        处理并继续等待
```

**第五层：`while` 循环的三种退出方式**

```javascript
while (true) {
  const { value, done } = await reader.read();

  // 退出方式 1：流正常关闭（设备断开、读取器被取消）
  if (done) {
    console.log('设备已断开');
    break;
  }

  // 退出方式 2：外部主动取消（如用户点击"断开"按钮）
  if (!isReading) {
    await reader.cancel();  // 主动取消读取
    break;
  }

  handleReceivedData(value);
}
```

> 💡 **提示：** 注意**没有**「`value` 为 `null`」这种退出方式——`read()` 出错（如设备物理拔出）时，返回的 Promise 会直接 **reject**，异常进入外层 `try/catch` 的 `catch` 分支处理，这就是第三种退出方式。

**第六层：不同场景的读取模式**

| 场景 | 模式 | 是否需要 while |
| --- | --- | --- |
| 持续监控（传感器、日志） | 一直监听 | ✅ 需要 |
| 一问一答（发指令→收响应） | 发一次收一次 | ❌ 不需要 |
| 限时读取（等 5 秒看有没有响应） | 带超时的读取 | ❌ 不需要 |

**不需要 while 的场景示例**：

```javascript
/**
 * 一问一答模式：发送指令后等待一次响应
 * 适用于"请求-响应"型协议（如 Modbus）
 */
async function sendAndWaitResponse(port, command, timeout = 2000) {
  // 1. 发送指令
  const writer = port.writable.getWriter();
  await writer.write(new TextEncoder().encode(command));
  writer.releaseLock();

  // 2. 创建带超时的读取
  const reader = port.readable.getReader();

  // 用 Promise.race 实现超时控制
  const responsePromise = reader.read();
  const timeoutPromise = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('等待响应超时')), timeout)
  );

  try {
    const { value } = await Promise.race([responsePromise, timeoutPromise]);
    return value;  // 收到响应，直接返回
  } catch (error) {
    throw error;  // 超时或出错
  } finally {
    reader.releaseLock();
  }
}

// 使用：发送读取温度指令，等待一次响应
const temp = await sendAndWaitResponse(port, 'GET_TEMP\n');
console.log('当前温度:', temp);
```

##### 为什么一问一答需要超时保护——Promise.race 详解

上面的代码中，为什么不能直接 `await reader.read()`，非要加个 `timeoutPromise` 做竞争？

**核心原因：`reader.read()` 没有内置超时机制**

`reader.read()` 返回的 Promise 只有两种情况会结束：

| 情况 | 结果 |
| --- | --- |
| 有数据到达 | 正常返回 `{ value, done: false }` |
| 流关闭 / 读取器取消 | 返回 `{ done: true }` |
| **设备一直不响应** | **永远 pending，永远不会结束** ❌ |

**哪些场景会导致设备不响应？**

| 场景 | 说明 |
| --- | --- |
| 设备断电或重启 | 物理上无法回复 |
| 设备死机 / 程序跑飞 | 固件卡死 |
| 发送了设备不认识的指令 | 设备不知道该怎么回 |
| 波特率不匹配 | 设备收到的是乱码 |
| 数据线接触不良 | 数据根本没传到 |
| 设备正在执行耗时任务 | 还没处理完当前请求 |

如果没有超时保护，程序会**永远卡在那里**，无法继续执行，也无法提示用户。

**Promise.race 的工作原理**

`Promise.race` 接收一个 Promise 数组，**谁先完成（成功或失败），就用谁的结果**：

```javascript
const responsePromise = reader.read();        // Promise A：等待设备响应
const timeoutPromise = new Promise((_, reject) =>  // Promise B：等待超时时间
  setTimeout(() => reject(new Error('等待响应超时')), timeout)
);

// race：谁先完成用谁
await Promise.race([responsePromise, timeoutPromise]);
```

**两种结果的完整时间线**：

```
情况 1：设备正常响应（100ms 内返回）
─────────────────────────────────────────────────────
0ms        50ms       100ms      150ms      200ms
│──────────│──────────│──────────│──────────│
发送指令     等待中      收到响应！   ↑
                      responsePromise 先完成 ✅
                      timeoutPromise 还没触发，自动忽略
                      返回数据，继续执行 ✅


情况 2：设备不响应（超时时间 2000ms）
─────────────────────────────────────────────────────
0ms       500ms      1000ms     1500ms     2000ms
│─────────│──────────│──────────│──────────│
发送指令    等待中      等待中      等待中      超时！
                                            ↑
                                     timeoutPromise 先完成 ❌
                                     responsePromise 还在等待，自动忽略
                                     抛出错误，进入 catch
```

**超时后的处理策略**：

```javascript
async function robustQuery(port, command, options = {}) {
  const timeout = options.timeout || 2000;
  const retries = options.retries || 0;  // 重试次数
  let lastError;

  for (let attempt = 0; attempt <= retries; attempt++) {
    try {
      // 1. 发送指令
      const writer = port.writable.getWriter();
      await writer.write(new TextEncoder().encode(command + '\n'));
      writer.releaseLock();

      // 2. 等待响应（带超时）
      const reader = port.readable.getReader();
      const responsePromise = reader.read();
      const timeoutPromise = new Promise((_, reject) =>
        setTimeout(() => reject(new Error('超时')), timeout)
      );

      try {
        const { value } = await Promise.race([responsePromise, timeoutPromise]);
        return value;  // 成功，返回数据
      } finally {
        reader.releaseLock();
      }
    } catch (error) {
      lastError = error;
      console.warn(`第 ${attempt + 1} 次尝试失败:`, error.message);

      if (attempt < retries) {
        // 等一段时间再重试
        await new Promise(r => setTimeout(r, 500));
      }
    }
  }

  throw new Error(`查询失败（已重试 ${retries} 次）: ${lastError.message}`);
}

// 使用：最多重试 2 次
try {
  const temp = await robustQuery(port, 'GET_TEMP', {
    timeout: 3000,
    retries: 2
  });
  console.log('温度:', temp);
} catch (error) {
  console.error('设备无响应，请检查连接');
  showToast('设备通信失败');
}
```

> 💡 **`robustQuery` 的两个关键行为**：
>
> **1. 成功立即返回，不会继续重试**
>
> 内部通过 `return value` 直接退出整个函数。只有**失败（超时或出错）** 才会进入 `catch`，进而进入下一次循环重试。执行流程如下：
>
> ```
> attempt = 0（首次）
>   ├─ 成功 → return value → 函数结束 ✅（不重试）
>   └─ 失败 → catch → 等 500ms → attempt++
>        ├─ 成功 → return value → 函数结束 ✅
>        └─ 失败 → catch → attempt++
>             ...
>             全部失败 → 循环结束 → throw 抛出错误
> ```
>
> **2. 循环次数 = `retries + 1`，不是 `retries`**
>
> 循环条件是 `attempt <= retries`（注意 `<=`），当 `retries = 2` 时：
>
> | attempt 值 | 含义 |
> |-----------|------|
> | 0 | 第 1 次（首次尝试） |
> | 1 | 第 2 次（第 1 次重试） |
> | 2 | 第 3 次（第 2 次重试） |
>
> 所以 `retries: 2` 实际会尝试 **3 次**（1 次初始 + 2 次重试）。变量名 `retries` 表达的是"重试次数"，而非"总尝试次数"。如果想让 `retries` 表示总尝试次数，把循环条件改成 `attempt < retries` 即可。

**其他几种 Promise 竞争模式的区别**：

```javascript
// Promise.race：谁先完成用谁 → 用于超时控制
await Promise.race([task, timeout]);

// Promise.all：全部完成才继续 → 用于并行任务
const [result1, result2] = await Promise.all([task1, task2]);

// Promise.any：谁先成功用谁 → 忽略失败的，用于多个备份
await Promise.any([backup1, backup2]);

// Promise.allSettled：等全部结束，不管成功失败 → 用于批量任务
const results = await Promise.allSettled([task1, task2]);
```

**超时时间怎么选？**

| 设备类型 | 推荐超时时间 | 原因 |
| --- | --- | --- |
| 普通传感器 | 1000~3000ms | 响应快 |
| 工业 PLC | 2000~5000ms | 扫描周期影响 |
| 执行器（电机、阀门） | 5000~10000ms | 物理动作耗时 |
| GPS 模块 | 3000~5000ms | 搜星可能需要时间 |

> 💡 **本质**：JavaScript 的 Promise 无法被外部取消或强制超时，所以用另一个"定时拒绝的 Promise"和它竞争，模拟超时效果。这是 JavaScript 中实现超时的**标准模式**，不仅用于串口，也用于 `fetch`、数据库查询等所有异步操作。

**第七层：while 循环与性能的关系**

很多人担心 `while(true)` 会不会卡死浏览器或消耗大量 CPU：

```
❌ 担心：while(true) 不是死循环吗？不会卡死吗？

✅ 真相：因为有 await，所以不是死循环

while (true) {
  const { value } = await reader.read();  // ← 关键点
  // ...
}
```

`await reader.read()` 的执行过程：

1. JavaScript 引擎执行到 `await`，**暂停当前函数**
2. 控制权交还给浏览器，浏览器可以处理其他任务（渲染、点击等）
3. 当串口数据到达时，浏览器**恢复**这个函数的执行
4. 处理完数据后，进入下一次循环，再次 `await` 等待

> 💡 **本质**：这叫**协作式并发**。`await` 让出了执行权，所以不会阻塞主线程。这和 `setTimeout`、`fetch` 是同样的机制——都是异步等待，不是忙等待。

**类比理解**：

| 方式 | 类比 | 是否占用资源 |
| --- | --- | --- |
| `while(true) { read() }`（无 await） | 一直疯狂敲门问"有信吗" | ❌ 死循环，卡死 |
| `while(true) { await read() }` | 坐在门口等，有人敲门才起来 | ✅ 不占 CPU |
| `setInterval(read, 100)` | 每隔 100ms 敲一次门 | ⚠️ 可能错过间隔内的数据 |

**第八层：正确的 while 循环写法（生产级）**

```javascript
/**
 * 生产级串口读取循环
 * 包含：错误处理、优雅退出、资源清理
 */
async function productionReadLoop(port, onData) {
  let reader;

  try {
    // 创建解码流
    const decoder = new TextDecoderStream();
    // pipeTo 建立连接，返回的 Promise 在流关闭时完成
    const streamClosed = port.readable.pipeTo(decoder.writable);

    reader = decoder.readable.getReader();

    // 核心读取循环
    while (true) {
      // await 挂起，等待数据到达（不消耗 CPU）
      const { value, done } = await reader.read();

      // 流已关闭，退出循环
      if (done) {
        console.log('读取流已结束');
        break;
      }

      // 跳过空数据
      if (!value) continue;

      // 调用回调处理数据
      onData(value);
    }

    // 读取循环结束后，等待流完全关闭
    await streamClosed;
  } catch (error) {
    // 处理各种错误
    if (error.name === 'NetworkError') {
      console.error('串口连接异常断开');
    } else {
      console.error('读取错误:', error);
    }
  } finally {
    // 确保资源被释放（无论是否出错）
    if (reader) {
      try {
        reader.releaseLock();
      } catch (e) {
        // 忽略释放锁时的错误
      }
    }
    console.log('读取循环已清理');
  }
}
```

```
                     ┌──────────────────────────┐
                     │    while (true) 循环      │
                     │                          │
                     │  ┌─────────────────────┐ │
                     │  │  await reader.read() │ │ ← 阻塞等待，不占 CPU
                     │  │  （挂起，等数据）     │ │
                     │  └──────────┬──────────┘ │
                     │             │             │
                     │             ▼             │
                     │    数据到达，恢复执行      │
                     │             │             │
                     │             ▼             │
                     │    处理数据（onData）      │
                     │             │             │
                     │             ▼             │
                     │    回到循环顶部，再次等待   │
                     └──────────────────────────┘
                                  │
                          设备断开或主动取消
                                  │
                                  ▼
                              退出循环
```

#### 步骤 5：写入数据（浏览器 → 设备）

```javascript
/**
 * 向串口设备发送数据
 * @param {SerialPort} port - 已打开的串口对象
 * @param {string} data - 要发送的字符串
 */
async function writeToSerial(port, data) {
  // 将字符串编码为字节数据
  const textEncoder = new TextEncoder();
  const encodedData = textEncoder.encode(data);

  // 获取写入器并写入数据
  const writer = port.writable.getWriter();
  try {
    await writer.write(encodedData);
    console.log('发送成功:', data);
  } catch (error) {
    console.error('写入串口失败:', error);
  } finally {
    // 释放写入器锁（必须释放，否则无法再次写入）
    writer.releaseLock();
  }
}
```

#### 步骤 6：数据格式——传给设备和接收设备的数据

这是串口通信的核心问题。浏览器和设备必须约定**相同的数据格式**，否则就是乱码。

##### 6.1 底层都是字节

串口线路上传输的**永远是字节（0~255）**，不存在"字符串"或"数字"：

```
线路上实际传输的：
┌────┬────┬────┬────┬────┐
│ 72 │ 69 │ 76 │ 76 │ 79 │   ← 这是 "Hello" 的 ASCII 字节
└────┴────┴────┴────┴────┘
```

浏览器和设备的**编解码规则**必须一致。

##### 6.2 文本格式（最常用）

**字符串 ↔ 字节 互转**：

```javascript
// 编码：字符串 → 字节（浏览器发给设备）
const encoder = new TextEncoder();           // 默认 UTF-8 编码
const bytes = encoder.encode('Hello\n');     // Uint8Array [72, 69, 76, 76, 79, 10]

// 解码：字节 → 字符串（设备发给浏览器）
const decoder = new TextDecoder();           // 默认 UTF-8 解码
const str = decoder.decode(bytes);           // "Hello\n"
```

**ASCII 码对照表**：

```
字符    ASCII 码（十进制）    ASCII 码（十六进制）
─────────────────────────────────────────────────
'0'           48                  0x30
'A'           65                  0x41
'a'           97                  0x61
\n (换行)     10                  0x0A
\r (回车)     13                  0x0D
空格          32                  0x20
```

**常见文本指令格式**：

```javascript
// 格式 1：纯文本指令 + 换行结束
await send(port, 'LED_ON\n');
await send(port, 'GET_TEMP\n');

// 格式 2：指令 + 参数，用空格分隔
await send(port, 'SET_SPEED 1500\n');
await send(port, 'SET_LED 255 0 0\n');    // RGB 红色

// 格式 3：指令 + 参数，用逗号分隔
await send(port, 'SET_PWM,3,80\n');        // 通道3，占空比80%

// 格式 4：类 AT 指令（调制解调器常用）
await send(port, 'AT+BAUD=9600\n');
await send(port, 'AT+NAME=MyDevice\n');
```

**设备响应格式**：

```javascript
// 响应格式 1：纯数据
// 设备 → "25.5"

// 响应格式 2：标签 + 数据
// 设备 → "TEMP:25.5"

// 响应格式 3：多数据，逗号分隔
// 设备 → "TEMP:25.5,HUMID:60.2,PRESS:1013"

// 响应格式 4：状态码 + 数据
// 设备 → "OK:TEMP:25.5"     ← 成功
// 设备 → "ERR:UNKNOWN_CMD"   ← 失败

// 响应格式 5：JSON（智能设备常用）
// 设备 → '{"temp":25.5,"humid":60.2,"status":"ok"}'
```

##### 6.3 二进制格式（硬件控制）

**为什么要用二进制**：

| 对比 | 文本格式 | 二进制格式 |
| --- | --- | --- |
| 可读性 | ✅ 人类可读 | ❌ 看不懂 |
| 数据量 | ❌ 大（"255" 占 3 字节） | ✅ 小（255 只占 1 字节） |
| 精确控制 | ❌ 有精度损失 | ✅ 精确到每一位 |
| 适用场景 | 调试、简单指令 | 硬件控制、高速通信 |

**二进制数据编解码**：

```javascript
/**
 * 构建二进制指令帧
 * 协议格式：[帧头, 命令, 数据长度, 数据..., 校验和]
 */
function buildCommandFrame(command, data = []) {
  const frame = new Uint8Array(4 + data.length);
  let checksum = 0;

  frame[0] = 0xFF;              // 帧头（固定标识一帧的开始）
  frame[1] = command;           // 命令字节
  frame[2] = data.length;       // 数据长度

  for (let i = 0; i < data.length; i++) {
    frame[3 + i] = data[i];
    checksum += data[i];
  }

  frame[3 + data.length] = checksum & 0xFF;  // 校验和（取低8位）

  return frame;
}

// 使用：发送"设置 LED 亮度"指令
// 命令 0x01 = 设置 LED，参数 [led编号, 亮度]
const frame = buildCommandFrame(0x01, [0x03, 0xC8]);  // LED3，亮度 200
console.log('发送的字节:', Array.from(frame).map(b => '0x' + b.toString(16)));
// 输出: [0xff, 0x01, 0x02, 0x03, 0xc8, 0xcb]
//                                              校验和 = 0x03 + 0xC8 = 0xCB

await sendBinary(port, frame);
```

**解析二进制响应**：

```javascript
/**
 * 解析二进制响应帧
 * 协议格式：[帧头, 状态, 数据长度, 数据..., 校验和]
 */
function parseResponseFrame(bytes) {
  // 1. 检查帧头
  if (bytes[0] !== 0xFF) {
    throw new Error('帧头错误');
  }

  // 2. 提取字段
  const status = bytes[1];          // 状态字节（0x00 = 成功）
  const length = bytes[2];          // 数据长度
  const data = bytes.slice(3, 3 + length);  // 数据部分
  const checksum = bytes[3 + length];       // 校验和

  // 3. 验证校验和
  let calculatedChecksum = 0;
  for (let i = 1; i < 3 + length; i++) {
    calculatedChecksum += bytes[i];
  }
  if ((calculatedChecksum & 0xFF) !== checksum) {
    throw new Error('校验和错误');
  }

  return { status, data };
}

// 使用
const response = parseResponseFrame(receivedBytes);
if (response.status === 0x00) {
  console.log('成功，数据:', response.data);
}
```

**多字节数据的编解码**：

```javascript
/**
 * 将 16 位整数编码为 2 字节（大端序：高位在前）
 */
function encodeUint16(value) {
  const buffer = new ArrayBuffer(2);
  const view = new DataView(buffer);
  view.setUint16(0, value, false);  // false = 大端序
  return new Uint8Array(buffer);
}

/**
 * 将 2 字节解码为 16 位整数
 */
function decodeUint16(bytes) {
  const view = new DataView(bytes.buffer);
  return view.getUint16(0, false);  // false = 大端序
}

/**
 * 将 32 位浮点数编码为 4 字节
 */
function encodeFloat(value) {
  const buffer = new ArrayBuffer(4);
  const view = new DataView(buffer);
  view.setFloat32(0, value, false);
  return new Uint8Array(buffer);
}

/**
 * 将 4 字节解码为 32 位浮点数
 */
function decodeFloat(bytes) {
  const view = new DataView(bytes.buffer);
  return view.getFloat32(0, false);
}

// 使用示例
const speedBytes = encodeUint16(1500);     // [0x05, 0xDC] → 1500
const speed = decodeUint16(speedBytes);     // 1500

const tempBytes = encodeFloat(25.5);        // 25.5 → 4 字节
const temp = decodeFloat(tempBytes);        // 25.5
```

##### 6.4 常见协议格式

**Modbus RTU（工业标准）**：

```
Modbus RTU 帧格式：
┌────────┬────────┬────────┬────────┐
│ 设备地址 │ 功能码  │  数据   │  CRC校验 │
│ 1 字节  │ 1 字节  │ N 字节  │  2 字节  │
└────────┴────────┴────────┴────────┘

示例：读取 01 号设备的保持寄存器
发送：[0x01, 0x03, 0x00, 0x00, 0x00, 0x02, 0xC4, 0x0B]
      │地址│功能码│ 起始地址 │ 寄存器数 │  CRC  │

响应：[0x01, 0x03, 0x04, 0x00, 0x64, 0x00, 0xC8, 0xXX, 0xXX]
      │地址│功能码│字节数│  数据1  │  数据2  │  CRC  │
```

```javascript
/**
 * 构建 Modbus RTU 读取保持寄存器指令
 * @param {number} address - 设备地址
 * @param {number} startReg - 起始寄存器地址
 * @param {number} quantity - 读取寄存器数量
 */
function buildModbusReadHolding(address, startReg, quantity) {
  const frame = new Uint8Array(8);

  frame[0] = address;                       // 设备地址
  frame[1] = 0x03;                          // 功能码：读保持寄存器
  frame[2] = (startReg >> 8) & 0xFF;        // 寄存器地址高字节
  frame[3] = startReg & 0xFF;               // 寄存器地址低字节
  frame[4] = (quantity >> 8) & 0xFF;        // 寄存器数量高字节
  frame[5] = quantity & 0xFF;               // 寄存器数量低字节

  // 计算 CRC16 校验
  const crc = calculateCRC16(frame.slice(0, 6));
  frame[6] = crc & 0xFF;                    // CRC 低字节
  frame[7] = (crc >> 8) & 0xFF;             // CRC 高字节

  return frame;
}

/**
 * CRC16 校验计算（Modbus 标准）
 */
function calculateCRC16(data) {
  let crc = 0xFFFF;

  for (const byte of data) {
    crc ^= byte;
    for (let i = 0; i < 8; i++) {
      if (crc & 0x0001) {
        crc = (crc >> 1) ^ 0xA001;
      } else {
        crc >>= 1;
      }
    }
  }

  return crc;
}

// 使用：读取 01 号设备从 0x0000 开始的 2 个寄存器
const command = buildModbusReadHolding(0x01, 0x0000, 0x0002);
console.log('Modbus 指令:', Array.from(command).map(b => '0x' + b.toString(16).padStart(2, '0')));
// 输出: [0x01, 0x03, 0x00, 0x00, 0x00, 0x02, 0xc4, 0x0b]
```

**自定义帧协议（推荐用于自己的项目）**：

```
自定义帧格式：
┌────────┬────────┬────────┬────────┬────────┬────────┐
│ 帧头    │ 命令   │ 长度    │  数据   │ 校验和  │ 帧尾    │
│ 2 字节  │ 1 字节 │ 1 字节  │ N 字节  │ 1 字节  │ 1 字节  │
└────────┴────────┴────────┴────────┴────────┴────────┘

帧头：0xAA 0x55（标识一帧的开始）
命令：区分不同操作（0x01=读温度，0x02=设LED...）
长度：数据字段的字节数
校验和：从命令到数据的累加和取低8位
帧尾：0x0D（\r，标识一帧结束）
```

```javascript
/**
 * 自定义帧协议——编码器
 */
class FrameEncoder {
  static FRAME_HEADER = [0xAA, 0x55];
  static FRAME_TAIL = 0x0D;

  /**
   * 编码一帧数据
   * @param {number} command - 命令字节
   * @param {Uint8Array} data - 数据部分
   */
  static encode(command, data = new Uint8Array(0)) {
    const length = data.length;
    const frame = new Uint8Array(4 + length + 2);

    frame[0] = this.FRAME_HEADER[0];  // 帧头
    frame[1] = this.FRAME_HEADER[1];
    frame[2] = command;               // 命令
    frame[3] = length;                // 长度
    frame.set(data, 4);               // 数据

    // 校验和（命令 + 长度 + 数据 的累加和）
    let checksum = command + length;
    for (const byte of data) {
      checksum += byte;
    }
    frame[4 + length] = checksum & 0xFF;
    frame[5 + length] = this.FRAME_TAIL;  // 帧尾

    return frame;
  }
}

/**
 * 自定义帧协议——解码器
 */
class FrameDecoder {
  static FRAME_HEADER = [0xAA, 0x55];
  static FRAME_TAIL = 0x0D;

  constructor() {
    this.buffer = new Uint8Array(0);  // 缓冲区，存储未处理的数据
  }

  /**
   * 向缓冲区追加数据，返回解析出的完整帧
   * @param {Uint8Array} newData - 新收到的数据
   * @returns {Array<{command: number, data: Uint8Array}>} 解析出的帧列表
   */
  feed(newData) {
    // 追加到缓冲区
    const combined = new Uint8Array(this.buffer.length + newData.length);
    combined.set(this.buffer);
    combined.set(newData, this.buffer.length);
    this.buffer = combined;

    const frames = [];

    // 尝试从缓冲区解析帧
    while (true) {
      const frame = this._tryParseFrame();
      if (!frame) break;
      frames.push(frame);
    }

    return frames;
  }

  _tryParseFrame() {
    // 1. 查找帧头
    const headerIndex = this._findHeader();
    if (headerIndex === -1) return null;

    // 移除帧头之前的数据（可能是噪声）
    if (headerIndex > 0) {
      this.buffer = this.buffer.slice(headerIndex);
    }

    // 2. 检查是否有足够的字节（最小帧长度 = 6）
    if (this.buffer.length < 6) return null;

    // 3. 提取字段
    const command = this.buffer[2];
    const length = this.buffer[3];

    // 4. 检查整帧是否完整
    const frameLength = 4 + length + 2;
    if (this.buffer.length < frameLength) return null;

    // 5. 提取数据
    const data = this.buffer.slice(4, 4 + length);
    const checksum = this.buffer[4 + length];
    const tail = this.buffer[5 + length];

    // 6. 验证帧尾
    if (tail !== this.FRAME_TAIL) {
      this.buffer = this.buffer.slice(2);
      return this._tryParseFrame();
    }

    // 7. 验证校验和
    let calculatedChecksum = command + length;
    for (const byte of data) {
      calculatedChecksum += byte;
    }
    if ((calculatedChecksum & 0xFF) !== checksum) {
      this.buffer = this.buffer.slice(2);
      return this._tryParseFrame();
    }

    // 8. 成功解析，从缓冲区移除这一帧
    this.buffer = this.buffer.slice(frameLength);

    return { command, data };
  }

  _findHeader() {
    for (let i = 0; i < this.buffer.length - 1; i++) {
      if (this.buffer[i] === this.FRAME_HEADER[0] &&
          this.buffer[i + 1] === this.FRAME_HEADER[1]) {
        return i;
      }
    }
    return -1;
  }
}

// 使用示例
const encoder = FrameEncoder;
const decoder = new FrameDecoder();

// 编码：发送"设置 LED"指令，LED 编号 3，亮度 200
const frame = encoder.encode(0x02, new Uint8Array([0x03, 0xC8]));
console.log('发送帧:', Array.from(frame).map(b => '0x' + b.toString(16).padStart(2, '0')));
// 输出: [0xaa, 0x55, 0x02, 0x02, 0x03, 0xc8, 0xcf, 0x0d]
//                              命令  长度  数据    校验和 = 0x02+0x02+0x03+0xC8 = 0xCF

// 解码：收到设备响应
const responseBytes = new Uint8Array([0xAA, 0x55, 0x01, 0x02, 0x19, 0x00, 0x1C, 0x0D]);
const frames = decoder.feed(responseBytes);
console.log('解析结果:', frames);
// 输出: [{ command: 0x01, data: Uint8Array [0x19, 0x00] }]  ← 温度 25.0
```

##### 6.5 数据格式选择指南

```
需要传输什么数据？
│
├─ 简单文本指令（如 "LED_ON"）
│   └─ 文本格式 + 换行结束 ✅ 最简单
│
├─ 数值数据（如温度 25.5）
│   ├─ 精度要求不高 → 文本 "25.5"
│   └─ 精度要求高 → 二进制（encodeFloat）
│
├─ 硬件控制（如 PWM、寄存器）
│   └─ 二进制帧协议 ✅ 精确控制每一位
│
├─ 工业设备通信
│   └─ Modbus RTU ✅ 行业标准
│
└─ 自己的项目
    └─ 自定义帧协议 ✅ 灵活可控
```

| 格式 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 文本 + 换行 | 简单、可读 | 数据量大、精度有限 | 调试、简单指令 |
| JSON | 结构化、易解析 | 数据量大、设备端解析复杂 | 智能设备、物联网 |
| 二进制帧 | 紧凑、精确 | 需要编解码、调试难 | 硬件控制、高速通信 |
| Modbus | 标准化、通用 | 协议开销大 | 工业设备 |

#### 步骤 7：关闭串口

```javascript
/**
 * 关闭串口连接，释放资源
 * @param {SerialPort} port - 已打开的串口对象
 * @param {Object} activeReader - 正在使用的读取器（如果读取循环还在运行）
 */
async function closeSerialPort(port, activeReader) {
  try {
    // 1. 先取消读取器——释放流的锁，并让挂起的 read() 尽快结束
    //    跳过这一步直接 close()，会因读取器持锁而抛出 InvalidStateError
    if (activeReader) {
      await activeReader.cancel();
    }

    // 2. 再关闭端口
    await port.close();
    console.log('串口已关闭');
  } catch (error) {
    console.error('关闭串口失败:', error);
  }
}
```

> ⚠️ **注意：** 关闭串口的**固定顺序**是「先 `reader.cancel()` → 再 `port.close()`」。只要还有读取器/写入器持有流的锁，`close()` 就会抛 `InvalidStateError`——这是新手最常踩的坑之一。

**多串口管理器实现**：

```javascript
/**
 * 多串口管理器
 * 同时管理多个串口设备的连接和通信
 */
class MultiSerialManager {
  constructor() {
    this.ports = new Map();       // { 端口名称: SerialPort 对象 }
    this.readLoops = new Map();   // { 端口名称: 读取循环控制器 }
  }

  /**
   * 连接一个新的串口设备
   * @param {string} name - 给设备起个名字（如 'temp-sensor'）
   * @param {number} baudRate - 波特率
   */
  async connect(name, baudRate = 9600) {
    try {
      // 1. 弹出设备选择器，让用户选一个设备
      const port = await navigator.serial.requestPort();

      // 2. 打开端口
      await port.open({ baudRate });

      // 3. 存储端口对象
      this.ports.set(name, port);
      console.log(`[${name}] 已连接，波特率 ${baudRate}`);

      // 4. 启动独立的读取循环
      this._startReading(name, port);

      return true;
    } catch (error) {
      console.error(`[${name}] 连接失败:`, error);
      return false;
    }
  }

  /**
   * 向指定设备发送数据
   * @param {string} name - 设备名称
   * @param {string} data - 要发送的数据
   */
  async send(name, data) {
    const port = this.ports.get(name);
    if (!port) {
      console.warn(`[${name}] 设备未连接`);
      return false;
    }

    const writer = port.writable.getWriter();
    try {
      await writer.write(new TextEncoder().encode(data));
      console.log(`[${name}] 发送:`, data);
      return true;
    } finally {
      writer.releaseLock();
    }
  }

  /**
   * 断开指定设备
   * @param {string} name - 设备名称
   */
  async disconnect(name) {
    // 1. 停止读取循环
    //    读取循环会 cancel() 自己的读取器并释放锁，这里等待它退出
    const controller = this.readLoops.get(name);
    if (controller) {
      controller.cancelled = true;
      await controller.reader?.cancel();
      await controller.done;          // 等待循环真正结束（锁已释放）
      this.readLoops.delete(name);
    }

    // 2. 关闭端口（此时读取器的锁已释放，close() 不会报错）
    const port = this.ports.get(name);
    if (port) {
      await port.close();
      this.ports.delete(name);
      console.log(`[${name}] 已断开`);
    }
  }

  /**
   * 断开所有设备
   */
  async disconnectAll() {
    const names = [...this.ports.keys()];
    for (const name of names) {
      await this.disconnect(name);
    }
  }

  /**
   * 内部方法：为每个端口启动独立的读取循环
   * controller 上保存 reader 和 done（循环结束的 Promise），
   * 供 disconnect() 取消读取、等待锁释放后再关端口
   */
  _startReading(name, port) {
    const controller = { cancelled: false, reader: null, done: null };
    this.readLoops.set(name, controller);

    controller.done = (async () => {
      const decoder = new TextDecoderStream();
      const streamClosed = port.readable.pipeTo(decoder.writable);
      const reader = decoder.readable.getReader();
      controller.reader = reader;

      try {
        while (!controller.cancelled) {
          const { value, done } = await reader.read();
          if (done || controller.cancelled) break;

          if (value) {
            // 触发这个设备的数据回调
            this._onDataReceived?.(name, value);
          }
        }
      } catch (error) {
        if (!controller.cancelled) {
          console.error(`[${name}] 读取错误:`, error);
        }
      } finally {
        reader.releaseLock();
        await streamClosed.catch(() => {});
        console.log(`[${name}] 读取循环已停止`);
      }
    })();
  }

  /**
   * 数据接收回调（供外部设置）
   * @param {Function} callback - (deviceName, data) => void
   */
  onData(callback) {
    this._onDataReceived = callback;
  }

  /**
   * 获取所有已连接设备的名称
   */
  getConnectedDevices() {
    return [...this.ports.keys()];
  }
}
```

#### 2. 按行读取（处理以换行符分隔的数据）

很多串口设备以换行符 `\n` 作为一条数据的结束标志。下面实现按行读取：

```javascript
/**
 * 按行读取串口数据
 * 适用于设备以换行符分隔发送数据的场景
 * @param {SerialPort} port - 已打开的串口对象
 * @param {Function} onLine - 每读到一行就回调一次
 */
async function readLines(port, onLine) {
  const textDecoder = new TextDecoderStream();
  const readableStreamClosed = port.readable.pipeTo(textDecoder.writable);
  const reader = textDecoder.readable.getReader();

  let buffer = ''; // 缓冲区，存储未完整的数据

  try {
    while (true) {
      const { value, done } = await reader.read();
      if (done) break;

      // 将新数据追加到缓冲区
      buffer += value;

      // 按换行符分割，逐行处理
      let lines = buffer.split('\n');

      // 最后一行可能不完整，留在缓冲区等待下一批数据
      buffer = lines.pop();

      // 处理完整的行
      for (const line of lines) {
        const trimmed = line.trim();
        if (trimmed) onLine(trimmed);
      }
    }
  } finally {
    reader.releaseLock();
    await readableStreamClosed.catch(() => {});
  }
}

// 使用
await readLines(port, (line) => {
  console.log('收到一行:', line);
  // 示例：解析 "HUMIDITY:65.2" 格式的数据
  if (line.startsWith('HUMIDITY:')) {
    const humidity = parseFloat(line.split(':')[1]);
    updateHumidityUI(humidity);
  }
});
```

```javascript
/**
 * 启动全双工通信：同时读写
 * 用 Promise.all 并行处理读取和写入
 */
async function startFullDuplex(port) {
  // 读取循环
  const readLoop = async () => {
    const decoder = new TextDecoderStream();
    port.readable.pipeTo(decoder.writable);
    const reader = decoder.readable.getReader();

    try {
      while (true) {
        const { value, done } = await reader.read();
        if (done) break;
        console.log('收到:', value);
      }
    } finally {
      reader.releaseLock();
    }
  };

  // 写入循环：每隔 2 秒发送一次心跳
  const writeLoop = async () => {
    const encoder = new TextEncoder();

    while (port.writable) {
      const writer = port.writable.getWriter();
      try {
        await writer.write(encoder.encode('PING\n'));
        console.log('发送: PING');
      } finally {
        writer.releaseLock();
      }
      // 等待 2 秒
      await new Promise(r => setTimeout(r, 2000));
    }
  };

  // 同时启动读写两个循环
  await Promise.all([readLoop(), writeLoop()]);
}
```

#### 2. 串口调试助手

```javascript
/**
 * 简易串口调试助手
 * 功能：选择端口、设置波特率、发送/接收数据、十六进制显示
 */
class SerialDebugger {
  constructor() {
    this.port = null;
    this.reader = null;
    this.isConnected = false;
    this.receiveCount = 0;
    this.sendCount = 0;
  }

  // 连接串口
  async connect(baudRate = 9600) {
    this.port = await navigator.serial.requestPort();
    await this.port.open({ baudRate });
    this.isConnected = true;
    this._startReading();
    return true;
  }

  // 断开连接
  async disconnect() {
    this.isConnected = false;
    if (this.reader) {
      await this.reader.cancel();
    }
    if (this.port) {
      await this.port.close();
    }
    this.port = null;
  }

  // 发送字符串
  async sendString(text) {
    const encoder = new TextEncoder();
    const writer = this.port.writable.getWriter();
    await writer.write(encoder.encode(text));
    writer.releaseLock();
    this.sendCount += text.length;
  }

  // 发送十六进制字符串（如 "FF 01 02 A5"）
  async sendHex(hexString) {
    const bytes = hexString
      .split(' ')
      .map(h => parseInt(h, 16));
    const writer = this.port.writable.getWriter();
    await writer.write(new Uint8Array(bytes));
    writer.releaseLock();
    this.sendCount += bytes.length;
  }

  // 内部读取循环
  async _startReading() {
    const decoder = new TextDecoderStream();
    this.port.readable.pipeTo(decoder.writable);
    this.reader = decoder.readable.getReader();

    while (this.isConnected) {
      const { value, done } = await this.reader.read();
      if (done) break;

      this.receiveCount += value.length;
      this._onDataReceived?.(value);
    }
  }

  // 数据接收回调（供外部设置）
  onData(callback) {
    this._onDataReceived = callback;
  }
}

// 使用（注意：不要用 debugger 作为变量名——它是 JS 保留字，会直接语法报错）
const serialDebugger = new SerialDebugger();
serialDebugger.onData((data) => {
  console.log('收到:', data);
});
```

### 八、常见问题与注意事项

#### 1. 安全限制

| 限制 | 说明 |
| --- | --- |
| **必须 HTTPS** | 除 localhost 外，必须在 HTTPS 环境下使用 |
| **用户手势触发** | `requestPort()` 必须在用户点击等手势事件中调用 |
| **无法静默连接** | 每次连接都需要用户手动选择设备（除非之前已授权） |

#### 2. 常见错误与处理

```javascript
// 完整的错误处理示例
async function connectWithRetry(maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      const port = await navigator.serial.requestPort();
      await port.open({ baudRate: 9600 });
      return port; // 成功，返回端口
    } catch (error) {
      switch (error.name) {
        case 'NotFoundError':
          // 用户取消了选择
          showToast('请选择串口设备');
          return null;

        case 'InvalidStateError':
          // 端口已被打开
          console.warn('端口已打开');
          return null;

        case 'NetworkError':
          // 端口被其他程序占用
          showToast('端口被占用，请关闭其他串口软件');
          break;

        default:
          console.error(`第 ${attempt} 次连接失败:`, error);
      }

      // 等待后重试
      if (attempt < maxRetries) {
        await new Promise(r => setTimeout(r, 1000));
      }
    }
  }

  showToast('连接失败，请检查设备');
  return null;
}
```

#### 3. 数据粘包与断包问题

串口通信中，数据可能**不按预期边界到达**——一次收到半条消息，或一次收到两条消息粘在一起。

```javascript
// ❌ 错误：假设每次 read() 都返回完整的一条消息
const { value } = await reader.read();
processMessage(value); // value 可能只是半条消息！

// ✅ 正确：使用缓冲区 + 分隔符处理粘包/断包
let buffer = '';

while (true) {
  const { value, done } = await reader.read();
  if (done) break;

  buffer += value;

  // 按换行符分割，只处理完整的消息
  const messages = buffer.split('\n');
  buffer = messages.pop(); // 最后一段可能不完整，留在缓冲区

  for (const msg of messages) {
    processMessage(msg.trim());
  }
}
```

### 九、与相关技术对比

| 对比维度 | Web Serial API | WebUSB API | 原生串口应用 |
| --- | --- | --- | --- |
| **使用方式** | 浏览器内 JS | 浏览器内 JS | 安装桌面软件 |
| **易用性** | ⭐⭐⭐ 简单 | ⭐⭐ 较复杂 | ⭐⭐⭐ 成熟 |

| **部署成本** | 零（网页访问） | 零（网页访问） | 需安装 |

### 十、总结

**Web Serial API 的核心要点回顾：**

- **本质**：让网页通过 JavaScript 直接与串口设备通信，无需安装任何软件
- **核心流程**：`requestPort()` → `port.open()` → 读写数据 → `port.close()`
- **关键对象**：`navigator.serial`（入口）、`SerialPort`（端口）、`ReadableStream`（读）、`WritableStream`（写）
- **数据转换**：`TextEncoder`（字符串→字节）和 `TextDecoderStream`（字节→字符串）
- **安全限制**：必须 HTTPS、必须用户手势触发、无法静默连接
- **最佳场景**：Arduino 数据采集、工业设备配置、串口调试工具、物联网面板

> 💡 **提示：** Web Serial API 目前仅被 Chromium 内核浏览器支持（Chrome/Edge/Opera）。如果需要兼容 Safari/Firefox，可以考虑使用 **WebUSB API** 作为替代方案，或者通过本地代理服务（如 Node.js `serialport` 库 + WebSocket）中转。

```vue
<!-- SerialPortDebugger.vue -->
<template>
  <div class="serial-debugger">
    <h2>串口调试助手</h2>

        {{ msg.type === 'send' ? '[发送]' : '[接收]' }} {{ msg.text }}
      </div>
    </div>

    <!-- 发送区 -->
    <div class="send-row">
      <input
        v-model="sendText"
        :disabled="!isConnected"
        @keyup.enter="sendMessage"
        placeholder="输入要发送的内容"
      />
      <button @click="sendMessage" :disabled="!isConnected || !sendText">
        发送
      </button>
    </div>
  </div>

<script setup>
import { ref, nextTick, onUnmounted } from 'vue';

// ========== 响应式状态 ==========
const baudRate = ref(9600);
const isConnected = ref(false);
const sendText = ref('');
const messages = ref([]);
const logArea = ref(null);

// ========== 内部变量 ==========
let port = null;
let reader = null;
let readLoopRunning = false;

// ========== 连接/断开 ==========
async function toggleConnection() {
  if (isConnected.value) {
    await disconnect();
  } else {
    await connect();
  }
}

async function connect() {
  try {
    // 1. 请求用户选择串口设备
    port = await navigator.serial.requestPort();

    // 2. 打开串口，配置波特率
    await port.open({ baudRate: baudRate.value });

    isConnected.value = true;
    addMessage('system', `已连接，波特率 ${baudRate.value}`);

    // 3. 启动读取循环
    readLoopRunning = true;
    startReadLoop();
  } catch (error) {
    if (error.name !== 'NotFoundError') {
      addMessage('error', `连接失败: ${error.message}`);
    }
  }
}

async function disconnect() {
  readLoopRunning = false;

  if (reader) {
    await reader.cancel();
    reader = null;
  }

  if (port) {
    await port.close();
    port = null;
  }

  isConnected.value = false;
  addMessage('system', '已断开连接');
}

// ========== 读取循环 ==========
async function startReadLoop() {
  // 创建文本解码流，自动将字节转为字符串
  const decoder = new TextDecoderStream();
  port.readable.pipeTo(decoder.writable);

  // 获取读取器
  reader = decoder.readable.getReader();

  try {
    while (readLoopRunning) {
      const { value, done } = await reader.read();
      if (done) break;
      if (value) {
        addMessage('receive', value);
      }
    }
  } catch (error) {
    if (readLoopRunning) {
      addMessage('error', `读取错误: ${error.message}`);
    }
  } finally {
    reader.releaseLock();
  }
}

// ========== 发送消息 ==========
async function sendMessage() {
  if (!sendText.value || !port) return;

  const encoder = new TextEncoder();
  const writer = port.writable.getWriter();

  try {
    // 发送用户输入的内容（加上换行符）
    await writer.write(encoder.encode(sendText.value + '\n'));
    addMessage('send', sendText.value);
    sendText.value = '';
  } catch (error) {
    addMessage('error', `发送失败: ${error.message}`);
  } finally {
    writer.releaseLock();
  }
}

// ========== 消息列表管理 ==========
function addMessage(type, text) {
  messages.value.push({ type, text });

  // 限制消息数量，避免内存溢出
  if (messages.value.length > 500) {
    messages.value = messages.value.slice(-300);
  }

  // 自动滚动到底部
  nextTick(() => {
    if (logArea.value) {
      logArea.value.scrollTop = logArea.value.scrollHeight;
    }
  });
}

// ========== 组件卸载时清理 ==========
onUnmounted(async () => {
  await disconnect();
});
</script>
```
