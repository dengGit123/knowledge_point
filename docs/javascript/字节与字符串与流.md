## 一、概述

在 JavaScript 里处理数据时，有三个绕不开的核心概念：

| 概念 | 是什么 | 解决什么问题 |
|------|--------|-------------|
| **字节（Byte）** | 计算机存储的最小单元（8 个二进制位） | 数据在内存/磁盘中到底长什么样 |
| **字符串（String）** | 给人看的文本 | 人类如何表示和理解信息 |
| **流（Stream）** | 按时间顺序逐步传递的数据序列 | 如何**边来边处理**，而不必等全部数据到齐 |

> 💡 **一句话串起来**：字节是数据的「物理形态」，字符串是数据的「语义形态」，流是数据的「时间形态」。三者配合，才能完整地描述数据从产生到被消费的全过程。

## 二、字节（Byte）：数据的物理形态

### 2.1 通俗理解

想象内存是一排**带编号的格子**：

```
地址:    [0x00] [0x01] [0x02] [0x03] [0x04] ...
内容:    [ 72 ] [101 ] [108 ] [108 ] [111 ]   ← 每个格子存 0-255
```

- 每个格子就是 **1 字节（Byte）= 8 位（bit）**，能表示 `0~255` 共 256 种值
- 字节本身没有含义——`72` 可以代表数字 72，也可以代表字母 `H`，取决于你用什么"视角"去读

### 2.2 JavaScript 中操作字节的工具

| API | 作用 | 类比 |
|-----|------|------|
| `ArrayBuffer` | 一块固定长度的原始内存 | 一排锁着的储物柜 |
| `TypedArray`（如 `Uint8Array`） | 按特定类型读写字节 | 一把固定大小的钥匙 |
| `DataView` | 灵活读写、控制字节序 | 一把万能钥匙 |

```js
// 申请 4 字节的内存
const buffer = new ArrayBuffer(4);

// 用 Uint8Array 视角写入（每元素占 1 字节）
const bytes = new Uint8Array(buffer);
bytes[0] = 72;   // H
bytes[1] = 101;  // e
bytes[2] = 108;  // l
bytes[3] = 108;  // l

console.log(bytes); // Uint8Array [72, 101, 108, 108]
```

### 2.3 字节序：同一个数，读法不同

一个 `0x1234`（十进制 4660）占 2 字节，存储时谁在高位？

```
数值: 0x1234

大端序（Big-Endian）:    [0x12] [0x34]   ← 高位在前（网络传输常用）
小端序（Little-Endian）: [0x34] [0x12]   ← 低位在前（x86 CPU 常用）
```

```js
const buffer = new ArrayBuffer(2);
const view = new DataView(buffer);

view.setUint16(0, 0x1234, true);  // true = 小端序
const low = view.getUint8(0);     // 0x34
const high = view.getUint8(1);    // 0x12

console.log(low.toString(16), high.toString(16)); // "34" "12"
```

> ⚠️ **注意**：跨平台、跨设备传输二进制数据时，字节序不一致会导致数据错乱。网络协议统一使用**大端序**（也称网络字节序）。

## 三、字符串（String）：数据的语义形态

### 3.1 通俗理解

字符串是给人看的文本。但计算机只懂字节，所以需要一个"翻译规则"把字节变成字符——这就是**字符编码**。

```
字符 "中"  ----编码---->  字节 [0xE4, 0xB8, 0xAD]   （UTF-8）
字节 [0xE4, 0xB8, 0xAD]  ----解码---->  字符 "中"
```

### 3.2 常见字符编码

| 编码 | 字节数/字符 | 覆盖范围 | 现状 |
|------|------------|---------|------|
| ASCII | 1 字节 | 英文字母、数字、符号 | 最基础，仅 128 个字符 |
| GBK | 1~2 字节 | 中文简体/繁体 | 中文 Windows 遗留 |
| UTF-8 | 1~4 字节 | 全球所有字符 | **Web 标准，最推荐** |
| UTF-16 | 2 或 4 字节 | 全球所有字符 | JavaScript 内部使用 |

> 💡 **提示**：现代 Web 开发统一使用 **UTF-8**。HTML 中可声明 `<meta charset="utf-8">`，文件保存时也选 UTF-8。

### 3.3 JavaScript 字符串的内部表示

JavaScript 字符串采用 **UTF-16** 编码：每个字符通常占 2 字节，但 emoji 等字符占 4 字节（两个"码元"）。

```js
const str = "A中😀";

str.length;                    // 4（😀 占 2 个码元，被算成 2 个）
str.charCodeAt(0);             // 65   (A)
str.charCodeAt(1);             // 20013 (中)
str.codePointAt(2);            // 128512 (😀 的完整码点)

// 正确遍历字符（按码点而非码元）
for (const ch of str) {
  console.log(ch); // "A" "中" "😀" 各占一次循环
}
```

> ⚠️ **注意**：`str.length` 和 `str[index]` 按 UTF-16 码元计算，对 emoji 会"拆坏"。需要按字符遍历时，用 `for...of` 或展开运算符 `[...str]`。

### 3.4 字符串与字节的互相转换

浏览器提供 `TextEncoder` / `TextDecoder` 完成 UTF-8 编解码：

```js
// 字符串 → UTF-8 字节
const encoder = new TextEncoder();
const bytes = encoder.encode("Hello 世界");
// Uint8Array [72,101,108,108,111,32,228,184,150,231,149,140]
//              H   e   l   l   o   空格 ──────世────── ────界────

// UTF-8 字节 → 字符串
const decoder = new TextDecoder("utf-8");
const str = decoder.decode(bytes);
console.log(str); // "Hello 世界"
```

## 五、流（Stream）：数据的时间形态

### 5.1 通俗理解

把数据想象成**水流**：

| 类比 | 实际含义 |
|------|---------|
| 水源 | 数据来源（文件、网络、用户输入…） |
| 水管 | 数据流动的通道 |
| 水龙头 | 控制阀门（暂停、恢复、取消） |
| 水杯 | 消费者，边接边用 |

**核心思想**：不需要等一整个湖蓄满才喝水——**来一点喝一点**。

### 5.2 为什么需要流？

假设要读取一个 **2 GB** 的视频文件：

| 方式 | 做法 | 问题 |
|------|------|------|
| 一次性加载 | 全部读进内存再处理 | 内存爆炸，用户干等 |
| 流 | 每次只读一小块（如 64 KB），边读边处理 | 内存占用恒定，响应快 |

### 5.3 流的分类（Streams API）

浏览器原生 **Streams API** 定义了三种流：

| 类型 | 方向 | 说明 | 类比 |
|------|------|------|------|
| `ReadableStream` | 只读 | 从源头读取数据 | 水龙头出水 |
| `WritableStream` | 只写 | 向目标写入数据 | 往水池注水 |
| `TransformStream` | 可读可写 | 读取→转换→写出 | 净水器（进水过滤后出水） |

### 5.4 ReadableStream：可读流

```js
// 创建一个可读流，每次 push 一个数字
const stream = new ReadableStream({
  start(controller) {
    // start 阶段：初始化时调用一次
    controller.enqueue(1); // enqueue = 往流里放入数据
    controller.enqueue(2);
    controller.enqueue(3);
    controller.close();    // close = 数据已全部放入
  }
});

// 消费流
const reader = stream.getReader();

async function readAll() {
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;          // done = 流已结束
    console.log(value);       // 1, 2, 3
  }
}
readAll();
```

### 5.5 用流读取大文件（fetch + stream）

```js
// 传统方式：一次性拿到整个响应
const res = await fetch("/big-file.zip");
const blob = await res.blob(); // 等全部下载完才返回

// 流式方式：边下载边处理
const res = await fetch("/big-file.zip");
const reader = res.body.getReader(); // body 是 ReadableStream

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  // value 是 Uint8Array，每次只拿到一小块
  console.log(`收到 ${value.length} 字节`);
}
```

> 💡 **提示**：`fetch` 返回的 `Response.body` 就是一个 `ReadableStream`，这是浏览器中最常见的流来源。

### 5.6 TransformStream：转换流

```js
// 把流入的文本全部转成大写
const upperCaseStream = new TransformStream({
  transform(chunk, controller) {
    // chunk 是流入的数据块
    controller.enqueue(chunk.toString().toUpperCase());
  }
});

// 管道连接：readable → transform → writable
readableStream
  .pipeThrough(upperCaseStream)
  .pipeTo(writableStream);
```

### 5.7 流的背压（Backpressure）

当**生产者太快、消费者太慢**时，流会"堵住"——这就是**背压**。Streams API 自动处理：

```
生产者 ──push──► [内部队列] ──pull──► 消费者
                      │
                      │ 队列满时，
                      │ 通知生产者暂停
                      ▼
                 highWaterMark（高水位线）
```

> 💡 **提示**：你通常不需要手动处理背压。`pipeTo` / `pipeThrough` 会根据消费者处理速度自动调节流速。

## 六、字节、字符串、流三者协作实战

### 场景 1：读取一个文本文件，按行处理

```js
// 1. 用户选择文件
const [file] = await showOpenFilePicker();

// 2. 用流读取（不一次性占满内存）
const stream = file.stream(); // ReadableStream<Uint8Array>

// 3. 用 TextDecoderStream 把字节流转成文本流
const textStream = stream.pipeThrough(new TextDecoderStream("utf-8"));

// 4. 用按行分割的 TransformStream
const lineStream = textStream.pipeThrough(
  new TransformStream({
    transform(chunk, controller) {
      // 简单按换行符切分（生产环境需处理跨块断行）
      const lines = chunk.split("\n");
      for (const line of lines) {
        controller.enqueue(line);
      }
    }
  })
);

// 5. 逐行消费
const reader = lineStream.getReader();
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  console.log("一行:", value);
}
```

**数据形态变化链**：

```
文件字节 → [ReadableStream<Uint8Array>]
         → [TextDecoderStream]  ← 字节变字符串
         → [TransformStream]    ← 字符串按行切分
         → 逐行消费
```

### 场景 2：把字符串通过 WebSocket 发送

```js
const ws = new WebSocket("wss://example.com");

// 字符串 → UTF-8 字节 → 网络传输
const encoder = new TextEncoder();
const bytes = encoder.encode("Hello 世界");

// WebSocket 发送二进制时用 ArrayBuffer / Uint8Array
ws.send(bytes); // 底层自动发送字节
```

### 场景 3：接收网络二进制数据并转成文本

```js
ws.binaryType = "arraybuffer";

ws.onmessage = (event) => {
  // 收到的是 ArrayBuffer（字节）
  const bytes = new Uint8Array(event.data);

  // 字节 → 字符串
  const decoder = new TextDecoder("utf-8");
  const text = decoder.decode(bytes);

  console.log("收到文本:", text);
};
```

## 七、Node.js 中的流（补充）

> ⚠️ **注意**：以下 API 属于 **Node.js** 环境，与浏览器 Streams API 是两套体系，但思想一致。

Node.js 的流有 4 种基本类型：`Readable`、`Writable`、`Duplex`、`Transform`。

```js
const fs = require("fs");

// 读文件流 → 写文件流（管道）
const readStream = fs.createReadStream("input.txt", { encoding: "utf-8" });
const writeStream = fs.createWriteStream("output.txt");

// 边读边写，内存占用恒定
readStream.pipe(writeStream);

readStream.on("data", (chunk) => {
  console.log(`收到 ${chunk.length} 字符`);
});
```

| 浏览器 Streams API | Node.js Stream | 对应关系 |
|-------------------|----------------|---------|
| `ReadableStream` | `Readable` | 可读流 |
| `WritableStream` | `Writable` | 可写流 |
| `TransformStream` | `Transform` | 转换流 |
| `pipeThrough()` | `.pipe()` | 管道连接 |

## 八、三者关系总结

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   字节（Byte）──────── 数据的物理形态，0 和 1 的载体            │
│       │                                                      │
│       │ 编码/解码（TextEncoder / TextDecoder）                │
│       ▼                                                      │
│   字符串（String）──── 数据的语义形态，人类可读的文本            │
│       │                                                      │
│       │ 随时间流动（ReadableStream / WebSocket / File）       │
│       ▼                                                      │
│   流（Stream）──────── 数据的时间形态，边来边处理               │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| 要做什么 | 用哪个概念 | 关键 API |
|---------|-----------|---------|
| 操作原始二进制数据 | 字节 | `ArrayBuffer`、`Uint8Array`、`DataView` |
| 处理文本 | 字符串 | `String`、`TextEncoder`、`TextDecoder` |
| 边读边处理、节省内存 | 流 | `ReadableStream`、`TransformStream`、`pipeTo` |
| 字节与文本互转 | 字节 ↔ 字符串 | `TextEncoder.encode()` / `TextDecoder.decode()` |
| 文本流经管道处理 | 字符串 + 流 | `TextDecoderStream` + `TransformStream` |

## 九、常见陷阱速查

| 陷阱 | 说明 | 正确做法 |
|------|------|---------|
| 以为 `str.length` 是字符数 | emoji 会被算成 2 | 用 `[...str].length` |
| 直接 `new Uint8Array(str)` | 不会按 UTF-8 编码，行为不确定 | 用 `new TextEncoder().encode(str)` |
| 忘记指定编码 | 不同环境默认编码可能不同 | 显式写 `new TextDecoder("utf-8")` |
| 一次性加载大文件 | 内存溢出 | 用 `file.stream()` 或 `ReadableStream` |
| 混用浏览器流和 Node 流 | 两套 API 不兼容 | 注意运行环境，或用 polyfill |
| 忽略字节序 | 跨平台二进制协议解析错误 | 网络协议用大端序，`DataView` 显式指定 |
