# 前端页面流式显示

> 从 HTTP 分块传输到浏览器逐字渲染的完整原理与实现

## 一、概述

**流式显示（Streaming）** 是指服务器将响应数据**分块、逐步**发送给浏览器，浏览器**边接收边渲染**，而不是等全部数据到齐后再展示。

传统模式下，用户必须等待服务器处理完毕、一次性返回完整结果，才能看到页面。流式模式下，数据像"水流"一样持续到达，用户可以**立即看到已到达的部分**，大幅降低感知延迟。

> 📖 相关规范与文档：
> - [Fetch Living Standard — Streams](https://fetch.spec.whatwg.org/#streams)
> - [MDN — Server-Sent Events](https://developer.mozilla.org/zh-CN/docs/Web/API/Server-sent_events)
> - [MDN — Streams API](https://developer.mozilla.org/zh-CN/docs/Web/API/Streams_API)
> - [MDN — Fetch API](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API)

---

## 二、为什么需要流式显示

| 场景 | 传统方式 | 流式方式 |
| --- | --- | --- |
| AI 对话生成 | 等模型生成完整回复后一次性显示 | 模型每生成一个 token 就推送一个，用户看到"打字机效果" |
| 大文件下载进度 | 下载完成后才显示内容 | 边下载边展示已收到的数据 |
| 实时日志/监控 | 定时轮询刷新整个页面 | 服务器主动推送增量数据 |
| 长页面加载 | 等待全部 HTML 返回 | 浏览器边接收边解析渲染 |

**核心价值**：

- **降低感知延迟**：用户无需等待，立即看到内容
- **节省内存**：无需在内存中缓存完整响应
- **实时性**：适合实时数据推送场景

## 三、核心原理

### 3.1 HTTP 分块传输编码（Chunked Transfer Encoding）

流式显示的底层依赖是 HTTP 的 **分块传输编码**。传统 HTTP 响应带有 `Content-Length` 头，浏览器知道总长度后等数据到齐再处理。分块传输则**不指定总长度**，将数据切成多个 chunk 逐个发送。

```
传统响应（Content-Length）：
┌──────────────────────────────────────┐
│  Headers (Content-Length: 10000)     │
├──────────────────────────────────────┤
│  完整 Body（10000 字节，一次性到达）   │
└──────────────────────────────────────┘

分块传输响应（Transfer-Encoding: chunked）：
┌──────────────────────────────────────┐
│  Headers (Transfer-Encoding: chunked)│
├──────────────────────────────────────┤
│  Chunk 1（"你"）                      │
├──────────────────────────────────────┤
│  Chunk 2（"好"）                      │
├──────────────────────────────────────┤
│  Chunk 3（"世"）                      │
├──────────────────────────────────────┤
│  Chunk 4（"界"）                      │
├──────────────────────────────────────┤
│  0\r\n\r\n（结束标记）                 │
└──────────────────────────────────────┘
```

**关键响应头**：

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Transfer-Encoding: chunked
Cache-Control: no-cache
Connection: keep-alive
```

> ⚠️ **注意**：使用分块传输时**不能**设置 `Content-Length`，两者互斥。

### 3.2 浏览器端的流式接收机制

当浏览器收到分块响应后，不会等所有数据到齐才交给 JavaScript。通过 **Streams API**，浏览器提供了一种**逐块读取**响应体的方式：

```
服务器 ──chunk1──> ──chunk2──> ──chunk3──> ──结束──>
                   │          │          │
                   ▼          ▼          ▼
              ReadableStream 的 reader 逐个读取
                   │          │          │
                   ▼          ▼          ▼
              JS 处理逻辑（渲染到页面）
```

### 3.3 三种主流流式技术对比

| 技术 | 方向 | 协议 | 适用场景 |
| --- | --- | --- | --- |
| **Fetch + Streams API** | 单向（服务端 → 客户端） | HTTP/1.1、HTTP/2 | AI 对话、文件流、通用流式请求 |
| **SSE（Server-Sent Events）** | 单向（服务端 → 客户端） | HTTP | 实时通知、日志推送、股票行情 |
| **WebSocket** | 双向 | WS/WSS | 聊天室、协同编辑、实时游戏 |

> 💡 **提示**：AI 大模型对话场景最常用的是 **Fetch + Streams API**，因为模型推理本身就是单向输出，且基于标准 HTTP，无需额外协议。

## 四、Fetch + Streams API 实现详解

### 4.1 基本流程

使用 Fetch API 获取流式响应的核心步骤：

```
1. 发起 fetch 请求
       │
       ▼
2. 从 response.body 获取 ReadableStream
       │
       ▼
3. 通过 getReader() 创建 reader
       │
       ▼
4. 循环调用 reader.read() 逐块读取
       │
       ▼
5. 用 TextDecoder 将 Uint8Array 转为字符串
       │
       ▼
6. 处理并渲染每一块数据
```

### 4.2 最简示例

```javascript
// 发起流式请求
async function fetchStream(url) {
  const response = await fetch(url);

  // response.body 是一个 ReadableStream
  const reader = response.body.getReader();

  // 将字节流转换为字符串
  const decoder = new TextDecoder('utf-8');

  // 循环读取，直到 done 为 true
  while (true) {
    const { value, done } = await reader.read();

    if (done) {
      console.log('流式传输结束');
      break;
    }

    // value 是 Uint8Array，需要解码
    const chunk = decoder.decode(value, { stream: true });
    console.log('收到数据块:', chunk);
  }
}
```

### 4.3 完整示例：AI 对话流式渲染

下面是一个完整的 AI 对话流式渲染实现，包含错误处理和取消机制：

```vue
<template>
  <div class="chat-container">
    <!-- 消息列表 -->
    <div class="messages">
      <div v-for="(msg, index) in messages" :key="index" class="message">
        <strong>{{ msg.role }}：</strong>
        <span>{{ msg.content }}</span>
      </div>
    </div>

    <!-- 输入区域 -->
    <div class="input-area">
      <input
        v-model="userInput"
        @keyup.enter="sendMessage"
        placeholder="输入问题..."
        :disabled="isLoading"
      />
      <button @click="sendMessage" :disabled="isLoading">
        {{ isLoading ? '生成中...' : '发送' }}
      </button>
      <!-- 取消按钮 -->
      <button v-if="isLoading" @click="cancelRequest">取消</button>
    </div>
  </div>
</template>

<script setup>
import { ref } from 'vue';

const messages = ref([]);
const userInput = ref('');
const isLoading = ref(false);

// 用于取消请求的 AbortController
let abortController = null;

async function sendMessage() {
  if (!userInput.value.trim() || isLoading.value) return;

  // 添加用户消息
  messages.value.push({ role: '用户', content: userInput.value });

  // 添加 AI 消息占位（内容为空，后续逐步填充）
  const aiMessage = { role: 'AI', content: '' };
  messages.value.push(aiMessage);

  const question = userInput.value;
  userInput.value = '';
  isLoading.value = true;

  // 创建 AbortController 用于取消请求
  abortController = new AbortController();

  try {
    const response = await fetch('/api/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ question }),
      // 传入 signal 以支持取消
      signal: abortController.signal,
    });

    // 检查响应是否成功
    if (!response.ok) {
      throw new Error(`HTTP 错误: ${response.status}`);
    }

    // 获取流式读取器
    const reader = response.body.getReader();
    const decoder = new TextDecoder('utf-8');

    // 循环读取数据块
    while (true) {
      const { value, done } = await reader.read();

      if (done) break;

      // 解码并追加到 AI 消息
      const chunk = decoder.decode(value, { stream: true });
      aiMessage.content += chunk;
    }
  } catch (error) {
    // 区分取消和其他错误
    if (error.name === 'AbortError') {
      aiMessage.content += ' [已取消]';
    } else {
      aiMessage.content = `请求失败: ${error.message}`;
    }
  } finally {
    isLoading.value = false;
    abortController = null;
  }
}

// 取消正在进行的请求
function cancelRequest() {
  if (abortController) {
    abortController.abort();
  }
}
</script>
```

### 4.4 服务端配合（Node.js / Express 示例）

流式显示需要**服务端配合**，以下是对应的服务端实现：

```javascript
const express = require('express');
const app = express();

app.post('/api/chat', async (req, res) => {
  const { question } = req.body;

  // 设置流式响应头
  res.setHeader('Content-Type', 'text/plain; charset=utf-8');
  res.setHeader('Transfer-Encoding', 'chunked');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  // 模拟逐字生成（实际场景调用大模型 API）
  const fullResponse = '这是 AI 的流式回复内容，逐字发送...';

  for (const char of fullResponse) {
    // 逐字符写入响应流
    res.write(char);

    // 模拟生成延迟
    await new Promise(resolve => setTimeout(resolve, 50));
  }

  // 结束响应
  res.end();
});

app.listen(3000);
```

> ⚠️ **注意**：服务端必须调用 `res.write()` 分块写入，最后调用 `res.end()` 结束。不能一次性 `res.send()` 返回完整内容。

## 五、SSE（Server-Sent Events）实现

SSE 是 HTML5 原生支持的服务器推送技术，基于 HTTP 协议，使用更简单。

### 5.1 SSE 协议格式

SSE 要求每个事件以 `data:` 开头，以**两个换行符**分隔：

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: 第一条消息

data: 第二条消息

data: {"type": "update", "value": 42}

```

### 5.2 客户端实现

```javascript
// 使用原生 EventSource（仅支持 GET 请求）
const eventSource = new EventSource('/api/sse');

// 监听消息
eventSource.onmessage = (event) => {
  console.log('收到消息:', event.data);
};

// 监听错误
eventSource.onerror = () => {
  console.error('SSE 连接出错');
  eventSource.close();
};

// 自定义事件类型
eventSource.addEventListener('update', (event) => {
  console.log('更新事件:', JSON.parse(event.data));
});
```

### 5.3 使用 Fetch 读取 SSE（支持 POST）

`EventSource` 只支持 GET 请求，需要 POST 时用 Fetch + Streams API 手动解析：

```javascript
async function fetchSSE(url, body) {
  const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');

  let buffer = ''; // 缓冲不完整的数据

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    // 追加新数据到缓冲区
    buffer += decoder.decode(value, { stream: true });

    // 按双换行分割事件
    const events = buffer.split('\n\n');
    // 最后一个可能不完整，留在缓冲区
    buffer = events.pop();

    for (const event of events) {
      // 解析 data: 行
      const lines = event.split('\n');
      for (const line of lines) {
        if (line.startsWith('data:')) {
          const data = line.slice(5).trim();
          if (data === '[DONE]') return; // 结束标记
          console.log('SSE 数据:', data);
        }
      }
    }
  }
}
```

## 六、ReadableStream 深入理解

### 6.1 ReadableStream 核心概念

`ReadableStream` 是 Streams API 的核心，表示一个**可读的数据流**。

```
ReadableStream
    │
    ├── getReader() → ReadableStreamDefaultReader
    │                     │
    │                     ├── read() → Promise<{ value, done }>
    │                     ├── cancel() → 取消流
    │                     └── releaseLock() → 释放读取锁
    │
    ├── cancel() → 取消流
    ├── pipeTo() → 管道传输
    └── pipeThrough() → 经过转换流
```

### 6.2 手动创建 ReadableStream

理解如何创建 ReadableStream 有助于深入理解流式机制：

```javascript
// 创建一个自定义的 ReadableStream
const stream = new ReadableStream({
  // start 方法：流创建时立即执行
  start(controller) {
    // controller 用于向流中放入数据
    controller.enqueue('第一块数据');
    controller.enqueue('第二块数据');
  },

  // pull 方法：消费者读取时执行（队列空了会调用）
  pull(controller) {
    if (/* 还有数据 */) {
      controller.enqueue('更多数据');
    } else {
      controller.close(); // 关闭流
    }
  },

  // cancel 方法：消费者取消时执行
  cancel(reason) {
    console.log('流被取消:', reason);
  },
});
```

### 6.3 TextDecoder 的 stream 模式

读取字节流时必须使用 `TextDecoder`，且要传 `{ stream: true }`：

```javascript
const decoder = new TextDecoder('utf-8');

// ❌ 错误：不传 stream 模式，每次调用都会重置状态
const text1 = decoder.decode(chunk1);
const text2 = decoder.decode(chunk2);

// ✅ 正确：stream 模式下，不完整的 UTF-8 字符会被保留到下次解码
const text1 = decoder.decode(chunk1, { stream: true });
const text2 = decoder.decode(chunk2, { stream: true });
```

> ⚠️ **注意**：UTF-8 字符可能占多个字节，一个字符可能被拆分到两个 chunk 中。`stream: true` 确保不完整的字符不会丢失。

## 七、实际应用场景

### 7.1 AI 对话打字机效果

最常见的流式显示场景，模型每生成一个 token 就推送给前端：

```javascript
// 处理 SSE 格式的流式 AI 响应（OpenAI 兼容格式）
async function streamAIResponse(question, onToken) {
  const response = await fetch('/api/chat/stream', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ messages: [{ role: 'user', content: question }] }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');
  let buffer = '';

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });

    // 按 SSE 格式解析（data: {...}\n\n）
    const parts = buffer.split('\n\n');
    buffer = parts.pop();

    for (const part of parts) {
      const line = part.split('\n').find(l => l.startsWith('data:'));
      if (!line) continue;

      const data = line.replace(/^data:\s*/, '');
      if (data === '[DONE]') return;

      try {
        const json = JSON.parse(data);
        const token = json.choices?.[0]?.delta?.content || '';
        if (token) onToken(token); // 逐 token 回调
      } catch {
        // 忽略解析失败的块
      }
    }
  }
}

// 使用
await streamAIResponse('你好', (token) => {
  document.getElementById('output').textContent += token;
});
```

### 7.2 大文件逐行读取

```javascript
// 流式读取大文件，逐行处理（不会撑爆内存）
async function readLargeFile(file) {
  const stream = file.stream();
  const reader = stream.getReader();
  const decoder = new TextDecoder('utf-8');

  let leftover = ''; // 上一行剩余部分

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    const text = decoder.decode(value, { stream: true });
    const lines = (leftover + text).split('\n');
    leftover = lines.pop(); // 最后一行可能不完整

    for (const line of lines) {
      processLine(line); // 逐行处理
    }
  }

  if (leftover) processLine(leftover); // 处理最后一行
}
```

### 7.3 实时日志展示

```javascript
// 实时读取服务器日志流
async function tailLog(url) {
  const response = await fetch(url);
  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');
  const logContainer = document.getElementById('logs');

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    const text = decoder.decode(value, { stream: true });

    // 创建新的日志行元素
    const line = document.createElement('div');
    line.className = 'log-line';
    line.textContent = text;
    logContainer.appendChild(line);

    // 自动滚动到底部
    logContainer.scrollTop = logContainer.scrollHeight;
  }
}
```

## 八、详细步骤总结

### 实现流式显示的完整步骤

**服务端**：

1. 设置响应头 `Transfer-Encoding: chunked`（或框架自动处理）
2. 设置 `Content-Type` 并指定 `charset=utf-8`
3. 设置 `Cache-Control: no-cache` 禁止缓存
4. 分块调用 `res.write(data)` 写入数据
5. 适时调用 `res.end()` 结束响应

**客户端**：

1. 使用 `fetch()` 发起请求
2. 通过 `response.body.getReader()` 获取 reader
3. 创建 `TextDecoder('utf-8')` 解码器
4. 循环调用 `reader.read()` 直到 `done === true`
5. 每次读取后用 `decoder.decode(value, { stream: true })` 解码
6. 将解码后的文本追加到页面

### 流程图

```
客户端                                    服务端
  │                                         │
  │──── POST /api/chat ────────────────────>│
  │                                         │
  │<── HTTP 200 (chunked) ─────────────────│
  │                                         │
  │<── chunk: "你"  ───────────────────────│
  │   渲染: "你"                            │
  │                                         │
  │<── chunk: "好"  ───────────────────────│
  │   渲染: "你好"                          │
  │                                         │
  │<── chunk: "世"  ───────────────────────│
  │   渲染: "你好世"                        │
  │                                         │
  │<── chunk: "界"  ───────────────────────│
  │   渲染: "你好世界"                      │
  │                                         │
  │<── done ───────────────────────────────│
  │   传输结束                              │
```

## 九、注意事项与常见问题

### 9.1 编码问题

> ⚠️ **注意**：必须使用 `TextDecoder` 并开启 `stream: true` 模式。

UTF-8 中文字符占 3 个字节，一个字符可能被拆分到两个 chunk 边界：

```
Chunk 1: [..., 0xE4, 0xBD]  ← "你" 的前两个字节
Chunk 2: [0xA0, ...]         ← "你" 的第三个字节
```

不传 `stream: true` 时，不完整的字节序列会被替换为 `�`（乱码）。

### 9.2 跨域问题

流式请求同样受 CORS 约束，服务端需要正确配置：

```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: POST, GET, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

> ⚠️ **注意**：某些响应头在跨域时需要通过 `Access-Control-Expose-Headers` 暴露给客户端。

### 9.3 请求取消

长时间运行的流式请求应该支持取消，使用 `AbortController`：

```javascript
const controller = new AbortController();

// 发起请求时传入 signal
fetch('/api/stream', { signal: controller.signal });

// 取消请求
controller.abort(); // 会触发 AbortError
```

### 9.4 错误处理

```javascript
try {
  const response = await fetch('/api/stream');

  // 检查 HTTP 状态码
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: ${response.statusText}`);
  }

  // 检查 body 是否存在
  if (!response.body) {
    throw new Error('响应体为空，可能浏览器不支持 Streams API');
  }

  const reader = response.body.getReader();
  // ... 读取流
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('请求被取消');
  } else if (error.name === 'TypeError') {
    console.error('网络错误或 CORS 问题');
  } else {
    console.error('其他错误:', error);
  }
}
```

### 9.6 代理与中间件问题

> ⚠️ **注意**：某些反向代理（如 Nginx）会**缓冲**响应，导致流式失效。

Nginx 需要关闭代理缓冲：

```nginx
location /api/ {
    proxy_pass http://backend;
    proxy_buffering off;        # 关闭缓冲
    proxy_cache off;            # 关闭缓存
    chunked_transfer_encoding on;
}
```

### 9.7 内存管理

- 流式读取本身不会在内存中积累完整响应
- 但如果将流数据**全部追加**到某个变量或 DOM 中，内存仍会持续增长
- 对于超长内容（如日志），应考虑**限制显示长度**，移除旧内容

```javascript
// 限制日志最多显示 1000 行
const MAX_LINES = 1000;
if (logContainer.children.length > MAX_LINES) {
  logContainer.removeChild(logContainer.firstChild);
}
```

### 9.8 重试机制

流式请求中途失败后无法从断点恢复（因为是无状态的），通常需要重新发起完整请求：

```javascript
async function fetchWithRetry(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);
      if (response.ok) return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      // 指数退避
      await new Promise(r => setTimeout(r, 1000 * Math.pow(2, i)));
    }
  }
}
```

## 十、与 WebSocket 的对比

| 维度 | Fetch + Streams | SSE | WebSocket |
| --- | --- | --- | --- |
| **通信方向** | 单向（请求-响应流） | 单向（服务端推送） | 双向 |
| **协议** | HTTP | HTTP | WS/WSS |
| **自动重连** | ❌ 需手动实现 | ✅ 浏览器自动重连 | ❌ 需手动实现 |
| **二进制支持** | ✅ | ❌ 仅文本 | ✅ |
| **多路复用** | 每个请求一个连接 | 每个源一个连接（HTTP/1.1 限 6 个） | 一个连接双向通信 |
| **适用场景** | AI 对话、文件流 | 通知推送、实时数据 | 聊天、协同 |
| **实现复杂度** | 低 | 最低 | 中高 |

**选择建议**：

- **AI 对话、大模型输出** → Fetch + Streams API
- **服务端主动推送（通知、行情）** → SSE
- **双向实时通信（聊天室、协同编辑）** → WebSocket

## 十一、总结

### 核心要点回顾

1. **流式显示 = 分块传输 + 逐块渲染**：底层依赖 HTTP 分块传输编码（`Transfer-Encoding: chunked`），浏览器通过 Streams API 逐块读取
2. **三要素**：服务端分块写入、HTTP 分块传输、客户端 Streams API 读取
3. **关键 API**：`fetch()` → `response.body.getReader()` → `reader.read()` → `TextDecoder.decode()`
4. **必须开启 `stream: true`**：否则 UTF-8 多字节字符在 chunk 边界会乱码
5. **记得取消**：长时间流式请求配合 `AbortController` 支持取消
6. **代理要关缓冲**：Nginx 等反向代理需关闭 `proxy_buffering`，否则流式会退化为一次性返回

### 快速参考

```javascript
// 最简流式读取模板
async function readStream(url) {
  const response = await fetch(url);
  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    const text = decoder.decode(value, { stream: true });
    // 处理每一块数据
    console.log(text);
  }
}
```
