# 反射与泛型——泛型擦除与 Type 体系

> 📖 官方文档：[java.lang.reflect 包 (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/package-summary.html) ｜ [Type (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/Type.html)

## 一、概述

泛型和反射是「欢喜冤家」：

- 一方面，**泛型在运行时会被擦除**——`List<String>` 和 `List<Integer>` 在运行时都是 `List`，反射的 `getClass()` 拿不到 `<>` 里的类型。
- 另一方面，**泛型信息并没有完全消失**：编译器把泛型签名写进了 class 文件的元数据里，反射 API 提供了一套 `Type` 体系（`ParameterizedType`、`TypeVariable` 等），**能把字段、方法、父类上的泛型实参重新读出来**。

这就是为什么 Jackson 能通过 `new TypeReference<List<User>>() {}` 反序列化出 `List<User>`、MyBatis 能知道 Mapper 接口方法的返回类型、Spring 能解析 `@Autowired List<Handler>` 里的所有 Handler——它们都在做「反射 + 泛型元数据」的解密工作。

> 💡 **先记住结论：** 变量上的泛型（局部变量、参数声明）运行时**拿不到**；但**类的字段声明、方法签名、继承关系**上写死的泛型，运行时**能通过反射拿到**。

## 二、泛型擦除：运行时没有 `List<String>`

```java
import java.util.*;

public class ErasureDemo {
    public static void main(String[] args) {
        List<String> a = new ArrayList<>();
        List<Integer> b = new ArrayList<>();

        System.out.println(a.getClass() == b.getClass()); // true —— 同一个 Class 对象！
        System.out.println(a.getClass());                 // class java.util.ArrayList —— 没有 <String>

        // 以下写法全部无法通过编译或拿不到泛型：
        // if (a instanceof List<String>) {}   ❌ 编译错误：禁止具体泛型的 instanceof
        // List<String> c = new List<String>().getClass() 泛型实参 ❌ 拿不到
    }
}
```

擦除的规则（JLS 4.6）：无限定的泛型类型擦除为原始类型（`List<String>` → `List`），类型变量擦除为左边界（`<T extends Number>` → `Number`，无边界则 `Object`）。

但注意一个微妙的事实——**擦除 ≠ 泛型信息销毁**。编译器把泛型签名作为附加元数据（`Signature` 属性）存进了 class 文件，反射 API 就是从这里读的：

```text
源码:   List<String> names;
字节码: 字段类型 List（擦除后） + Signature 元数据 Ljava/util/List<Ljava/lang/String;>;（泛型留存）
反射:   field.getType()          → List          （擦除后的类型）
        field.getGenericType()   → List<String>  （从 Signature 还原的完整泛型）
```

## 三、Type 体系：反射眼中的类型

`java.lang.reflect.Type` 是所有类型的顶层接口，其子接口各司其职：

```text
Type（顶层接口）
 ├── Class<T>            普通类型 / 原始类型（raw type）：String、List
 ├── ParameterizedType   参数化类型：List<String>、Map<String, User>
 ├── TypeVariable<D>     类型变量：T、E
 ├── WildcardType        通配符：?、? extends Number、? super User
 └── GenericArrayType    泛型数组：T[]、List<String>[]
```

| 类型 | `getType()` 返回 | 说明 |
| ---- | ---- | ---- |
| `Class` | `String`、`int` | 不含泛型的类型，最常见 |
| `ParameterizedType` | `List<String>` | 带 `<>` 的类型，**获取泛型实参的关键** |
| `TypeVariable` | `T` | 类/方法上声明的类型参数本身 |
| `WildcardType` | `? extends Number` | 通配符及其上下界 |
| `GenericArrayType` | `T[]` | 元素类型为类型变量/参数化类型的数组 |

### ParameterizedType 的三个核心方法

```java
public interface ParameterizedType extends Type {
    Type[] getActualTypeArguments(); // ✅ 泛型实参数组：<String, User> → [String, User]
    Type getRawType();               // 原始类型：List<String> → List
    Type getOwnerType();             // 外围类型（内部类场景），如 Map.Entry 的 Map
}
```

## 四、实战一：获取字段的泛型类型

```java
import java.lang.reflect.Field;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.List;
import java.util.Map;

public class GenericFieldDemo {
    private List<String> names;
    private Map<String, Integer> scores;
    private int plain;

    public static void main(String[] args) throws Exception {
        Class<?> cls = GenericFieldDemo.class;

        Field names = cls.getDeclaredField("names");
        // getType()：擦除后的类型
        System.out.println(names.getType());          // interface java.util.List
        // getGenericType()：完整泛型类型
        Type t = names.getGenericType();
        System.out.println(t);                        // java.util.List<java.lang.String>

        if (t instanceof ParameterizedType) {         // ✅ 判断是否带泛型
            ParameterizedType pt = (ParameterizedType) t;
            Type raw = pt.getRawType();               // interface java.util.List
            Type[] args1 = pt.getActualTypeArguments(); // [java.lang.String]
            System.out.println("原始类型: " + raw);
            System.out.println("泛型实参: " + args1[0]);
        }

        // 嵌套泛型逐层拆
        Field scores = cls.getDeclaredField("scores");
        ParameterizedType pt = (ParameterizedType) scores.getGenericType();
        Type key = pt.getActualTypeArguments()[0];    // String
        Type val = pt.getActualTypeArguments()[1];    // Integer
        System.out.println(key + " -> " + val);

        // 非泛型字段 getGenericType() == getType()
        System.out.println(cls.getDeclaredField("plain").getGenericType()); // int
    }
}
```

> 💡 **提示：** `instanceof ParameterizedType` 是标准防御写法——字段可能根本没写泛型（`getType()` 与 `getGenericType()` 相同），直接强转会抛 `ClassCastException`。

## 五、实战二：获取父类泛型实参（TypeReference 的原理）

Jackson 的 `TypeReference`、Spring 的 `ResolvableType`、Gson 的 `TypeToken`，原理都是同一个：**创建一个匿名子类，把泛型固化在「类的继承声明」上，再反射读父类泛型**。

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.ArrayList;
import java.util.List;

public class TypeTokenDemo {
    public static void main(String[] args) {
        // 匿名子类：把 List<User> 固化进继承关系
        Type sup = new ArrayList<String>() {}.getClass().getGenericSuperclass();
        System.out.println(sup); // java.util.ArrayList<java.lang.String>

        ParameterizedType pt = (ParameterizedType) sup;
        System.out.println(pt.getActualTypeArguments()[0]); // class java.lang.String
    }
}
```

自己实现一个迷你版 `TypeReference`：

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

/** 泛型工具：捕获子类指定的泛型实参 */
public abstract class TypeReference<T> {
    private final Type type;

    protected TypeReference() {
        // this 是匿名子类，its 父类是 TypeReference<T>
        Type sup = getClass().getGenericSuperclass();
        if (sup instanceof ParameterizedType) {
            this.type = ((ParameterizedType) sup).getActualTypeArguments()[0];
        } else {
            throw new IllegalStateException("必须以带泛型的子类形式使用");
        }
    }

    public Type getType() { return type; }
}

// 使用方：
// new TypeReference<List<User>>() {}.getType()  →  List<User>
```

> 💡 **提示：** 这招依赖「**继承声明上的泛型不会被擦除**」。注意 `getClass()` 拿到的是匿名子类的 Class，`getGenericSuperclass()` 才带着完整泛型；直接 `new TypeReference<List<User>>()` 不加 `{}`（不产生子类）是拿不到泛型的——因为 `TypeReference` 自己声明里的 `T` 是类型变量，不是实参。

## 六、实战三：方法与构造器的泛型

```java
import java.lang.reflect.Method;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.List;

public class GenericMethodDemo {
    public List<String> findNames() { return null; }

    public <T extends Number> T convert(Object raw) { return null; }

    public static void main(String[] args) throws Exception {
        Class<?> cls = GenericMethodDemo.class;

        // 1. 返回值的泛型
        Method find = cls.getMethod("findNames");
        Type ret = find.getGenericReturnType();       // ✅ 带泛型的返回类型
        System.out.println(ret);                      // java.util.List<java.lang.String>
        Type ele = ((ParameterizedType) ret).getActualTypeArguments()[0];
        System.out.println(ele);                      // class java.lang.String

        // 2. 方法声明的类型变量 T
        Method convert = cls.getMethod("convert", Object.class);
        System.out.println(convert.getTypeParameters()[0]); // T —— 类型变量本身

        // 3. 参数的泛型：getGenericParameterTypes()
        System.out.println(convert.getGenericParameterTypes()[0]); // class java.lang.Object
    }
}
```

对应关系：`Method.getReturnType()` ↔ `getGenericReturnType()`；`getParameterTypes()` ↔ `getGenericParameterTypes()`；`Constructor` 同理。`Field.getType()` ↔ `getGenericType()`。

## 七、注意事项

1. **局部变量的泛型彻底拿不到**：方法体内的 `List<String> x = ...` 没有对应元数据入口，编译后只剩 `List`。想拿泛型只能「声明在字段/方法签名/继承关系上」。
2. **`instanceof` 判断后再强转 `ParameterizedType`**：`getGenericXxx()` 返回 `Type`，实际运行时可能是五个子类型中的任何一个，盲转会翻车。
3. **类型变量（`T`）不等于类型实参（`String`）**：在泛型类内部（如 `class Box<T>` 里）反射字段拿到的往往是 `TypeVariable`（`T` 本身），需要沿 `getGenericSuperclass()` 一路向上解析到具体实参。Spring 的 `ResolvableType`、`GenericTypeResolver` 就是干这个的，复杂场景直接用它们。
4. **桥接方法干扰**：泛型擦除会让编译器生成桥接方法（`isBridge() == true`），按名称遍历方法时注意过滤，否则可能匹配到参数为 `Object` 的桥接版本。
5. **Java 8 后反射泛型 API 已稳定**，但部分第三方库（如老版本 Gson）对 `Type` 的解析有各自实现，跨库混用 `Type` 对象时注意兼容性。

## 八、使用场景

| 场景 | 说明 |
| ---- | ---- |
| JSON 反序列化 | Jackson `TypeReference` / Gson `TypeToken` 捕获 `List<User>` 等完整泛型，正确反序列化集合元素 |
| Spring 依赖注入 | `@Autowired List<Handler>`：解析字段泛型实参，收集所有 Handler Bean 注入 |
| MyBatis / Feign | 解析 Mapper/Client 接口方法的返回值与参数泛型，决定反序列化目标类型 |
| 事件总线 | `EventListener<T>` 泛型父类解析，按事件类型分发监听器 |
| 通用 CRUD | 泛型父类 `BaseDao<T>` 中解析实体类型，自动生成 SQL 与表映射 |

## 九、总结

- 泛型擦除只影响**运行时对象**（`getClass()` 拿不到实参），但**声明处的泛型**（字段、方法签名、继承关系）以 `Signature` 元数据形式保留，反射可读。
- `Type` 体系五个分支：`Class`（普通类型）、`ParameterizedType`（参数化类型）、`TypeVariable`（类型变量）、`WildcardType`（通配符）、`GenericArrayType`（泛型数组）。
- 三大入口：`Field.getGenericType()`、`Method.getGenericReturnType()/getGenericParameterTypes()`、`Class.getGenericSuperclass()/getGenericInterfaces()`。
- `TypeReference` 模式的三板斧：匿名子类固化泛型 → `getGenericSuperclass()` → `getActualTypeArguments()[0]`。
- 永远先 `instanceof ParameterizedType` 再强转；局部变量泛型、泛型类内部的类型变量，是反射的盲区。
