# 反射常见异常——速查与处理

> 📖 官方文档：[java.lang.reflect 包 (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/package-summary.html) ｜ [ReflectiveOperationException (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/ReflectiveOperationException.html)

## 一、概述

反射把「编译期检查」推迟到了「运行期」——方法名拼错、参数类型不匹配、忘记解锁 private，这些在普通调用里编译器会替你拦下的问题，反射全都要**运行时才能暴露**，而且以异常的形式。

好消息是：反射异常的家族非常规整，触发原因几乎是一对一映射。把下面这张「全家桶对照表」装进脑子，排查反射问题就是查表游戏。

先看家族关系（全部是**受检异常**）：

```text
Exception
   └── ReflectiveOperationException（Java 7 起的反射异常公共父类）
        ├── ClassNotFoundException
        ├── NoSuchMethodException
        ├── NoSuchFieldException
        ├── IllegalAccessException
        ├── InstantiationException
        └── InvocationTargetException
```

## 二、异常全家桶对照表

| 异常 | 抛出的 API | 触发原因（一句话） |
| ---- | ---- | ---- |
| `ClassNotFoundException` | `Class.forName` | 类名写错 / 类不在 classpath |
| `NoSuchMethodException` | `getMethod` / `getDeclaredMethod` / `getDeclaredConstructor` | 方法或构造器名、参数类型列表对不上 |
| `NoSuchFieldException` | `getField` / `getDeclaredField` | 字段名不对 / 用了 `getField` 找 private |
| `IllegalAccessException` | `Field.get/set`、`Method.invoke`、`Constructor.newInstance` | 成员不可访问：private 未 `setAccessible`；跨模块受限；写 `static final` 字段 |
| `InstantiationException` | `newInstance` | 抽象类无法实例化（`Constructor.newInstance`）；接口 / 数组类 / 基本类型 / void / 无无参构造器（已废弃的 `Class.newInstance`） |
| `InvocationTargetException` | `Method.invoke`、`Constructor.newInstance` | **被调方法/构造器内部抛了异常**，真实异常在 `getCause()` |
| `IllegalArgumentException` | `invoke` / `set` / `setInt` 等 | 实参个数或类型不匹配、拆箱失败、对象不是声明类实例 |
| `NullPointerException` | `invoke` / `Field.get`（实例成员传 `null`） | 实例方法/字段却传了 `null` 对象 |
| `ExceptionInInitializerError` | `forName` / `newInstance` / 首次访问静态成员 | **静态代码块抛异常**，初始化失败（是 Error） |
| `InaccessibleObjectException` | `setAccessible(true)` | Java 9+ 模块未 open，拒绝抑制访问检查（RuntimeException） |
| `LinkageError` 家族 | `Class.forName` | 类链接失败：版本冲突、重复加载等（Error） |
| `UndeclaredThrowableException` | 动态代理调用 | 代理 handler 抛出了目标方法 `throws` 之外的受检异常 |

> 💡 **记忆分三层：** **找得到吗？**（`ClassNotFound` / `NoSuchMethod` / `NoSuchField`——查找阶段）→ **够得着吗？**（`IllegalAccess` / `InaccessibleObject`——权限阶段）→ 跑得动吗？（`Instantiation` / `InvocationTarget` / `IllegalArgument`——执行阶段）。按这三层排查，几分钟就能定位。

## 三、高频异常详解与修复

### 1. ClassNotFoundException——找不到类

```java
// ❌ 触发：类名拼错、漏写包名、依赖没引入
Class<?> cls = Class.forName("java.util.Hashmap");  // 大小写错了

// ✅ 修复：用「二进制名称」——全限定名，内部类用 $
Class<?> ok1 = Class.forName("java.util.HashMap");
Class<?> ok2 = Class.forName("java.util.Map$Entry");    // 内部类用 $，不是 .
```

排查顺序：① 类名拼写（注意大小写）→ ② 是否全限定名 → ③ 依赖 jar 是否在 classpath → ④ 类加载器是否找得到（不同加载器看到的类不同）。

### 2. NoSuchMethodException——找不到方法

三个最常见的坑：

```java
// 坑①：拿 private 方法却用了 getMethod（它只查 public）
// Method m = User.class.getMethod("secret", String.class);  // ❌
Method m = User.class.getDeclaredMethod("secret", String.class); // ✅

// 坑②：参数类型列表不精确（重载）
// Method m2 = User.class.getMethod("setName"); // ❌ setName 需要 String 参数
Method m2 = User.class.getMethod("setName", String.class);     // ✅

// 坑③：基本类型与包装类型不分
// Method m3 = Util.class.getMethod("add", Integer.class);  // ❌ 形参是 int
Method m3 = Util.class.getMethod("add", int.class);        // ✅ 基本类型写 int.class
```

### 3. IllegalAccessException——不可访问

```java
// ❌ 场景一：private 拿到了但没解锁
Field f = User.class.getDeclaredField("age");
// f.get(user);                 // IllegalAccessException!
f.setAccessible(true);          // ✅ 先解锁
f.get(user);

// ❌ 场景二：反射写 static final 字段（官方禁止）
// Field cf = Config.class.getDeclaredField("MAX");
// cf.setAccessible(true);
// cf.set(null, 100);           // IllegalAccessException!

// ❌ 场景三：Java 9+ 跨模块访问非公开成员（伴随 InaccessibleObjectException）
// 解决：--add-opens 或改用 trySetAccessible() 探测
```

### 4. InvocationTargetException——被调方法内部炸了

这是**最容易被误读**的异常：它本身不是错误，只是个「包裹」。

```java
public class UserService {
    public void register(String name) {
        if (name == null) {
            throw new IllegalArgumentException("用户名不能为空"); // 真正的异常
        }
    }
}

try {
    Method m = UserService.class.getMethod("register", String.class);
    m.invoke(new UserService(), (Object) null);
} catch (InvocationTargetException e) {
    // ❌ 打印 e 只能看到 "java.lang.reflect.InvocationTargetException"，没有根因
    // ✅ 解包
    Throwable cause = e.getCause();
    System.out.println(cause);   // java.lang.IllegalArgumentException: 用户名不能为空

    // ✅ 框架级标准姿势：还原成真实异常抛出，保留完整异常链
    throw new RuntimeException(cause);
}
```

> ⚠️ **注意：** 日志系统里如果只打印了最外层异常、没有 `-XX:+ShowCodeDetailsInExceptionMessages` 之类的辅助也没有堆栈展开，排查会卡死在「 InvocationTargetException 到底哪来的」。**永远追 `getCause()`。**

### 5. InstantiationException——没法实例化

```java
// ❌ 抽象类不能 new
// AbstractList.class.getDeclaredConstructor().newInstance(); // InstantiationException!

// ❌ 接口同理
// List.class.getDeclaredConstructor().newInstance();

// ✅ 实例化前先判断
Class<?> cls = getClassFromSomewhere();
if (cls.isInterface() || java.lang.reflect.Modifier.isAbstract(cls.getModifiers())) {
    throw new IllegalStateException(cls + " 不能实例化");
}
Object obj = cls.getDeclaredConstructor().newInstance();
```

### 6. ExceptionInInitializerError——静态块炸了

```java
class Config {
    static {
        if (System.getenv("ENV") == null) {
            throw new IllegalStateException("缺少 ENV 环境变量"); // 静态块抛异常
        }
    }
}

// Class.forName("Config"); → ExceptionInInitializerError（是 Error 不是 Exception！）
// 之后再访问 Config 类会得到 NoClassDefFoundError（类已被标记为失败）
```

> ⚠️ **注意：** 这个异常是 `Error` 的子类，`catch (Exception e)` **接不住**。它的 `getCause()` 才是静态块里真正的异常。

## 四、统一处理的框架级写法

工具类里把反射异常统一翻译成运行时异常，让业务代码不必层层 `throws`：

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.InvocationTargetException;

public class Reflects {
    /** 安全实例化：查找/权限/执行阶段的异常统一转 RuntimeException，保留异常链 */
    public static <T> T newInstance(String className, Object... args) {
        try {
            @SuppressWarnings("unchecked")
            Class<T> cls = (Class<T>) Class.forName(className);
            Class<?>[] types = java.util.Arrays.stream(args)
                    .map(Object::getClass)
                    .map(Reflects::toPrimitive)   // 拆回基本类型，匹配基本类型构造器
                    .toArray(Class<?>[]::new);
            Constructor<T> ctor = cls.getDeclaredConstructor(types);
            ctor.setAccessible(true);
            return ctor.newInstance(args);
        } catch (ClassNotFoundException e) {
            throw new IllegalArgumentException("类不存在: " + className, e);
        } catch (NoSuchMethodException e) {
            throw new IllegalArgumentException("构造器不匹配: " + className, e);
        } catch (InvocationTargetException e) {
            // ✅ 解包：构造器内部异常直接以真实异常抛出
            if (e.getCause() instanceof RuntimeException rt) throw rt;
            throw new RuntimeException(e.getCause());
        } catch (InstantiationException | IllegalAccessException e) {
            throw new IllegalStateException("无法实例化: " + className, e);
        }
    }

    /** 包装类型 → 基本类型（Integer → int.class），用于匹配基本类型参数 */
    static Class<?> toPrimitive(Class<?> c) {
        if (c == Integer.class)   return int.class;
        if (c == Long.class)      return long.class;
        if (c == Boolean.class)   return boolean.class;
        if (c == Double.class)    return double.class;
        if (c == Float.class)     return float.class;
        if (c == Short.class)     return short.class;
        if (c == Byte.class)      return byte.class;
        if (c == Character.class) return char.class;
        return c;
    }
}
```

> 💡 **提示：** 上面 `toPrimitive` 处理的就是「反射传参」的经典坑——实参 `Integer` 的运行时类永远是 `Integer.class`，而目标构造器形参可能声明为 `int.class`，不做这层转换就 `NoSuchMethodException`。（注：`null` 实参会让 `Object::getClass` 抛 `NullPointerException`，工具里可先过滤或要求非空。）

## 五、注意事项

1. **所有反射异常都是运行时才炸**：反射相关的拼写错误在 IDE 里不标红。防御方式是单元测试覆盖反射路径，或启动期（而非运行期）做一次反射探测、失败快速失败。
2. **受检异常必须处理**：`ReflectiveOperationException` 家族是受检的，`throws Exception` 草草了事会掩盖真实问题；按上面的「分层翻译」处理更清晰。
3. **`ExceptionInInitializerError` 与 `NoClassDefFoundError` 是 Error**：`catch Exception` 拦不住；且初始化失败后该类在本 JVM 中基本「报废」，重试 `forName` 也是 `NoClassDefFoundError`。
4. **`getCause()` 是反射异常的万能钥匙**：`InvocationTargetException`、`ExceptionInInitializerError` 都要用它还原根因。
5. **Java 9+ 新增 `InaccessibleObjectException`**：它是 `RuntimeException`，不在受检家族里，升级 JDK 后老代码最容易在这一点上翻车。

## 六、总结

- 反射异常按「查找 → 权限 → 执行」三层记忆：找不到（`ClassNotFound`/`NoSuchMethod`/`NoSuchField`）、够不着（`IllegalAccess`/`InaccessibleObject`）、跑不动（`Instantiation`/`InvocationTarget`/`IllegalArgument`）。
- `InvocationTargetException` 只是包装壳，`getCause()` 才是真实异常——排障第一动作。
- `private` 三件套：`getDeclaredXxx` 拿到 → `setAccessible(true)` 解锁 → 才能操作；漏一步就 `IllegalAccessException`。
- `static final` 字段不可反射写、抽象类接口不可实例化、静态块异常是 `Error`——这些硬规则记牢可少走弯路。
- 框架级工具类应统一把反射异常翻译成语义清晰的运行时异常，并保留完整异常链。
