# 获取类结构信息——getXxx 与 getDeclaredXxx

> 📖 官方文档：[Class (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Class.html) ｜ [Oracle 反射教程 - Members](https://docs.oracle.com/javase/tutorial/reflect/member/index.html)

## 一、概述

拿到 `Class` 对象后，第二步就是查询类的内部结构：有哪些**字段**（`Field`）、哪些**方法**（`Method`）、哪些**构造器**（`Constructor`），甚至嵌套的内部类。

`Class` 针对每一类成员都提供了两组方法：**`getXxx()`** 和 **`getDeclaredXxx()`**。这两组的区别是反射面试的**最高频考点**，也是实际使用中最容易踩坑的地方——用错了轻则拿不到想要的成员，重则拿到一堆「意外惊喜」（比如 `getMethods()` 里混进了从 `Object` 继承的十几个方法）。

> 💡 **一句话记忆：** 不带 `Declared` 的 =「**public 的全家福**（含继承来的）」；带 `Declared` 的 =「**本类自己声明的全家福**（含 private，不含继承）」。`declared` 意为「声明的」——只看这个类自己写了什么。

## 二、API 总览

以示例类作为贯穿：

```java
package com.example;

import java.util.Objects;

public class User {
    public String name;              // 本类 public 字段
    private int age;                 // 本类 private 字段
    public static int count;         // 本类 public 静态字段

    public User() {}
    public User(String name, int age) { this.name = name; this.age = age; }

    public void hello() { System.out.println("hello"); }
    private String secret(String msg) { return "secret: " + msg; }

    @Override
    public String toString() { return "User{name='" + name + "', age=" + age + "}"; }

    @Override
    public boolean equals(Object o) { return this == o; }
    @Override
    public int hashCode() { return Objects.hashCode(name); }
}
```

### 1. 获取字段（Field）

| 方法 | 返回 | 范围 |
| ---- | ---- | ---- |
| `getFields()` | `Field[]` | 所有 **public** 字段，**含继承**自父类/接口的 |
| `getDeclaredFields()` | `Field[]` | **本类声明**的所有字段（含 private/protected/默认），**不含继承** |
| `getField(String name)` | `Field` | 按名称取**单个 public** 字段（找不到抛 `NoSuchFieldException`） |
| `getDeclaredField(String name)` | `Field` | 按名称取**本类声明的单个字段**（含 private） |

```java
Class<?> cls = User.class;

Field[] allPublic = cls.getFields();
// → [public String name, public static int count]（如果父类也有 public 字段，也会在里面）

Field[] declared = cls.getDeclaredFields();
// → [public String name, private int age, public static int count] —— 含 private，不含继承

Field f1 = cls.getField("name");          // ✅ public 字段
Field f2 = cls.getDeclaredField("age");   // ✅ private 字段也能「拿到」
// Field f3 = cls.getField("age");        // ❌ NoSuchFieldException：getField 只找 public
```

### 2. 获取方法（Method）

| 方法 | 返回 | 范围 |
| ---- | ---- | ---- |
| `getMethods()` | `Method[]` | 所有 **public** 方法，**含继承**（父类 + 接口 default 方法 + `Object` 的方法） |
| `getDeclaredMethods()` | `Method[]` | **本类声明**的所有方法（含 private），**不含继承** |
| `getMethod(String name, Class<?>... paramTypes)` | `Method` | 按名称 + 参数类型取**单个 public** 方法 |
| `getDeclaredMethod(String name, Class<?>... paramTypes)` | `Method` | 取**本类声明的单个方法**（含 private） |

```java
Class<?> cls = User.class;

Method[] allPublic = cls.getMethods();
// → hello、toString、equals、hashCode、getClass、wait、notify、notifyAll……
//   大量来自 Object 父类的方法也混在里面 —— 这就是「含继承」的效果

Method[] declared = cls.getDeclaredMethods();
// → [hello, secret, toString, equals, hashCode] —— 只有本类声明的

Method m1 = cls.getMethod("hello");                        // ✅
Method m2 = cls.getDeclaredMethod("secret", String.class); // ✅ private 方法
// Method m3 = cls.getMethod("secret", String.class);      // ❌ NoSuchMethodException
```

> ⚠️ **注意：** 方法重载要求**参数类型必须精确写出**。`getMethod("hello")` 与 `getMethod("hello", String.class)` 是两个不同的查找。无参方法就什么参数都不传；参数是基本类型时写 `int.class` 而不是 `Integer.class`。

### 3. 获取构造器（Constructor）

构造器比较特殊：它**不能被继承**，所以没有「含继承」的问题，但 public / declared 两组仍然存在：

| 方法 | 返回 | 范围 |
| ---- | ---- | ---- |
| `getConstructors()` | `Constructor<?>[]` | 所有 **public** 构造器 |
| `getDeclaredConstructors()` | `Constructor<?>[]` | **本类声明**的所有构造器（含 private——单例模式防反射的关键） |
| `getConstructor(Class<?>... paramTypes)` | `Constructor<T>` | 指定参数的 public 构造器 |
| `getDeclaredConstructor(Class<?>... paramTypes)` | `Constructor<T>` | 指定参数的构造器（含 private），**无参写法 `getDeclaredConstructor()` 即拿无参构造器** |

### 4. 获取内部类与其它信息

| 方法 | 说明 |
| ---- | ---- |
| `getClasses()` | 所有 public 的内部类/接口（含继承的） |
| `getDeclaredClasses()` | 本类声明的所有内部类/接口（含 private） |
| `getSuperclass()` | 直接父类的 `Class` 对象（`Object` 的父类为 `null`，接口返回 `null`） |
| `getInterfaces()` | 直接实现的接口数组 |
| `getEnclosingClass()` / `getEnclosingMethod()` | 匿名类/局部类的外部类、所在方法 |

## 三、getXxx vs getDeclaredXxx 对比表

| 对比项 | `getXxx`（如 `getMethods`） | `getDeclaredXxx`（如 `getDeclaredMethods`） |
| ---- | ---- | ---- |
| 访问修饰符范围 | 只含 **public** | **全部**：public / protected / 默认 / private |
| 含继承成员 | ✅ 含（父类、接口的 public 成员） | ❌ 不含，只看本类声明的 |
| 能拿到 private | ❌ 找不到直接抛异常 | ✅ 能拿到对象（但**访问**它还需 `setAccessible(true)`） |
| 典型用途 | 遍历对外 API、按名调用公开方法 | 工具/框架解析类结构、操作私有成员 |

> 💡 **「拿到」≠「能访问」：** `getDeclaredField("age")` 成功返回了 `Field` 对象，只说明「找到了这个字段」。要真正 `get`/`set` 它的值，还需要 `setAccessible(true)` 关闭访问检查，否则抛 `IllegalAccessException`。详见 [setAccessible.md](./setAccessible.md)。

## 四、继承体系下的成员查找

反射获取成员时的「继承可见性」容易混淆，整理成一张表：

| 查找目标 | 会找到的位置 |
| ---- | ---- |
| `getField` / `getFields` | 本类 public → 逐级**直接超接口**（递归）→ 逐级**父类**（递归）。接口字段天然 `public static final`，同样能被找到 |
| `getMethod` / `getMethods` | 本类 public → 逐级父类 public → 接口的 default/public 方法 → **`Object` 的 public 方法** |
| `getDeclaredField(s)` | **仅本类**。想拿父类的 private 字段，必须先 `getSuperclass()` 再查 |
| `getDeclaredMethod(s)` | **仅本类**。同理，父类私有方法要先切到父类的 `Class` 对象 |

父类私有字段的正确打开方式：

```java
class Animal {
    private String name = "动物";
    public String getName() { return name; }
}

class Dog extends Animal { }

// 想读 Dog 对象里从 Animal 继承（实则存在于父类声明中）的 private name
Dog dog = new Dog();

// ❌ 错误：Dog 的 declared 里没有 name
// Field f = Dog.class.getDeclaredField("name"); // NoSuchFieldException

// ✅ 正确：切到父类的 Class 对象去找
Field f = Dog.class.getSuperclass().getDeclaredField("name");
f.setAccessible(true);
System.out.println(f.get(dog)); // 动物
```

## 五、修饰符与完整描述

拿到 `Field` / `Method` / `Constructor` 后，常用三个方法描述它：

```java
import java.lang.reflect.Modifier;

Field f = User.class.getDeclaredField("age");

f.getName();                          // age —— 名称
f.getType();                          // int —— 字段类型的 Class 对象
Modifier.toString(f.getModifiers());  // private —— 修饰符字符串
f.toGenericString();                  // private int com.example.User.age —— 含泛型的完整描述
```

方法还多了返回值和参数信息：

```java
Method m = User.class.getDeclaredMethod("secret", String.class);

m.getName();              // secret
m.getReturnType();        // class java.lang.String —— 返回值类型
m.getParameterTypes();    // [class java.lang.String] —— 参数类型数组
m.getModifiers();         // 修饰符整数
m.toGenericString();      // private java.lang.String com.example.User.secret(java.lang.String)
```

> 💡 **提示：** `Modifier.toString()` 能把整数标志位翻译成 `public static final` 这样的可读字符串，打印类结构、生成代码时非常好用。原理见 [Modifier.md](./Modifier.md)。

## 六、综合示例：手写一个「类结构查看器」

模仿 IDEA 调试器或 `javap` 的输出，运行时打印一个类的完整结构：

```java
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;

public class ClassInspector {
    public static void inspect(Class<?> cls) {
        System.out.println("==== 类：" + cls.getName() + " ====");
        System.out.println("父类: " + (cls.getSuperclass() == null ? "无" : cls.getSuperclass().getName()));

        System.out.println("---- 字段 ----");
        for (Field f : cls.getDeclaredFields()) {
            System.out.println("  " + Modifier.toString(f.getModifiers())
                    + " " + f.getType().getSimpleName() + " " + f.getName());
        }

        System.out.println("---- 方法 ----");
        for (Method m : cls.getDeclaredMethods()) {
            System.out.println("  " + Modifier.toString(m.getModifiers())
                    + " " + m.getReturnType().getSimpleName() + " " + m.getName()
                    + java.util.Arrays.toString(m.getParameterTypes()));
        }
    }

    public static void main(String[] args) {
        inspect(com.example.User.class);
    }
}
```

输出（节选）：

```text
==== 类：com.example.User ====
父类: java.lang.Object
---- 字段 ----
  public String name
  private int age
  public static int count
---- 方法 ----
  public void hello
  private String secret [class java.lang.String]
  public String toString
  ...
```

## 七、注意事项

1. **`getMethods()` 的返回值里通常有大量「垃圾」**：`Object` 的 `wait`/`notify`/`hashCode` 等全在里面。做框架时通常用 `getDeclaredMethods()` 再自己沿父类上行，或按注解过滤。
2. **找不到成员时抛的是受检异常**：`NoSuchMethodException` / `NoSuchFieldException`，必须处理；而批量获取（`getFields()` 等）永远不抛「找不到」，最多返回空数组。
3. **`getDeclaredXxx` 拿到 private 成员后不 `setAccessible(true)` 就直接 `get`/`set`/`invoke`，会抛 `IllegalAccessException`**——「拿到」和「访问」是两步。
4. **同名成员的顺序不保证**：`getDeclaredFields()` 返回数组中字段的顺序，JVM 规范并未强制保证，不同编译器/JVM 实现可能不同。依赖字段顺序做逻辑是不可靠的，应按名称或注解定位。
5. **数组类型的成员查找**：数组类没有声明的字段和方法，`int[].class.getDeclaredFields()` 返回空数组；它从 `Object` 继承的方法要通过 `getMethods()` 获取。

## 八、使用场景

| 场景 | 说明 |
| ---- | ---- |
| JSON 序列化框架 | `getDeclaredFields()` 遍历字段生成 JSON 键值对；按 `@JsonProperty` 注解过滤改名 |
| ORM 结果集映射 | 根据数据库列名 `getDeclaredField`，配合 `setAccessible(true)` 回填对象属性 |
| 依赖注入 | Spring 扫描 `getDeclaredFields()`，对带 `@Autowired` 的字段赋值 |
| 接口文档 / 调试工具 | `getDeclaredMethods()` + `toGenericString()` 自动生成 API 说明 |
| 单例防反射破坏 | 构造器私有化后，外部仍可 `getDeclaredConstructor().newInstance()` 破解；可在构造器里检测已存在实例则抛异常 |

## 九、总结

- `Class` 对每个成员都提供 `getXxx`（public、含继承）与 `getDeclaredXxx`（本类声明、含 private、不含继承）两组方法，**这是反射最高频的考点与用错点**。
- 查单个成员用 `getXxx(名称, 参数类型)`，找不到抛 `NoSuchXxxException`；批量获取返回数组，找不到成员就返回空数组。
- 私有成员「拿到」后要 `setAccessible(true)` 才能真正访问；父类私有成员要先用 `getSuperclass()` 切到父类再查。
- 方法重载要求精确写出参数类型，基本类型写 `int.class`，无参不传。
- 成员返回顺序不保证，按名称或注解定位才是可靠姿势。
