# 反射应用场景——框架如何使用反射

> 📖 官方文档：[Java Reflection API 教程 (Oracle)](https://docs.oracle.com/javase/tutorial/reflect/)

## 一、概述

前面各篇讲的是反射「怎么用」，本篇回答「**用在哪**」。

反射在业务代码里的存在感很低（也不该高），但它是**几乎所有 Java 框架的底层引擎**。理解框架如何使用反射，一能让你在面试中讲清楚 Spring/MyBatis 的工作原理，二能让你在自己设计通用工具时选对模式。

框架使用反射的四个通用模式：

```text
① 配置驱动实例化：读类名字符串 → Class.forName → newInstance     （IoC、SPI）
② 注解扫描分发：扫描注解 → 反射读元信息 → 按注解决定行为          （MVC、JUnit、调度）
③ 成员读写映射：getDeclaredFields/Methods → setAccessible → 读写 （ORM、JSON、注入）
④ 方法调用拦截：动态代理 → InvocationHandler → 转发/增强          （AOP、Mapper、RPC）
```

## 二、场景一：Spring IoC——配置驱动的对象工厂

Spring 容器启动时，把 XML 或注解里声明的 Bean 变成对象，核心两步反射：

```java
// 模拟 Spring 读取 <bean id="userService" class="com.example.UserServiceImpl"/> 的简化逻辑
public class MiniContainer {
    private final Map<String, Object> beans = new HashMap<>();

    public void register(String className) throws Exception {
        // ① 按类名加载
        Class<?> cls = Class.forName(className);

        // ② 反射实例化
        Object bean = cls.getDeclaredConstructor().newInstance();
        beans.put(cls.getSimpleName(), bean);

        // ③ 字段注入：处理 @Autowired（简化版）
        for (Field f : cls.getDeclaredFields()) {
            if (f.isAnnotationPresent(Autowired.class)) {
                f.setAccessible(true);
                // 递归创建依赖 Bean 再注入
                Object dep = beans.computeIfAbsent(
                        f.getType().getSimpleName(),
                        k -> {
                            try {
                                return f.getType().getDeclaredConstructor().newInstance();
                            } catch (Exception e) { throw new RuntimeException(e); }
                        });
                f.set(bean, dep);
            }
        }
    }
}
```

对应知识点：`Class.forName` 动态加载、`Constructor.newInstance` 实例化、`Field.set` + `setAccessible` 字段注入——见 [Class对象.md](./Class对象.md)、[Constructor.md](./Constructor.md)、[Field.md](./Field.md)。

## 三、场景二：JDBC——一行代码背后的反射

```java
Class.forName("com.mysql.cj.jdbc.Driver");   // 老式 JDBC 的经典一行
```

它利用 `Class.forName` **会触发类初始化**的特性：驱动类被初始化时，其静态代码块执行 `DriverManager.registerDriver(new Driver())`，把自己注册进驱动管理器。之后 `DriverManager.getConnection(url)` 按注册表找到匹配的驱动建立连接。

现代 JDBC 4.0+ 用 SPI（`META-INF/services/java.sql.Driver`）自动发现驱动，不再需要手写；但理解这行代码是理解「反射触发静态初始化」的最佳案例。框架里所有「插件式扩展」（如 `ServiceLoader`）本质都是这套「类名 → 加载 → 初始化 → 注册」模式。

## 四、场景三：JSON 序列化——成员读写的批量操作

Jackson/Gson 把对象转 JSON 的核心流程：

```java
public static Map<String, Object> toMap(Object obj) throws Exception {
    Map<String, Object> result = new LinkedHashMap<>();
    for (Field f : obj.getClass().getDeclaredFields()) {
        int mods = f.getModifiers();
        if (Modifier.isStatic(mods) || Modifier.isTransient(mods)) continue; // 跳过静态/瞬态
        f.setAccessible(true);                       // 解锁 private 字段
        result.put(f.getName(), f.get(obj));         // 字段名 → 字段值
    }
    return result;
}
// {"name":"张三","age":20} —— 再转成 JSON 字符串即可
```

反序列化反向操作：`newInstance` 创建空对象 → 按键名 `getDeclaredField` → `set` 回填。真实框架还会处理注解改名（`@JsonProperty`）、类型适配、循环引用等，但骨架就是「枚举字段 + 反射读写」。

## 五、场景四：ORM 结果集映射——数据库行变对象

MyBatis/Hibernate 把 `ResultSet` 变成实体对象的简化骨架：

```java
public static <T> T mapRow(ResultSet rs, Class<T> cls) throws Exception {
    T obj = cls.getDeclaredConstructor().newInstance();       // ① 反射创建实体
    ResultSetMetaData meta = rs.getMetaData();
    for (int i = 1; i <= meta.getColumnCount(); i++) {        // ② 遍历查询结果的每一列
        String column = meta.getColumnLabel(i);               //    列名（如 user_name）
        String prop = underlineToCamel(column);               //    列名转属性名（userName）
        try {
            Field f = cls.getDeclaredField(prop);
            f.setAccessible(true);
            f.set(obj, rs.getObject(i));                      // ③ 反射回填字段值
        } catch (NoSuchFieldException ignored) {
            // 列在实体里没有对应字段：跳过
        }
    }
    return obj;
}
```

## 六、场景五：MVC 路由与 JUnit——注解扫描分发

Spring MVC 收到请求后的路由简化版：

```java
// 启动时：扫描 Controller，构建「路径 → 方法」路由表
Map<String, Method> routes = new HashMap<>();
for (Method m : UserController.class.getDeclaredMethods()) {
    RequestMapping rm = m.getAnnotation(RequestMapping.class);
    if (rm != null) routes.put(rm.value(), m);            // /user → getUser 方法
}

// 请求时：查表 + 反射调用
Method handler = routes.get(requestPath);
Object[] args = resolveArguments(handler, request);        // 按参数注解提取请求参数
Object view = handler.invoke(controller, args);            // 反射执行业务方法
```

JUnit 同理：扫描测试类的 `@Test` 方法 → `newInstance` 创建测试实例 → 逐个 `invoke`。**「启动期扫描注解建表，运行期查表反射执行」**是这两个框架共同的骨架。

## 七、场景六：动态代理——AOP 与 RPC 的引擎

事务管理的真实过程（Spring `@Transactional` 简化）：

```java
Object proxy = Proxy.newProxyInstance(
        service.getClass().getClassLoader(),
        service.getClass().getInterfaces(),
        (p, method, args) -> {
            if (method.isAnnotationPresent(Transactional.class)) {  // 方法有事务注解
                tx.begin();                                          // 开事务
                try {
                    Object result = method.invoke(target, args);     // 执行业务
                    tx.commit();                                     // 提交
                    return result;
                } catch (InvocationTargetException e) {
                    tx.rollback();                                   // 异常回滚（解包真实异常）
                    throw e.getCause();                              // 以真实异常抛出
                }
            }
            return method.invoke(target, args);                     // 无注解：直接执行
        });
```

MyBatis Mapper、OpenFeign 客户端的完整案例见 [动态代理.md](./动态代理.md)。

## 八、场景七：SPI 与插件化——ServiceLoader

Java 内置的 SPI（Service Provider Interface）机制就是「反射 + 约定文件」：

```java
// ① 约定：jar 包里放 META-INF/services/com.example.Search 接口实现清单
//    文件内容：com.example.FileSearch（每行一个实现类全限定名）

// ② 加载方：ServiceLoader 反射实例化所有实现
ServiceLoader<Search> loader = ServiceLoader.load(Search.class);
for (Search impl : loader) {         // 底层就是 forName + newInstance
    impl.search("query");
}
```

JDBC 驱动、SLF4J 绑定、Spring Boot 自动装配（`spring.factories`）都是这个模式的变体。**「接口 + 配置文件 + 反射实例化」让程序不修改代码就能扩展功能**——插件化的本质。

## 十、注意事项：什么时候不要用反射

1. **业务代码优先直接调用**：反射丢失编译期检查、性能差、可读性低。业务里需要「动态」时，先考虑多态、策略模式、函数式接口（`Function`/`Supplier` 传行为）这些**类型安全**的替代方案。
2. **需要写反射的信号**：处理「编译期不存在的类」（用户配置、插件）、需要突破封装的框架/工具逻辑、运行时才确定的成员操作。
3. **警惕安全边界**：反射能绕过 private，意味着它也能绕过你以为存在的安全检查。反序列化漏洞（如经典的 Jackson 漏洞链）很多就是「攻击者控制了反射的目标类/成员」。对外暴露反射能力时，白名单校验必不可少。
4. **模块化时代更谨慎**：JDK 9+ 对非公开成员的反射收紧，依赖 JDK 内部 API（`sun.misc.*`）的反射代码升级时风险最高。

## 十一、总结

- 反射的四大应用模式：**配置驱动实例化**（IoC/SPI）、**注解扫描分发**（MVC/JUnit）、成员读写映射（ORM/JSON/注入）、方法调用拦截（AOP/Mapper/RPC）。
- 框架的通用节奏是「**启动期反射建元数据表，运行期查表执行**」——反射只发生一次，开销被摊薄。
- JDBC 的 `Class.forName` 是理解「反射触发静态初始化」的活化石；SPI 是理解插件化的最小样本。
- 业务代码的「动态性」优先用多态与函数式接口解决；反射是框架层的专属武器，使用时要守住性能（缓存）与安全（白名单）两条线。
