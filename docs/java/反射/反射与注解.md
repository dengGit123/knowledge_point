# 反射与注解——运行时读取注解

> 📖 官方文档：[AnnotatedElement (Java SE 21)](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/AnnotatedElement.html) ｜ [Oracle 反射教程 - Annotations](https://docs.oracle.com/javase/tutorial/reflect/annot/index.html)

## 一、概述

注解本身只是「贴在代码上的标签」——**标签本身不产生任何行为**。让注解「活过来」的正是反射：框架在运行时扫描类/方法/字段上的注解，读到 `@RequestMapping("/user")` 的路径、`@Test` 的标记、`@Value("${key}")` 的配置键，再据此执行相应逻辑。

一句话概括这条框架设计的核心链路：

```text
定义注解 → 贴到代码上 → 框架用【反射】读取注解 → 按注解信息执行逻辑
（@interface）  （@Xxx）      （isAnnotationPresent）    （invoke / set / 注册……）
```

> 💡 **前提条件（最重要）：** 只有**保留策略为 `RetentionPolicy.RUNTIME`** 的注解才能被反射读到。默认的 `CLASS` 策略只保留到 class 文件、运行时不可见；`SOURCE` 策略编译后即丢弃。所以自定义注解几乎总是写成 `@Retention(RetentionPolicy.RUNTIME)`。

## 二、AnnotatedElement：注解的统一读取接口

`AnnotatedElement` 是「可被注解的元素」的统一抽象，以下反射类都实现了它：

```text
AnnotatedElement（接口：getAnnotation / isAnnotationPresent ...）
   ▲
   ├── Class          类、接口、枚举上的注解
   ├── Field          字段上的注解
   ├── Method         方法上的注解
   ├── Constructor    构造器上的注解
   ├── Package        包上的注解（package-info）
   └── Parameter      方法参数上的注解（Java 8+）
```

也就是说：**同一个 API 套路，四类元素通吃**——这正是接口抽象的价值。

### 核心 API

| 方法 | 说明 |
| ---- | ---- |
| `isAnnotationPresent(Xxx.class)` | 判断是否存在某注解 |
| `getAnnotation(Xxx.class)` | 获取注解实例（可读其属性值），不存在返回 `null` |
| `getAnnotations()` | 返回元素上**所有**注解（含父类可继承的） |
| `getDeclaredAnnotations()` | 返回**直接标注**的注解（不含继承） |
| `getAnnotationsByType(Xxx.class)` | 获取**可重复注解**的全部实例（Java 8+） |
| `getDeclaredAnnotation(Xxx.class)` | 只查直接标注的单个注解 |

标准读取套路：

```java
import java.lang.reflect.Method;

Method m = UserController.class.getMethod("getUser");

// ① 先判断
if (m.isAnnotationPresent(RequestMapping.class)) {
    // ② 再取实例
    RequestMapping rm = m.getAnnotation(RequestMapping.class);
    // ③ 读属性
    System.out.println(rm.value());   // /user
}

// 简写：getAnnotation 拿不到返回 null，可省去 isAnnotationPresent
RequestMapping rm = m.getAnnotation(RequestMapping.class);
if (rm != null) {
    System.out.println(rm.value());
}
```

> 💡 **提示：** `isAnnotationPresent` + `getAnnotation` 会做两次查找，性能敏感场景直接 `getAnnotation` 判 `null` 即可；语义优先场景（表达「必须存在」）用前者更清晰。

## 三、完整示例：自定义注解 + 反射读取

### 1. 定义注解

```java
import java.lang.annotation.*;

@Documented                                   // 导入 javadoc
@Target({ElementType.METHOD, ElementType.TYPE}) // 能贴在哪：方法、类/接口上
@Retention(RetentionPolicy.RUNTIME)           // ✅ 保留到运行时 —— 反射可读的前提
public @interface ApiLog {
    String value() default "";                // 日志说明
    LogLevel level() default LogLevel.INFO;   // 枚举属性
    boolean printArgs() default false;        // 是否打印入参

    enum LogLevel { INFO, WARN, ERROR }
}
```

### 2. 使用注解

```java
public class OrderService {

    @ApiLog(value = "创建订单", level = ApiLog.LogLevel.WARN, printArgs = true)
    public void createOrder(String userId, double amount) {
        System.out.println("订单已创建");
    }

    public void normalMethod() {
        System.out.println("无注解的普通方法");
    }
}
```

### 3. 反射读取并执行逻辑（框架视角）

```java
import java.lang.reflect.Method;

public class ApiLogProcessor {
    public static void main(String[] args) throws Exception {
        Class<?> cls = OrderService.class;
        Object service = cls.getDeclaredConstructor().newInstance();

        for (Method m : cls.getDeclaredMethods()) {
            ApiLog log = m.getAnnotation(ApiLog.class);   // 读注解
            if (log == null) {
                continue;                                 // 没注解：跳过（不演示调用）
            }
            if (m.getParameterCount() > 0) {
                continue;                                 // 带参方法演示中不调用（无实参可传）
            }
            // ✅ 有注解：按注解属性增强行为
            System.out.println("[日志" + log.level() + "] " + log.value());
            long start = System.nanoTime();
            m.invoke(service);                            // 反射调用无参原方法
            long cost = (System.nanoTime() - start) / 1000;
            System.out.println("[耗时] " + cost + "μs");
        }
    }
}
```

这就是 AOP 日志切面、接口监控的原始雏形——**注解提供配置，反射提供执行力**。

## 四、不同目标上的注解读取

| 目标 | 读取入口 | 示例 |
| ---- | ---- | ---- |
| 类 | `Class` 对象 | `User.class.getAnnotation(Component.class)` |
| 字段 | `Field` 对象 | `field.getAnnotation(Autowired.class)` |
| 方法 | `Method` 对象 | `method.getAnnotation(RequestMapping.class)` |
| 构造器 | `Constructor` 对象 | `ctor.getAnnotation(Autowired.class)` |
| 方法参数 | `Parameter` 对象（Java 8+） | `method.getParameters()[0].getAnnotation(Param.class)` |
| 包 | `Package` 对象 | `cls.getPackage().getAnnotation(...)` |

```java
// 字段注解：模拟 Spring 的 @Autowired 注入
import java.lang.reflect.Field;

public class Injector {
    public static void inject(Object bean) throws Exception {
        for (Field f : bean.getClass().getDeclaredFields()) {
            if (f.isAnnotationPresent(Autowired.class)) {
                f.setAccessible(true);                       // private 字段也能注入
                Object dependency = f.getType()
                                     .getDeclaredConstructor()
                                     .newInstance();         // 简化：直接 new 依赖
                f.set(bean, dependency);                     // ✅ 注入
            }
        }
    }
}
```

```java
// 参数注解（Java 8+）：按参数名绑定值，模拟 @RequestParam
Method m = cls.getMethod("handler", String.class, int.class);
Parameter[] ps = m.getParameters();
for (Parameter p : ps) {
    System.out.println(p.getName());                  // arg0/arg1（需 -parameters 编译才是原名）
    RequestParam rp = p.getAnnotation(RequestParam.class);
    if (rp != null) System.out.println(rp.value());   // 参数上绑定的请求参数名
}
```

> ⚠️ **注意：** 参数名反射默认拿不到源码名（是 `arg0`、`arg1`），需要在编译时加 `-parameters` 参数保留。Spring Boot 默认开启该编译参数；Maven 原生 `maven-compiler-plugin` 需要显式配置。

## 五、元注解与可继承性

### 1. 五大元注解（给注解贴的注解）

| 元注解 | 作用 |
| ---- | ---- |
| `@Target` | 限制注解能贴的位置：`TYPE`（类/接口/枚举）、`METHOD`、`FIELD`、`PARAMETER`、`CONSTRUCTOR`、`ANNOTATION_TYPE` 等 |
| `@Retention` | 保留策略：`SOURCE`（仅源码）→ `CLASS`（默认，到 class 文件）→ `RUNTIME`（✅ 反射可读） |
| `@Inherited` | 子类能**继承父类上**的该注解（仅对**类**有效，方法/字段注解永远不继承） |
| `@Documented` | 让注解出现在 javadoc 生成的文档中 |
| `@Repeatable`（Java 8+） | 允许同一位置重复标注 |

### 2. `@Inherited` 的行为与陷阱

```java
import java.lang.annotation.*;
import java.lang.reflect.AnnotatedElement;

@Inherited                       // ✅ 声明可继承
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Marker {}

@Marker
class Parent {}

class Child extends Parent {}    // 子类没写注解

public class InheritDemo {
    public static void main(String[] args) {
        System.out.println(Child.class.isAnnotationPresent(Marker.class)); // true —— 从父类继承到了
        System.out.println(Child.class.getAnnotation(Marker.class) != null); // true
    }
}
```

> ⚠️ **注意：** `@Inherited` 只对**类**生效。父类方法上的注解，子类重写后**不会**继承到重写方法上——这就是 Spring 中 `@Transactional` 等注解写在实现类方法上而不推荐写在接口方法上的原因之一：代理与反射查找时，重写会「丢失」接口方法上的注解语义。

### 3. 可重复注解

```java
import java.lang.annotation.*;

@Repeatable(Roles.class)          // 指明「容器注解」
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Role { String value(); }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Roles { Role[] value(); }   // 容器注解

@Role("admin")
@Role("user")                     // ✅ 同一位置重复标注
class Account {}

// 读取：用 getAnnotationsByType 直接拿全部实例
Role[] roles = Account.class.getAnnotationsByType(Role.class);
// → ["admin", "user"] —— 它会自动展开容器注解，是读取重复注解的推荐 API
// 而 getAnnotation(Role.class) 在重复标注场景下返回 null（单个 @Role 不直接存在，
// 实际存的是容器 @Roles），需要先拿容器再手动展开 value() 数组
```

## 六、注意事项

1. **注解不生效的第一排查项**：`@Retention` 是不是 `RUNTIME`？`@Target` 位置对不对？用 `isAnnotationPresent` 打印验证。
2. **重写会丢方法注解**：父类/接口方法上的注解不会带到子类重写方法上；框架扫描时若按实现类方法查找，接口方法注解可能拿不到（Spring AOP 有专门的 `AnnotatedElementUtils.findMergedAnnotation` 处理这类合并查找）。
3. **注解属性必须是编译期常量**：只能用字面量、`static final` 常量、枚举、`Class`、注解或其一维数组，不能传运行期才确定的值。
4. **缓存注解读取结果**：注解查找有反射开销，框架通常在启动时一次性解析并缓存到 `Map<Method, AnnotationMeta>`，运行期不再重复 `getAnnotation`。
5. **`getAnnotation` 与 `getDeclaredAnnotation` 的范围差异**：前者含继承（类场景），后者只看直接标注。拿不准时明确自己要哪种语义。

## 七、使用场景

| 场景 | 说明 |
| ---- | ---- |
| Spring 全家桶 | `@Component` 注册 Bean、`@Autowired` 注入、`@RequestMapping` 路由、`@Transactional` 事务——全部「注解 + 反射」驱动 |
| 单元测试 | JUnit 的 `@Test`/`@BeforeEach`：反射扫描并按注解决定执行流程 |
| 自定义路由/调度 | 根据注解注册任务：扫描 `@Scheduled(cron=...)` 后按 cron 表达式调度 |
| 参数校验 | 自定义 `@Phone`/`@Length` 注解，反射校验字段值合法性 |
| 数据导出 | `@ExcelHeader("列名")` 标注字段，导出 Excel 时按注解决定列头与顺序 |
| 配置绑定 | `@Value("${db.url}")` 反射注入配置值到字段 |

一个参数校验的迷你实现：

```java
import java.lang.annotation.*;
import java.lang.reflect.Field;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotNull {
    String message() default "不能为空";
}

class LoginForm {
    @NotNull(message = "用户名不能为空")
    private String username;

    private String remark;          // 没加注解：不校验
}

public class Validator {
    public static void validate(Object obj) throws Exception {
        for (Field f : obj.getClass().getDeclaredFields()) {
            NotNull rule = f.getAnnotation(NotNull.class);
            if (rule == null) continue;
            f.setAccessible(true);
            if (f.get(obj) == null) {
                System.out.println(f.getName() + " " + rule.message());
            }
        }
    }

    public static void main(String[] args) {
        validate(new LoginForm());  // username 不能为空
    }
}
```

## 八、总结

- 注解是「数据」，反射是「执行力」：`RUNTIME` 保留策略 + `AnnotatedElement` 统一 API（`isAnnotationPresent` / `getAnnotation` / `getAnnotationsByType`），类/字段/方法/构造器/参数通吃。
- 自定义注解三板斧：`@Target` 定位置、`@Retention(RUNTIME)` 保运行时、属性带 `default`。
- `@Inherited` 只对类生效，方法注解不随重写继承——框架注解「写在实现类上」的习惯由此而来。
- 可重复注解用 `getAnnotationsByType` 读取，免手动展开容器注解。
- 「注解 + 反射」是 Java 框架的通用设计范式：启动期扫描缓存，运行期按注解元信息分发执行。
