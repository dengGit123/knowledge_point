# 代码块与初始化顺序

> 📖 官方文档：[Java Language Specification - Static Initializers](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.7) ｜ [Instance Initializers](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.6)

---

### 一、概述

Java 中用大括号 `{}` 包裹、独立于方法之外的代码块，按是否带 `static` 分为两类：

| 类型 | 写法 | 执行时机 | 执行次数 | 所在内存区域 |
|------|------|---------|---------|-------------|
| **静态代码块** | `static { ... }` | 类加载的**初始化阶段** | 只执行 **1 次** | 逻辑上属方法区（类级别） |
| **实例代码块**（构造代码块） | `{ ... }` | **每次创建对象**时，构造方法之前 | 每个对象 **1 次** | 随对象在堆中（对象级别） |

> 💡 **通俗理解**：把类比作"门店"：
> - **静态代码块**是"开业典礼"——装修完（类加载）那天办一次，之后无论接待多少客人（创建对象）都不再办。
> - **实例代码块**是"迎宾流程"——每位客人（对象）进门都要走一遍。
> - **构造方法**是"点单服务"——每位客人还要按各自需求定制（初始化各自的字段值）。

为什么静态代码块只执行一次？为什么实例代码块每次都执行？答案藏在**类加载**和**对象创建**的内存机制里——这正是本文与 [07-类加载机制.md](./07-类加载机制.md)、[08-对象在内存中.md](./08-对象在内存中.md) 的关联点。

### 二、静态代码块：类级别的初始化

#### 1. 执行机制

编译器把**所有静态变量显式赋值 + 静态代码块**按**源码书写顺序**收集成 `<clinit>()` 方法，在类加载的**初始化阶段**由 JVM 执行：

- **只执行一次**：`<clinit>()` 被 JVM 加锁保证线程安全，且仅在类第一次初始化时执行；
- **按书写顺序执行**：多个静态代码块、静态变量赋值混排时，严格按源码先后；
- **静态变量可以先声明后赋值，但"使用"必须在赋值之后**（非法前向引用）。

```java
public class StaticBlockDemo {
    static int a = printInit("① 静态变量 a 赋值");       // <clinit>() 第 1 条

    static {                                            // <clinit>() 第 2 条
        System.out.println("② 静态代码块执行, a=" + a);
    }

    static int b = printInit("③ 静态变量 b 赋值");       // <clinit>() 第 3 条

    static int printInit(String msg) {
        System.out.println(msg);
        return 1;
    }

    public static void main(String[] args) {
        System.out.println("④ main 开始");              // 类已初始化完毕，这里最后执行
        new StaticBlockDemo();
        new StaticBlockDemo();                          // 不会再触发静态代码块
    }
}
// 输出：
// ① 静态变量 a 赋值
// ② 静态代码块执行, a=1
// ③ 静态变量 b 赋值
// ④ main 开始
```

#### 2. 为什么只执行一次？

从内存视角看：静态代码块初始化的数据落在**方法区/类级别**，与堆中对象的个数无关。类的一生只初始化一次，所以静态代码块也只执行一次——类不卸载，静态数据一直存活。

#### 3. 典型应用

```java
public class DbConfig {
    static Properties props = new Properties();

    // 类加载时读取配置文件：全局只需读一次，且保证使用前已就绪
    static {
        try (InputStream in = DbConfig.class
                .getResourceAsStream("/db.properties")) {
            props.load(in);
        } catch (IOException e) {
            throw new ExceptionInInitializerError(e);   // 静态块抛错 → 类初始化失败
        }
    }

    public static String getUrl() {
        return props.getProperty("url");
    }
}
```

其他典型场景：JDBC 驱动注册（`Class.forName` 内部触发的静态块）、单例模式的静态内部类写法、工具类一次性加载字典数据。

> ⚠️ **注意：** 静态代码块抛出异常会导致类初始化失败（`ExceptionInInitializerError`），之后再次使用该类会抛 `NoClassDefFoundError`——这个类在当前 JVM 里"死"了。

### 三、实例代码块：对象级别的初始化

#### 1. 执行机制

实例代码块的代码会被编译器**复制进每一个构造方法**的开头（`this()` 调用除外），因此**每 new 一次执行一次**，且总在构造方法体之前：

```java
public class InstanceBlockDemo {
    int x;

    {                                        // 实例代码块
        System.out.println("② 实例代码块执行");
        x = 10;
    }

    public InstanceBlockDemo() {
        // 编译器实际生成的构造方法：先插入实例代码块内容，再执行原构造体
        System.out.println("③ 无参构造执行, x=" + x);
    }

    public InstanceBlockDemo(int x) {
        System.out.println("③ 有参构造执行, x=" + x);
    }

    public static void main(String[] args) {
        new InstanceBlockDemo();
        new InstanceBlockDemo(5);
    }
}
// 输出：
// ② 实例代码块执行
// ③ 无参构造执行, x=10
// ② 实例代码块执行
// ③ 有参构造执行, x=10
```

#### 2. 与构造方法的分工

| 维度 | 实例代码块 | 构造方法 |
|------|-----------|---------|
| 执行次数 | 每次 `new` 都执行 | 每次 `new` 都执行 |
| 执行顺序 | 先 | 后（编译器把它插在构造体前面） |
| 能否带参数 | 不能 | 能（接收创建参数） |
| 适用场景 | **所有**构造方法都要做的公共初始化 | 按**不同参数**差异化初始化 |

> 💡 **提示：** 实际开发中实例代码块用得很少——"公共初始化"通常抽成私有方法在各构造器里调用，可读性更好。但在阅读框架源码（如 HashMap 的 `putMapEntries` 前置逻辑、线程池）时会遇到。

### 四、完整执行顺序（高频考点）

把静态代码块、实例代码块、构造方法、父类串起来，顺序如下：

```java
public class OrderDemo {
    public static void main(String[] args) {
        new Son("小明");
        System.out.println("───── 第二次创建 ─────");
        new Son("小红");
    }
}

class Parent {
    static { System.out.println("1. Parent 静态代码块"); }
    {      System.out.println("3. Parent 实例代码块"); }
    Parent() { System.out.println("4. Parent 构造方法"); }
}

class Son extends Parent {
    static int s = init();
    static int init() { System.out.println("2. Son 静态变量赋值"); return 1; }
    {      System.out.println("5. Son 实例代码块"); }
    Son(String name) { System.out.println("6. Son 构造方法: " + name); }
}
```

```text
第一次 new Son("小明")：
1. Parent 静态代码块      ← 父类先初始化（类加载，仅一次）
2. Son 静态变量赋值       ← 子类初始化（仅一次）
3. Parent 实例代码块      ← 父类部分先构造
4. Parent 构造方法
5. Son 实例代码块
6. Son 构造方法: 小明

第二次 new Son("小红")：
3. Parent 实例代码块      ← 静态部分不再执行！
4. Parent 构造方法
5. Son 实例代码块
6. Son 构造方法: 小红
```

**规律总结**：

```
父类静态 → 子类静态          （类级别，只执行一次）
父类实例块 → 父类构造 → 子类实例块 → 子类构造   （对象级别，每次 new 都执行）
```

> 💡 **记忆口诀**：**"静先动后、父先子后、块先构后"**——静态先于实例，父类先于子类，代码块先于构造。

### 五、内存视角：三种初始化的对照

把三种代码块放回 JVM 内存区域里看，它们各自的"家"不同：

```
┌──────────────────────────────────────────────────────────────┐
│                        JVM 内存                               │
│                                                              │
│  方法区（类级别，一份）                                        │
│  ┌────────────────────────────────────────────┐              │
│  │ 类元信息（字节码）                           │              │
│  │ 运行时常量池                                 │              │
│  │ <clinit>() ← 静态代码块在这里执行（1 次）     │              │
│  └────────────────────────────────────────────┘              │
│                                                              │
│  堆（对象级别，N 份）                                          │
│  ┌──────────────┐ ┌──────────────┐                           │
│  │ 对象 1        │ │ 对象 2        │                           │
│  │ 实例块+构造    │ │ 实例块+构造    │  ← 每个 new 都走一遍        │
│  │ 初始化的数据   │ │ 初始化的数据   │                           │
│  └──────────────┘ └──────────────┘                           │
│                                                              │
│  虚拟机栈（每线程一份）                                         │
│  ┌────────────┐                                              │
│  │ 栈帧: 局部变量│  ← 构造方法执行时的参数、局部变量在这里          │
│  └────────────┘                                              │
└──────────────────────────────────────────────────────────────┘
```

| 阶段 | 对应内存动作 | 执行次数 |
|------|-------------|---------|
| 类加载·准备 | 方法区中静态变量分配内存，赋**零值** | 1 次 |
| 类加载·初始化 | 执行 `<clinit>()`（静态赋值 + 静态代码块） | 1 次（JVM 加锁） |
| 对象创建·零值 | 堆中对象内存清零（成员变量默认值） | 每个对象 1 次 |
| 对象创建·`<init>()` | 实例代码块 + 构造方法 | 每个对象 1 次 |

> ⚠️ **注意：** `<clinit>()` 与 `<init>()` 是两个不同的方法：`<clinit>()` 是**类**构造器（静态初始化，编译器生成），`<init>()` 是**实例**构造器（实例代码块 + 构造方法）。面试时别混。

### 六、实际应用场景

#### 1. 静态代码块实现单例（饿汉式）

```java
public class Singleton {
    private static final Singleton INSTANCE;

    static {
        // 类加载时创建：JVM 保证 <clinit>() 线程安全且只执行一次
        INSTANCE = new Singleton();
    }

    private Singleton() {}

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

#### 2. 静态内部类单例（懒加载 + 线程安全）

```java
public class LazySingleton {
    private LazySingleton() {}

    // 内部类不会在 LazySingleton 加载时初始化，
    // 首次调用 getInstance() 才触发 Holder 的加载 → 懒加载
    private static class Holder {
        static final LazySingleton INSTANCE = new LazySingleton();
    }

    public static LazySingleton getInstance() {
        return Holder.INSTANCE;   // 首次访问触发 Holder 的 <clinit>()，JVM 保证线程安全
    }
}
```

#### 3. 实例代码块做公共初始化（如 StringBuilder 预分配）

```java
public class ReportBuilder {
    private final StringBuilder sb;

    {
        sb = new StringBuilder(1024);   // 无论用哪个构造器，都先完成预分配
        sb.append("=== 报告 ===\n");
    }

    public ReportBuilder(String title) {
        sb.append("标题：").append(title).append('\n');
    }

    public ReportBuilder(String title, String author) {
        sb.append("标题：").append(title).append('\n');
        sb.append("作者：").append(author).append('\n');
    }
}
```

### 七、常见问题与注意事项

#### Q1：静态代码块能访问实例变量吗？

不能。静态代码块执行时对象还不存在，只能访问静态成员：

```java
public class BlockScopeDemo {
    int instanceVar = 1;
    static int staticVar = 2;

    static {
        // System.out.println(instanceVar);  // ❌ 编译错误：静态上下文访问实例变量
        System.out.println(staticVar);       // ✅ 只能访问静态成员
    }
}
```

#### Q2：静态代码块和静态变量赋值，谁先执行？

**按源码书写顺序**执行（都在 `<clinit>()` 里）。若静态代码块写在静态变量赋值之前，代码块执行时该变量还是零值（或使用会编译报错——非法前向引用）。

#### Q3：接口中可以有代码块吗？

接口**不能有实例代码块和静态代码块**，但可以有静态变量初始化（隐式 `public static final`）。接口初始化时同样执行变量赋值，但不生成静态块。

#### Q4：构造方法执行时，实例代码块一定已经执行了吗？

不一定！当构造方法第一行是 `this(...)` 调用另一个构造器时，实例代码块只会在**最终那个构造器**里执行一次，避免重复初始化。所以严格说是"每个对象创建时实例代码块执行一次"，而非"每个构造方法都执行一次"。

### 八、总结

| 知识点 | 核心要点 |
|--------|---------|
| 静态代码块 | 初始化阶段执行，只 1 次，随 `<clinit>()`，JVM 加锁保证线程安全 |
| 实例代码块 | 每次创建对象执行，编译器复制进构造方法开头 |
| 完整顺序 | 父静 → 子静 →（每次 new）父实例块 → 父构造 → 子实例块 → 子构造 |
| 记忆口诀 | 静先动后、父先子后、块先构后 |
| 内存归属 | 静态初始化数据 → 方法区（类级别）；实例初始化数据 → 堆（对象级别） |
| 单例应用 | 饿汉式 / 静态内部类都依赖 `<clinit>()` 的线程安全与一次性 |

**记住两句话**：

1. **静态代码块 = 类的开业典礼（1 次），实例代码块 = 每位客人的迎宾流程（每次 new）。**
2. **"静先动后、父先子后、块先构后"——执行顺序题秒答。**
