# 实例属性、实例方法、静态属性、静态方法、静态代码块

> 📖 官方文档：[Java Language Specification - Fields](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.3) ｜ [Static Method Declarations](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.4.3.2) ｜ [Static Initializers](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.7)

---

### 一、概述

类里的成员按"**归属谁**"分为两大阵营：**实例成员**（属性、方法）归属**对象**，**静态成员**（属性、方法、代码块）归属**类**。这个归属差异决定了它们存在哪、活多久、怎么访问、线程是否安全——是理解 Java 内存模型的关键一环。

| 成员 | 关键字 | 归属 | 本质 |
|------|--------|------|------|
| 实例属性 | 无修饰（或 `public`/`private` 等） | 对象 | 每个对象**独有一份**，随对象存在堆中 |
| 实例方法 | 无修饰 | 对象 | 隐式接收 `this`，通过对象调用 |
| 静态属性 | `static` | 类 | **全类共享一份**，逻辑上属方法区 |
| 静态方法 | `static` | 类 | 无 `this`，通过类名调用 |
| 静态代码块 | `static { }` | 类 | 类加载初始化时执行，只执行一次 |

> 💡 **通俗理解**：把类比作"产品图纸 + 生产线"：
> - **实例属性**是每件产品的"个性化配置"——每台手机颜色不同，各自存放在各自的产品（堆中对象）里；
> - **静态属性**是挂在车间墙上的"公共看板"——所有产品共享一份产量计数器（全类一份）；
> - **实例方法**是"对某件产品的操作"——必须指明操作哪台手机（`this`）；
> - **静态方法**是"车间级的规定动作"——不需要针对具体产品（无 `this`）；
> - **静态代码块**是"车间投产当天的开机仪式"——只办一次（类初始化）。

语法细节（重写、继承、隐藏等）见 [../类/静态属性.md](../类/静态属性.md)、[../类/静态方法.md](../类/静态方法.md) 等专题文档，本文聚焦**内存视角**：这些成员存在哪、何时生、何时死、怎么访问。

### 二、五大成员的内存归属全景

```java
public class MemberDemo {
    // ── 静态成员：类级别，全类一份 ──────────────────
    static String version = "v1.0";              // ① 静态属性
    static int created = 0;

    static {                                      // ② 静态代码块
        System.out.println("类初始化：只执行一次");
    }

    // ── 实例成员：对象级别，每对象一份 ────────────────
    String name;                                  // ③ 实例属性
    int id;

    void sayHi() {                                // ④ 实例方法
        System.out.println(id + " " + name + " / " + version);
    }

    static int getCreated() {                     // ⑤ 静态方法
        return created;
        // sayHi();                               // ❌ 编译错误：静态方法不能直接调用实例方法
    }

    public MemberDemo(String name) {
        this.name = name;
        created++;                                // 实例构造中更新静态计数器
    }
}
```

```
  栈（线程私有）          堆（线程共享）                  方法区（线程共享）
┌────────────┐    ┌──────────────────────┐    ┌────────────────────────┐
│ main 栈帧  │    │ MemberDemo 对象1      │    │ MemberDemo 类元信息     │
│  m1 ●──────┼──→ │  name = "张三" ③      │    │  类结构/方法字节码       │
├────────────┤    │  id = 1        ③      │    │  ─────────────────     │
│ sayHi 栈帧 │    └──────────────────────┘    │  version="v1.0" ①      │
│  this ●────┼──→ ┌──────────────────────┐    │  created=2       ①     │
│  (指向对象1)│    │ MemberDemo 对象2      │    │  ─────────────────     │
├────────────┤    │  name = "李四" ③      │    │  静态方法字节码 ⑤        │
│ 静态方法调用│    │  id = 2        ③      │    │  <clinit>() ② 执行完毕  │
│ （无需this）│    └──────────────────────┘    │  （version/created      │
└────────────┘                                │   JDK 7+ 实际存于堆中）  │
                                              └────────────────────────┘
```

**从内存图读出的四个关键结论**：

1. **实例属性③在堆中、每个对象一份**：`对象1.name` 和 `对象2.name` 互不干扰；对象被 GC 回收，实例属性随之消失。
2. **静态属性①全类一份**：无论创建多少对象，`version`、`created` 只有一份，所有对象看到的是同一个值（JDK 7 起物理上随 `Class` 对象存于堆，逻辑上属方法区，详见 [06-方法区.md](./06-方法区.md)）。
3. **实例方法④依赖 `this`**：调用 `m1.sayHi()` 时，`this` 指向堆中的对象 1——实例方法的局部变量表 Slot 0 固定是 `this`（见 [03-虚拟机栈与栈帧.md](./03-虚拟机栈与栈帧.md)）。
4. **静态方法⑤不依赖对象**：通过类名调用，栈帧里没有 `this`，因此**无法访问实例成员**。

### 三、访问规则矩阵（高频考点）

谁能访问谁？一张矩阵记牢（以静态方法 / 实例方法两个视角看）：

```java
public class AccessRules {
    static int sField = 1;
    int iField = 2;

    static void staticMethod() {
        System.out.println(sField);    // ✅ 静态方法访问静态属性
        // System.out.println(iField); // ❌ 实例属性：没有对象，iField 是谁的？
        // instanceMethod();           // ❌ 实例方法：需要 this，哪里来的 this？
        AccessRules obj = new AccessRules();
        System.out.println(obj.iField);// ✅ 换个方式：自己 new 一个对象，通过引用访问
        obj.instanceMethod();
    }

    void instanceMethod() {
        System.out.println(sField);    // ✅ 实例方法访问静态属性（类是共享的，当然能访问）
        System.out.println(iField);    // ✅ 实例方法访问实例属性（this.iField）
        staticMethod();                // ✅ 实例方法调用静态方法（等价于 AccessRules.staticMethod()）
    }
}
```

| 调用方 → 被访问方 | 静态属性 | 实例属性 | 静态方法 | 实例方法 |
|------------------|:-------:|:-------:|:-------:|:-------:|
| **静态方法** | ✅ 直接访问 | ❌ 需先创建对象 | ✅ 直接调用 | ❌ 需先创建对象 |
| **实例方法** | ✅ 直接访问 | ✅ 直接访问 | ✅ 直接调用 | ✅ 直接调用 |

> ⚠️ **注意（核心逻辑）：** 记不住矩阵就记一句话——**静态上下文没有 `this`**。实例属性和实例方法都必须依附于某个对象（`this.xxx`），静态方法里没有 `this`，自然访问不了；反过来说，实例方法里静态成员"顺理成章"就能用。

### 四、逐个详解（内存视角）

#### 1. 实例属性（Instance Field）

| 维度 | 说明 |
|------|------|
| 存储位置 | **堆**中对象实例数据区（对象头之后） |
| 生命周期 | 随对象：`new` 时诞生（零值初始化 → 构造赋值），对象不可达后被 GC 回收 |
| 份数 | 每个对象独有一份 |
| 默认值 | 有——对象创建的"零值初始化"步骤赋予（`int`=0、引用=null），见 [08-对象在内存中.md](./08-对象在内存中.md) |
| 访问方式 | 必须通过引用：`obj.field`；实例方法内部可直接写 `field`（隐含 `this.`） |
| 线程安全 | 不安全——堆被共享，多线程同时读写需同步 |

#### 2. 实例方法（Instance Method）

| 维度 | 说明 |
|------|------|
| 字节码存储 | 方法字节码在**方法区只有一份**（所有对象共享同一份方法代码！差异只在 `this` 指向谁） |
| 调用机制 | 通过对象调用，编译器把引用传入：`obj.sayHi()` → `sayHi(this)`；Slot 0 固定是 `this` |
| 生命周期 | 与类相同——字节码随类加载进方法区，不随对象消亡 |
| 线程安全 | 方法本身线程安全（每线程有自己的栈帧，`this` 各指向各自的对象）；但方法内**修改共享数据**（静态属性、堆中对象）时要小心 |
| 覆写（override） | 支持——多态的基础；静态方法不支持覆写（只支持"隐藏"） |

```java
public class ThisDemo {
    private int id;

    public ThisDemo(int id) {
        this.id = id;            // this.id 是实例属性（堆中对象），id 是构造参数（栈帧局部变量表）
    }

    // 编译器视角：实际等价于一个隐藏参数 this
    // void sayHi(ThisDemo this) { System.out.println(this.id); }
    public void sayHi() {
        System.out.println("id = " + id);   // 实际访问的是 this.id
    }
}
```

> 💡 **提示：** "方法字节码只有一份、`this` 各指各的对象"是常被误解的点——100 个对象不会复制 100 份方法代码，它们共享方法区里的同一份 `sayHi()` 字节码，执行时只是传入的 `this` 不同。

#### 3. 静态属性（Static Field）

| 维度 | 说明 |
|------|------|
| 存储位置 | 逻辑上属**方法区**（JDK 7 起物理上随 `java.lang.Class` 对象存于**堆**） |
| 生命周期 | **随类**：类加载准备阶段分配并赋零值，初始化阶段赋真实值，类卸载才回收 |
| 份数 | 全类唯一一份，所有对象共享 |
| 访问方式 | 推荐类名：`MemberDemo.version`；通过对象访问也能编译（`obj.version`），但会被编译器按声明类型解析，易误导 |
| 线程安全 | 不安全——天然共享，`static int count++` 多线程下会丢失更新，需 `AtomicInteger` 或加锁 |
| 典型风险 | **静态集合只增不减是内存泄漏头号来源**（静态属性永远可达，GC 收不走），见 [11-内存溢出与泄漏排查.md](./11-内存溢出与泄漏排查.md) |

```java
public class StaticCounter {
    static int count = 0;                    // 全类一份

    public StaticCounter() {
        count++;                             // 每创建一个对象 +1
    }

    public static void main(String[] args) {
        new StaticCounter();
        new StaticCounter();
        new StaticCounter();
        System.out.println(StaticCounter.count);   // 3 —— 三个对象共享同一个 count
    }
}
```

#### 4. 静态方法（Static Method）

| 维度 | 说明 |
|------|------|
| 字节码存储 | 方法区一份，与实例方法同区；区别是没有隐式 `this` 参数 |
| 调用机制 | 类名直接调用：`Math.max(1, 2)`；无需创建对象 |
| 生命周期 | 随类 |
| 能访问什么 | 静态属性、静态方法；要碰实例成员必须先自己拿到对象引用 |
| 覆写 | ❌ 不支持覆写——`子类.静态方法` 只是"隐藏"父类同名静态方法，调用绑定看**声明类型**（静态绑定） |
| 典型场景 | 工具方法（`Math`、`Arrays`、`Collections`）、工厂方法（`Integer.valueOf`）、`main` 入口 |

```java
public class StaticMethodDemo {
    static String greet() {
        return "hello";
    }

    void demo() {
        System.out.println(greet());         // 实例方法里调用静态方法 ✅
    }

    public static void main(String[] args) {
        System.out.println(StaticMethodDemo.greet());  // ✅ 推荐类名调用
        new StaticMethodDemo().demo();
        System.out.println(new StaticMethodDemo().greet()); // 能编译，但不推荐：按引用的声明类型解析
    }
}
```

#### 5. 静态代码块（Static Block）

| 维度 | 说明 |
|------|------|
| 执行时机 | 类加载的**初始化阶段**：编译器把它收集进 `<clinit>()`，随静态变量赋值按源码顺序执行 |
| 执行次数 | **仅一次**（JVM 保证 `<clinit>()` 线程安全且只执行一次） |
| 能访问什么 | 只能访问静态成员——执行时对象还不存在 |
| 典型用途 | 初始化复杂的静态数据：读配置文件、注册驱动、填充静态 Map、单例创建 |
| 失败后果 | 静态块抛异常 → `ExceptionInInitializerError`，该类在当前 JVM 中不可再用（再引用抛 `NoClassDefFoundError`） |

```java
public class StaticBlockInit {
    static Map<String, Integer> codeMap = new HashMap<>();

    static {
        // 配置项多，一行赋值写不下 → 静态代码块是最佳初始化场所
        codeMap.put("OK", 200);
        codeMap.put("NOT_FOUND", 404);
        codeMap.put("SERVER_ERROR", 500);
        System.out.println("codeMap 初始化完成（只打印一次）");
    }

    public static int code(String key) {
        return codeMap.get(key);
    }
}
```

执行机制与完整顺序（含父类、实例代码块）详见 [09-代码块与初始化顺序.md](./09-代码块与初始化顺序.md)。

### 五、生命周期对比：一句"随谁"决定一切

| 成员 | 诞生时机 | 死亡时机 | 活多久 |
|------|---------|---------|--------|
| 静态属性 / 静态方法 / 静态代码块 | 类加载时（初始化阶段） | 类卸载时（核心类永不卸载） | ≈ 应用全程 |
| 实例属性 | 对象创建时（零值 → 构造） | 对象不可达被 GC 回收时 | 从 `new` 到没人引用 |
| 实例方法（字节码） | 类加载时 | 类卸载时 | ≈ 应用全程（与对象个数无关） |

```
时间轴 ────────────────────────────────────────────────────→
 │类加载                │new              │new          │GC      │JVM 退出
 ▼                     ▼                 ▼             ▼
 [静态成员诞生]──═════════════════════════════════════════════╝ 全程存活
             [实例属性A诞生]═════════╡                ╡ 随对象死亡
                       [实例属性B诞生]═════════════════╡
        （实例方法字节码同样全程存在，只是"被谁调用"随对象变化）
```

> ⚠️ **注意：** 静态成员"活太久"是一把双刃剑：方便共享，也意味着放进静态容器的数据**永远占着内存**。判断标准很简单——这个数据是"类级别的"（全局只有一份语义）才放静态；只要属于"某次业务的对象状态"，一律用实例属性。

### 六、方法调用绑定：静态绑定 vs 动态绑定

静态与实例方法还有一个深层差异——**调用目标确定时机**：

```java
public class BindDemo {
    static class Parent {
        static void staticSay() { System.out.println("Parent.staticSay"); }
        void instanceSay()      { System.out.println("Parent.instanceSay"); }
    }

    static class Son extends Parent {
        static void staticSay() { System.out.println("Son.staticSay"); }      // 隐藏，非覆写
        @Override
        void instanceSay()      { System.out.println("Son.instanceSay"); }     // 覆写
    }

    public static void main(String[] args) {
        Parent p = new Son();
        p.staticSay();       // Parent.staticSay —— 静态方法按【声明类型】静态绑定
        p.instanceSay();     // Son.instanceSay    —— 实例方法按【实际类型】动态绑定（多态）
    }
}
```

| 维度 | 静态方法 | 实例方法 |
|------|---------|---------|
| 绑定时机 | **编译期**（静态绑定） | **运行期**（动态绑定） |
| 绑定依据 | 引用的**声明类型** | 对象的**实际类型** |
| 支持多态 | ❌ | ✅（覆写的根基） |
| 虚方法调用 | 非虚方法（`invokestatic` 指令） | 虚方法（`invokevirtual` 指令） |

> 💡 **提示：** 字节码层面两者用不同指令：静态方法是 `invokestatic`（无需对象），实例方法是 `invokevirtual`（需要操作数栈顶的对象引用）。这也是"静态方法里没有 this"在字节码层的直接体现。

### 七、常见问题与注意事项

#### Q1：静态属性在堆里还是方法区里？

逻辑上属方法区（随类存在、全局一份），JDK 7 起物理实现移入堆中（作为 `java.lang.Class` 对象的一部分）。面试建议两个都答，先逻辑后物理，体现版本视野。详见 [06-方法区.md](./06-方法区.md)。

#### Q2：`main` 方法为什么是静态的？

JVM 启动时**还没有任何对象**，必须有一种"不需要对象就能调用"的方法作入口——静态方法恰好满足。若 `main` 不是静态的，JVM 就得先想办法创建对象才能启动，鸡生蛋问题。

#### Q3：静态方法里能用 `this` 吗？`super` 呢？

都不能。两者都指向对象上下文（`this` 是当前对象、`super` 是父类部分），静态方法调用时没有对象，自然两者皆无。

#### Q4：单线程里改静态属性一定安全吗？

不安全。线程安全与"实例/静态"无关，与"**是否被多线程共享**"有关。静态属性被所有线程共享，`static int count++`（读-改-写三步）在并发下必然丢失更新；实例属性只要不暴露给其他线程就是安全的（见 [03-虚拟机栈与栈帧.md](./03-虚拟机栈与栈帧.md) 的"局部变量天然线程安全"）。

#### Q5：工具类为什么要求"私有构造 + 全静态方法"？

工具类（如 `java.util.Arrays`）无状态——不维护对象级数据，只有类级别的纯函数。私有构造防止被实例化，全静态方法方便直接以类名调用。反面教材是"把可变状态放工具类静态属性里"，多线程下会出各种诡异问题。

### 八、总结

| 成员 | 存哪 | 几份 | 随谁生灭 | 有 this 吗 | 调用绑定 |
|------|------|:---:|---------|:---------:|---------|
| 实例属性 | 堆（对象实例数据） | 每对象一份 | 对象 | —— | 通过引用访问 |
| 实例方法 | 方法区（字节码） | 全类一份代码 | 类（代码）/ 对象（this） | ✅ Slot 0 | 动态绑定（多态） |
| 静态属性 | 方法区（逻辑）/ 堆（JDK 7+ 物理） | 全类一份 | 类 | ❌ | 类名访问 |
| 静态方法 | 方法区 | 全类一份 | 类 | ❌ | 静态绑定 |
| 静态代码块 | `<clinit>()` 执行 | 全类一次 | 类初始化 | ❌ | 不可调用，仅初始化时执行 |

**记住三句话**：

1. **静态成员随类生灭、全类一份、活在无 this 的世界；实例成员随对象生灭、每对象一份。**
2. **方法字节码全类只有一份，实例方法的差异只在传入的 `this` 不同——静态方法连 this 都没有。**
3. **线程安全的判据是"是否被多线程共享"，不是"是否 static"——但静态属性天然共享，十有八九要防并发。**
