# 虚拟机栈与栈帧

> 📖 官方文档：[The Java Virtual Machine Specification - Java Virtual Machine Stacks](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5.2) ｜ [Frames](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.6)

---

### 一、概述

**Java 虚拟机栈**（Java Virtual Machine Stack）是线程私有的内存区域，生命周期与线程相同。线程每执行一个方法，JVM 就会在它的虚拟机栈中创建一个**栈帧（Stack Frame）**——方法内的局部变量、计算过程的中间结果，都存在栈帧里。

> 💡 **通俗理解**：虚拟机栈像一摞盘子。调用一个方法 = 往上放一个盘子（入栈），方法执行完 = 拿走这个盘子（出栈）。永远只操作最顶上的盘子——也就是"当前正在执行的方法"。
>
> ```text
> 调用链：main() → methodA() → methodB()
>
>        ┌─────────────┐
>        │ methodB 栈帧 │ ← 栈顶（当前方法）
>        ├─────────────┤
>        │ methodA 栈帧 │
>        ├─────────────┤
>        │  main 栈帧   │ ← 栈底
>        └─────────────┘
> ```
> 方法 B 执行完，它的盘子被拿走，methodA 自动成为新的栈顶，从调用点继续往下执行——这就是方法调用的全部秘密。

方法执行为什么快、局部变量为什么线程安全、递归为什么会爆栈，答案都在这摞"盘子"里。

### 二、栈帧的内部结构

栈帧是方法运行时的"私有工作区"，包含五个部分（前三部分最常考）：

```
┌───────────────────────────────────────┐
│         栈帧（Stack Frame）            │
├───────────────────────────────────────┤
│ ① 局部变量表（Local Variables）        │ ← 方法参数 + 方法内局部变量
├───────────────────────────────────────┤
│ ② 操作数栈（Operand Stack）            │ ← 执行字节码指令的工作区
├───────────────────────────────────────┤
│ ③ 动态链接（Dynamic Linking）          │ ← 指向运行时常量池中该方法的引用
├───────────────────────────────────────┤
│ ④ 方法返回地址（Return Address）       │ ← 方法结束后回到调用处的位置
├───────────────────────────────────────┤
│ ⑤ 附加信息                            │ ← 调试信息等（实现相关）
└───────────────────────────────────────┘
```

#### 1. 局部变量表

存放**方法参数**和**方法体内定义的局部变量**，以**变量槽（Slot）** 为最小单位：

- 一个 Slot 占 32 位：`int`、`float`、引用、`returnAddress` 各占 1 个 Slot；`long`、`double` 占 2 个 Slot。
- `byte`、`short`、`char` 在存储前会被转为 `int`，也占 1 个 Slot。
- 实例方法的第 0 个 Slot 固定存放 `this`（所以静态方法里没有 `this`）。
- **基本类型直接存值，引用类型存地址**（指向堆中的对象）。

```java
public class SlotDemo {
    private int count = 0;                      // 成员变量 → 存在堆的对象里，不在局部变量表

    public int calc(int a, int b) {             // a、b 是参数 → Slot 1、Slot 2
        int sum = a + b;                        // sum 是局部变量 → 新的 Slot
        return sum;
    }

    public static int staticCalc(int x) {       // 静态方法没有 this，x 就是 Slot 0
        return x * 2;
    }
}
```

> 💡 **提示：** 局部变量没有默认值！类加载时被零值初始化的是**堆中的成员变量**，而局部变量表不经过这个步骤，所以局部变量必须先赋值再使用，否则编译报错。这与 [08-对象在内存中.md](./08-对象在内存中.md) 讲的对象创建流程直接相关。

#### 2. 操作数栈

字节码指令的"临时工作台"，是一个后进先出（LIFO）的栈。算术运算、方法传参、接收返回值，都通过它完成。以 `a + b` 为例，字节码是这样执行的：

```text
int c = a + b;   对应字节码（a=1, b=2 时）：

iload_1    ; 把局部变量表 Slot 1 的 a(1) 压入操作数栈     栈: [1]
iload_2    ; 把局部变量表 Slot 2 的 b(2) 压入操作数栈     栈: [1, 2]
iadd       ; 弹出两个值相加，结果压回栈                   栈: [3]
istore_3   ; 弹出栈顶 3，存入局部变量表 Slot 3（c）       栈: []
```

> ⚠️ **注意：** 操作数栈的最大深度在**编译期**就确定了，写进 Class 文件的 `Code` 属性里。递归或超长表达式会让栈帧变大，占用更多栈空间。

#### 3. 动态链接

每个栈帧持有一个引用，指向**运行时常量池**中当前方法所属的符号引用。方法调用时需要把常量池里的"符号引用"（如 `Person.sayHi()` 这种名字描述）转换成"直接引用"（真实的内存地址）：

- **静态链接（早期绑定）**：编译期就能确定目标方法（`private`、`static`、构造器、`final` 方法），类加载时直接替换。
- **动态链接（晚期绑定）**：运行期才能确定（多态调用 `p.sayHi()` 到底执行哪个重写版本），每次调用时动态解析。

多态的实现就依赖动态链接——运行时根据对象的实际类型找到目标方法。

#### 4. 方法返回地址

方法退出的两种方式，殊途同归都要恢复调用者的执行现场：

| 退出方式 | 触发 | 返回地址来源 |
|---------|------|-------------|
| 正常完成 | 遇到 `return` 指令 | 调用者的 PC 计数器值（调用指令的下一条） |
| 异常完成 | 抛出异常且未捕获 | 通过异常处理表确定，栈帧中不保存返回地址 |

### 三、方法的调用与栈的运作

把一次完整的方法调用串起来看：

```java
public class StackDemo {
    public static void main(String[] args) {         // ① main 栈帧入栈
        int result = add(1, 2);                      // ② add 栈帧入栈，参数 1、2 存入其局部变量表
        System.out.println(result);                  // ⑤ add 返回 3，回到这行继续
    }

    static int add(int a, int b) {
        int sum = a + b;                             // ③ 在操作数栈中完成加法，结果存局部变量表
        return sum;                                  // ④ sum 作为返回值传回，add 栈帧出栈
    }
}
```

时间线：

```
main 入栈 → add 入栈 → add 执行 → add 出栈（返回 3）→ main 继续 → main 出栈（程序结束）

栈的变化：
[main]                        ← main 调用 add 前
[main, add]                   ← 调用 add，add 成为栈顶（当前方法）
[main]                        ← add 结束出栈，main 拿到返回值继续执行
[]                            ← main 结束，栈空，线程结束
```

### 四、两种异常：StackOverflowError 与 OutOfMemoryError

| 异常 | 触发条件 | 典型场景 |
|------|---------|---------|
| `StackOverflowError` | 栈深度超过允许的最大深度（`-Xss` 可调） | 递归没有终止条件、递归层级过深、方法调用链过长 |
| `OutOfMemoryError` | 动态扩展栈时申请不到内存 | 创建过多线程（每个线程都要分一块栈内存） |

```java
// ❌ 经典死递归：没有终止条件，栈帧无限入栈
public class OverflowDemo {
    private static int depth = 0;

    public static void recursion() {
        depth++;                 // 记录递归深度
        recursion();             // 每调用一次压入一个栈帧，最终 StackOverflowError
    }

    public static void main(String[] args) {
        try {
            recursion();
        } catch (StackOverflowError e) {
            System.out.println("爆栈时递归深度：" + depth); // 默认 -Xss 下通常是几千到一万左右
        }
    }
}

// ✅ 正确写法：必须有让递归"停下"的边界条件
public static int factorial(int n) {
    if (n <= 1) return 1;        // 边界条件：递归出口
    return n * factorial(n - 1);
}
```

> ⚠️ **注意：** `StackOverflowError` 继承自 `Error` 而不是 `Exception`，属于"程序无法恢复的严重错误"。`try-catch` 能捕获它，但正确做法是**修掉无限递归**，而不是捕获后继续跑。

#### 栈大小参数 `-Xss`

```bash
# 设置每个线程的栈大小为 512KB（JDK 8+ Linux/x86-64 默认 1MB）
java -Xss512k MyApp

# 栈越小 → 可容纳的栈帧越少 → 递归深度越小；创建大量线程时，小栈能容纳更多线程
```

> 💡 **提示：** 栈内存是"单线程栈大小 × 线程数"的总账。想跑更多线程（如高并发网关）可调小 `-Xss`；递归很深（如深层树遍历）可调大 `-Xss`。这是个此消彼长的权衡。

### 五、栈上的一笔账：为什么局部变量天然线程安全

多个线程共享堆和方法区，但**每个线程的栈是私有的**——这带来一个重要推论：

```java
public class SafeDemo {
    private int memberCount = 0;            // ❌ 成员变量在堆中，多线程共享，需要同步

    public void unsafe() {
        memberCount++;                      // 多线程同时执行会丢失更新
    }

    public int safe(int input) {
        int local = input * 2;              // ✅ 局部变量在当前线程的栈帧里，其他线程碰不到
        return local + 1;
    }
}
```

只要变量的生命周期限制在方法内部（不逃逸出去），它就天然线程安全。这也是 Java 多线程规范的基石之一：**共享才需要同步**。

### 六、与堆的关系：引用的诞生

栈帧的局部变量表里，引用类型只存一个"地址"，真正的对象在堆中：

```java
public class RefDemo {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder("hi"); // sb（引用）→ 栈；StringBuilder 对象 → 堆
        append(sb);                                  // 把"地址"复制一份传给 append
        System.out.println(sb);                      // 输出 hi-world：堆中同一个对象被修改了
    }

    static void append(StringBuilder s) {
        s.append("-world");                          // s 和 sb 指向堆中同一个对象
        s = null;                                    // ❗ 只是把局部引用 s 置空，不影响 sb
    }
}
```

> 💡 **提示：** Java 的方法传参是**值传递**——引用类型传的是"地址的副本"。方法内通过副本地址修改堆中对象，外部可见；但让副本指向新对象，外部无感。详见 [08-对象在内存中.md](./08-对象在内存中.md) 的"引用与对象访问"一节。

### 七、本地方法栈

**本地方法栈（Native Method Stack）** 与虚拟机栈作用非常相似，区别只有一点：

| 对比项 | 虚拟机栈 | 本地方法栈 |
|--------|---------|-----------|
| 服务的对象 | Java 方法（字节码） | Native 方法（C/C++ 实现） |
| 异常 | `StackOverflowError` / OOM | `StackOverflowError` / OOM |
| HotSpot 实现 | **两者合二为一**（HotSpot 不区分） | 同左 |

什么是 Native 方法？被 `native` 修饰、没有方法体的方法，实现写在 C/C++ 动态库中：

```java
public class Object {
    // native 修饰：方法体不在 Java 里，由本地库实现
    public native int hashCode();

    // Java 方法对比：有方法体，跑在虚拟机栈上
    public boolean equals(Object obj) {
        return (this == obj);
    }
}
```

调用 Native 方法时，执行从虚拟机栈切换到本地方法栈，进入操作系统层面的函数调用。

### 八、总结

| 知识点 | 核心要点 |
|--------|---------|
| 虚拟机栈 | 线程私有，生命周期与线程相同，方法调用以栈帧为单位入栈/出栈 |
| 栈帧五要素 | 局部变量表、操作数栈、动态链接、返回地址、附加信息 |
| 局部变量表 | Slot 为单位，基本类型存值、引用存地址，实例方法 Slot 0 是 `this` |
| 操作数栈 | 字节码运算的临时工作台，深度编译期确定 |
| 异常 | 深度超限 `StackOverflowError`；扩展失败 OOM |
| 线程安全 | 栈私有 ⇒ 局部变量天然线程安全 |
| 本地方法栈 | 服务 Native 方法，HotSpot 中与虚拟机栈合并 |

**记住三句话**：

1. **一个方法一个栈帧，方法调用即入栈，方法结束即出栈，永远在操作栈顶。**
2. **局部变量表存值和地址，真正的对象实体在堆里。**
3. **递归没出口就 `StackOverflowError`，`-Xss` 控制每个线程的栈有多大。**
