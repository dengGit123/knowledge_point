# JVM 内存区域总览

> 📖 官方文档：[The Java Virtual Machine Specification - Run-Time Data Areas](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5) ｜ [HotSpot Virtual Machine Garbage Collection Tuning Guide](https://docs.oracle.com/en/java/javase/21/gctuning/introduction.html)

---

### 一、概述

JVM（Java Virtual Machine，Java 虚拟机）是 Java 程序的"运行引擎"。它负责把 `.class` 字节码翻译成机器指令执行，并在执行过程中**自动管理内存**——这也是 Java 与 C/C++ 最大的区别：C 程序员要手动 `malloc`/`free`，Java 程序员只管 `new`，内存的分配与释放都由 JVM 代劳。

JVM 管理内存的方式，是先把申请到的内存**划分成若干个区域（运行时数据区）**，不同区域存放不同类型的数据、遵循不同的生命周期、采用不同的回收策略。

> 💡 **通俗理解**：JVM 就像一座"自动化工厂"，里面划分了不同的车间：
> - **堆**是"成品仓库"——所有 `new` 出来的对象都堆在这里，仓库管理员（GC）定期清理没人要的货。
> - **虚拟机栈**是"工人的工作台"——每个线程（工人）有自己的工作台，上面放着正在处理的任务（方法调用）。
> - **方法区**是"图纸资料室"——存放所有产品的"设计图纸"（类信息）、常用规格（常量）。
> - **程序计数器**是"工人做到第几步的小本本"——CPU 切走再切回来，靠它知道接着干哪一步。

理解内存区域划分，是理解**对象存储、垃圾回收、内存溢出（OOM）、多线程可见性**的地基。

### 二、运行时数据区全景图

JVM 规范（JVMS）定义了 5 个运行时数据区，按"**线程是否共享**"分成两组（基于 JDK 8+，方法区由元空间实现）：

```
┌──────────────────────────────────────────────────────────────┐
│                    JVM 运行时数据区（JDK 8+）                  │
├──────────────────────┬───────────────────────────────────────┤
│                      │   程序计数器（PC Register）  线程私有   │
│                      ├───────────────────────────────────────┤
│   线程隔离区域        │   虚拟机栈（VM Stack）      线程私有   │
│ （每个线程独有一份，  │   ┌─────────────┐                     │
│   线程创建时分配，    │   │ 栈帧（方法） │ ← 方法调用入栈      │
│   线程结束时回收）    │   └─────────────┘                     │
│                      ├───────────────────────────────────────┤
│                      │   本地方法栈（Native Stack）线程私有   │
├──────────────────────┼───────────────────────────────────────┤
│                      │                      ┌──────────────┐ │
│   线程共享区域        │   堆（Heap）         │ 新生代        │ │
│ （随 JVM 启动创建，   │  （对象实例存放处）   │ Eden/S0/S1   │ │
│   JVM 关闭才销毁）    │                      ├──────────────┤ │
│                      │                      │ 老年代        │ │
│                      │                      └──────────────┘ │
│                      ├───────────────────────────────────────┤
│                      │   方法区（Method Area）                │
│                      │   JDK 8+ 由元空间实现（使用本地内存）   │
│                      │   类信息、运行时常量池、JIT 代码        │
└──────────────────────┴───────────────────────────────────────┘
         之外还有：直接内存（Direct Memory，不属于规范定义的数据区）
```

**为什么这样分？** 核心依据是**生命周期**：

| 分组 | 成员 | 生命周期 | 原因 |
|------|------|---------|------|
| 线程私有 | 程序计数器、虚拟机栈、本地方法栈 | 与线程相同——线程创建时分配，线程结束时回收 | 每个线程执行到哪、调用链多深，是线程自己的状态，不能共享 |
| 线程共享 | 堆、方法区 | 与 JVM 相同——随虚拟机启动而创建，随虚拟机退出而销毁 | 对象和类信息需要被所有线程访问 |

### 三、五大区域速览

每个区域在这里只需要混个"脸熟"，详细内容见各自文档。

#### 1. 程序计数器（Program Counter Register）

记录当前线程正在执行的字节码指令**地址（行号）**。线程私有，是**唯一不会发生 `OutOfMemoryError`** 的区域。CPU 时间片轮转切换线程后，靠它恢复到正确的执行位置。

👉 详见 [02-程序计数器.md](./02-程序计数器.md)

#### 2. 虚拟机栈（Java Virtual Machine Stack）

线程私有。每次**方法调用**都会创建一个**栈帧（Stack Frame）**压栈，方法结束栈帧出栈。栈帧里放着局部变量表、操作数栈等。递归过深会抛 `StackOverflowError`。

👉 详见 [03-虚拟机栈与栈帧.md](./03-虚拟机栈与栈帧.md)

#### 3. 本地方法栈（Native Method Stack）

线程私有。与虚拟机栈作用类似，但服务于 **Native 方法**（用 C/C++ 实现的方法）。HotSpot 虚拟机中两者**合二为一**，不单独区分。

👉 详见 [03-虚拟机栈与栈帧.md](./03-虚拟机栈与栈帧.md)（含本地方法栈）

#### 4. 堆（Heap）

线程共享，**最大的一块**。存放**几乎所有对象实例和数组**，是**垃圾回收（GC）的主战场**。内部分新生代（Eden + 两个 Survivor）和老年代。空间不足抛 `OutOfMemoryError: Java heap space`。

👉 详见 [05-堆.md](./05-堆.md)

#### 5. 方法区（Method Area）

线程共享。存放**类元信息、运行时常量池、静态变量、JIT 编译后的代码**。JDK 8 起由**元空间（Metaspace）** 实现，使用**本地内存**，不再是堆的一部分。

👉 详见 [06-方法区.md](./06-方法区.md)

#### 五大区域对比总表

| 区域 | 线程私有 | 存储内容 | 生命周期 | 异常类型 |
|------|:-------:|---------|---------|---------|
| 程序计数器 | ✅ | 字节码执行地址 | 与线程相同 | 无（唯一不 OOM） |
| 虚拟机栈 | ✅ | 栈帧（局部变量表、操作数栈） | 与线程相同 | `StackOverflowError` / `OutOfMemoryError` |
| 本地方法栈 | ✅ | 为 Native 方法服务 | 与线程相同 | `StackOverflowError` / `OutOfMemoryError` |
| 堆 | ❌ | 对象实例、数组 | 与 JVM 相同 | `OutOfMemoryError: Java heap space` |
| 方法区 | ❌ | 类信息、运行时常量池、静态变量 | 与 JVM 相同 | `OutOfMemoryError: Metaspace`（JDK 8+） |

### 四、五大区域如何协作（一个对象的旅程）

以一行代码为线索，看数据在各区域间怎么流动：

```java
public class Demo {
    public static void main(String[] args) {        // ① main 所在的 Demo 类信息 → 方法区
        int x = 10;                                 // ② x → main 栈帧的局部变量表（栈）
        Person p = new Person("张三");               // ③ Person 类元信息 → 方法区
                                                    //    Person 对象 → 堆
                                                    //    引用 p → 栈，指向堆中对象
        p.sayHi();                                  // ④ sayHi 栈帧入栈，方法内 this 指向堆中 p 对象
    }
}
```

```
   虚拟机栈（线程私有）          堆（线程共享）            方法区（线程共享）
  ┌───────────────┐                        ┌──────────────┐     ┌──────────────────┐
  │ main 栈帧     │                        │ Person 对象  │     │ Demo 类元信息     │
  │  x = 10       │                        │  对象头       │────→│ Person 类元信息   │
  │  p ●──────────┼─────── 引用 ─────────→ │  name="张三" │     │  sayHi() 字节码   │
  ├───────────────┤                        │  sayHi 入口 ─┼────→│  运行时常量池      │
  │ sayHi 栈帧    │                        └──────────────┘     └──────────────────┘
  │  this ●───────┼──── 指向堆中对象
  └───────────────┘
```

三个关键结论（后面所有文档都围绕它们展开）：

1. **`new` 出来的都在堆**，局部变量（含对象引用）都在**栈**，类信息、常量在**方法区**。
2. 栈中的引用只是一个**地址**，真正的对象实体在堆里——这就是"引用类型"的含义。
3. 对象没人引用后不会立刻消失，要等 **GC**（垃圾回收）来收走，详见 [10-垃圾回收.md](./10-垃圾回收.md)。

### 五、方法区的实现演变（高频考点）

"方法区"是 JVM **规范**中定义的概念，而"永久代/元空间"是 HotSpot 虚拟机对这个概念的**实现**——概念没变，实现一直在变：

| JDK 版本 | 方法区实现 | 所在位置 | 典型 OOM |
|---------|-----------|---------|---------|
| JDK 6 及以前 | 永久代（PermGen） | JVM 进程内存，有固定上限（`-XX:MaxPermSize`） | `OOM: PermGen space` |
| JDK 7 | 永久代（瘦身中） | 字符串常量池已移到堆 | `OOM: PermGen space` |
| **JDK 8+** | **元空间（Metaspace）** | **本地内存**（机器物理内存） | `OOM: Metaspace` |

> ⚠️ **注意：** 元空间使用的**本地内存**不属于 Java 堆，`-Xmx` 调再大也不会给元空间多分一点。元空间默认不设上限（用多少占多少物理内存），生产环境建议用 `-XX:MaxMetaspaceSize` 显式限制，防止吃光系统内存。

### 六、直接内存（规范之外）

**直接内存（Direct Memory）** 不是 JVM 规范定义的运行时数据区，但实际开发绕不开：

- **NIO** 通过 `ByteBuffer.allocateDirect()` 分配**堆外内存**，避免数据在 Java 堆和本地内存之间来回复制，提升 IO 性能（Netty、Kafka 等高性能框架重度使用）。
- 受机器物理内存限制，分配失败会抛 `OutOfMemoryError: Direct buffer memory`。

```java
import java.nio.ByteBuffer;

// 分配 1MB 直接内存（堆外内存），不占用 -Xmx 划出的堆空间
ByteBuffer buffer = ByteBuffer.allocateDirect(1024 * 1024);
```

### 七、与相关概念辨析

初学者容易把几个"内存模型"混为一谈，这里一次性分清：

| 术语 | 全称 | 说的是什么 | 解决什么问题 |
|------|------|-----------|-------------|
| **运行时数据区** | Runtime Data Areas | JVM 把内存划成哪几块、各放什么 | 内存"怎么分" |
| **JMM（Java 内存模型）** | Java Memory Model | 多线程之间共享变量的**可见性、有序性**规则（`volatile`、`happens-before`） | 并发"怎么对" |
| **对象内存布局** | Object Memory Layout | 一个对象在堆里由哪几部分组成 | 对象"长什么样" |

> 💡 **提示：** 面试官问"JVM 内存模型"时，十有八九指的是**运行时数据区**；问 `volatile`、线程安全时，指的是 **JMM**。两者名字相近，内容完全不同。

### 八、总结

| 知识点 | 核心要点 |
|--------|---------|
| 五大区域 | 程序计数器、虚拟机栈、本地方法栈（线程私有）；堆、方法区（线程共享） |
| 唯一不 OOM | 程序计数器 |
| 对象放哪 | 实例在堆，局部变量在栈，类信息在方法区 |
| 方法区演变 | 永久代（JDK 7-）→ 元空间（JDK 8+，本地内存） |
| 规范之外 | 直接内存：NIO 堆外内存，受物理内存限制 |
| 别混淆 | 运行时数据区（内存分区）≠ JMM（并发可见性规则） |
