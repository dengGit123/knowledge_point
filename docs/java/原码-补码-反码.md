# 原码、反码、补码

> 📖 [Java Language Specification — Binary Numeric Promotion](https://docs.oracle.com/javase/specs/jls/se17/html/jls-5.html#jls-5.6.2)

## 一、概述

计算机中的**有符号整数**有三种表示方式：**原码**、**反码**、**补码**。它们解决的核心问题是：**如何让计算机用二进制表示负数，并统一加减法运算**。

| 表示法 | 核心思想 | 现状 |
| --- | --- | --- |
| **原码** | 最高位为符号位（0 正 1 负），其余为绝对值 | 直观但运算复杂，已被淘汰 |
| **反码** | 正数不变，负数符号位不变、其余位取反 | 过渡方案，存在 ±0 问题 |
| **补码** | 正数不变，负数反码 + 1 | **现代计算机统一使用**，Java 整数采用此方案 |

> 💡 **一句话记忆：** 原码是"人看的"，补码是"机器用的"。Java 中所有整数类型（`byte`、`short`、`int`、`long`）底层都用**补码**存储。

## 二、原码（Sign-Magnitude）

### 1. 定义

原码是最直观的表示方式：**最高位为符号位，其余位表示数值的绝对值**。

- 符号位：`0` 表示正数，`1` 表示负数
- 数值位：与原数的二进制相同

### 2. 表示规则（以 8 位为例）

```
[+5]原 = 00000101    // 符号位 0，数值位 101
[-5]原 = 10000101    // 符号位 1，数值位 101
[+0]原 = 00000000
[-0]原 = 10000000    // ⚠️ 原码中 0 有两种表示
```

### 3. 原码的取值范围（n 位）

```
范围：-(2^(n-1) - 1) ~ +(2^(n-1) - 1)

8 位：-127 ~ +127（存在 +0 和 -0）
32 位（int）：-2147483647 ~ +2147483647
```

### 4. 原码的运算问题

原码做加减法时，**符号位需要单独判断**，不能直接运算：

```
  00000101    (+5)
+ 10000101    (-5)
──────────
  10001010    (-10)  ❌ 错误！实际应为 0
```

> ⚠️ **问题根源：** 符号位参与运算会导致结果错误。原码的加法和减法需要不同的电路逻辑，硬件实现复杂。

## 三、反码（Ones' Complement）

### 1. 定义

反码是为了解决原码运算问题而提出的过渡方案：

- **正数**：反码与原码相同
- **负数**：符号位不变，其余位**按位取反**（0 变 1，1 变 0）

### 2. 表示规则（以 8 位为例）

```
[+5]反 = 00000101    // 正数，与原码相同
[-5]反 = 11111010    // 符号位不变，0000101 取反 → 1111010

[+0]反 = 00000000
[-0]反 = 11111111    // ⚠️ 反码中 0 也有两种表示
```

### 3. 反码的计算方法

求 -X 的反码（n 位）：

```
方法：先写出 +X 的原码，符号位保持为 1，其余位全部取反

示例：求 -3 的 8 位反码
+3 原码 = 00000011
-3 反码 = 11111100   （符号位 1，其余 0000011 取反 → 1111100）
```

### 4. 反码的运算

反码做加法时，符号位**参与运算**，但**最高位的进位需要加到最低位**（循环进位）：

```
  00000101    (+5 的反码)
+ 11111010    (-5 的反码)
──────────
  11111111    (-0 的反码)  ✅ 结果是 0
```

```
  00000101    (+5 的反码)
+ 11111001    (-6 的反码)
──────────
  11111110    (-0 的反码)  ⚠️ 结果是 -0，不是 -1
```

> ⚠️ **反码的问题：** 存在 +0 和 -0 两种零的表示，且跨零运算（如 5 + (-6)）需要额外的循环进位操作，硬件实现仍有负担。

## 四、补码（Two's Complement）⭐ 核心

### 1. 定义

补码是**现代计算机统一采用的整数表示方法**，Java 中所有整数类型底层都是补码：

- **正数**：补码与原码相同
- **负数**：反码 + 1（或者说：从原码 → 符号位不变其余取反 → 再加 1）

### 2. 表示规则（以 8 位为例）

```
[+5]补 = 00000101    // 正数，与原码相同
[-5]补 = 11111011    // 反码 11111010 + 1 = 11111011

[+0]补 = 00000000
[-0]补 = 00000000    // ✅ 反码 11111111 + 1 = 100000000，溢出后 = 00000000
```

### 3. 补码的计算方法

#### 方法一：原码 → 反码 → 补码

```
求 -5 的 8 位补码：

+5 原码：00000101
取反（符号位不变）：11111010    ← 这是反码
加 1：11111011                    ← 这是补码
```

#### 方法二：从右往左，第一个 1 之前的所有位取反

```
求 -5 的 8 位补码：

+5 原码：00000101
从右找第一个 1，它左边的所有位（含符号位）取反：
           ↓↓↓↓↓
结果：    11111011    ← 补码

解释：第一个 1 右边不变（011），左边全取反（00000 → 11111）
```

#### 方法三：公式法（适用于任意位数）

```
负数 X 的补码 = 2^n + X    （n 为位数）

示例：-5 的 8 位补码
= 2^8 + (-5)
= 256 - 5
= 251
= 11111011（二进制）✅
```

### 4. 补码的取值范围（n 位）

```
范围：-2^(n-1) ~ +(2^(n-1) - 1)

8 位（byte）：-128 ~ +127
16 位（short）：-32768 ~ +32767
32 位（int）：-2147483648 ~ +2147483647
64 位（long）：-9223372036854775808 ~ +9223372036854775807
```

> 💡 **为什么负数比正数多一个？** 因为 0 占了一个正数的位置（`000...0`），而负数多出来的那个就是最小值（`100...0`）。

```
8 位最小值：10000000 → -128
-128 的补码没有对应的原码和反码！
```

### 5. 补码的运算优势

补码的最大优势：**加减法统一为加法运算，符号位直接参与计算，无需额外判断**。

```
  00000101    (+5 的补码)
+ 11111011    (-5 的补码)
──────────
1 00000000    // 溢出舍去，结果为 00000000 = 0 ✅

  00000101    (+5 的补码)
+ 11111010    (-6 的补码)
──────────
  11111111    // 直接得到 -1 的补码 ✅
```

> 💡 **核心原理：** 补码的设计使得 `X + (-X) = 0`（模 2^n 意义下），所以减法 `A - B` 可以变成 `A + (-B)` 来做。

## 五、三种码的相互转换

### 转换关系图

```
        ┌─────────────────────────────────────┐
        │            正数（>0）                │
        │   原码 == 反码 == 补码               │
        └─────────────────────────────────────┘

        ┌─────────────────────────────────────┐
        │            负数（<0）                │
        │                                     │
        │  原码 ──取反──→ 反码 ──+1──→ 补码   │
        │   ↑                        │       │
        │   └───── 再走一遍 ←────────┘       │
        │   （补码取反+1 也能回到原码）        │
        └─────────────────────────────────────┘
```

### 转换规则表

| 转换方向 | 操作步骤 |
| --- | --- |
| **原码 → 反码** | 正数不变；负数符号位不变，其余位取反 |
| **反码 → 原码** | 正数不变；负数符号位不变，其余位取反（反操作） |
| **反码 → 补码** | 正数不变；负数 + 1 |
| **补码 → 反码** | 正数不变；负数 - 1 |
| **补码 → 原码** | 正数不变；负数符号位不变，取反，再 + 1 |
| **原码 → 补码** | 正数不变；负数符号位不变，取反，再 + 1 |

### 转换示例（以 -6 的 8 位为例）

```
原码 → 补码：
+6 原码 = 00000110
符号位变 1 = 10000110    （原码）
其余取反   = 11111001    （反码）
加 1      = 11111010    （补码）

补码 → 原码：
补码      = 11111010
减 1      = 11111001    （反码）
其余取反   = 10000110    （原码）
```

### Java 验证

```java
int num = -6;
// 打印补码的二进制形式
System.out.println(Integer.toBinaryString(num));
// 输出：11111111111111111111111111111010（32 位补码）

// 验证：补码取反 + 1 得到原码的绝对值
int complement = num;
int inverted = ~complement;     // 按位取反
int original = inverted + 1;    // 加 1
System.out.println(original);   // 6 ✅
```

## 六、Java 中的实际应用

### 1. 按位取反运算符 `~`

`~` 是对补码进行**按位取反**（包括符号位），结果仍是补码：

```java
int a = 5;          // 补码：00000000 00000000 00000000 00000101
int b = ~a;         // 取反：11111111 11111111 11111111 11111010
System.out.println(b);  // -6 ✅

// 公式：~x = -x - 1
System.out.println(~5);   // -6
System.out.println(~0);   // -1
System.out.println(~-1);  // 0
```

### 2. 负数快速求值技巧

```java
// 一个负数的补码，按位取反 + 1 得到它的绝对值
int neg = -100;
int abs = ~neg + 1;     // 等价于 Math.abs(neg)
System.out.println(abs); // 100
```

### 3. 移位运算符

```java
// 算术右移 >>：符号位不变，整体右移（补码操作）
int a = -8;             // 补码：11111111 11111111 11111111 11111000
int b = a >> 1;         // 算术右移：11111111...11111100 = -4
System.out.println(b);  // -4（除以 2，向下取整）

// 逻辑右移 >>>：高位补 0
int c = a >>> 1;        // 逻辑右移：01111111...11111100 = 2147483644
System.out.println(c);  // 2147483644（变成正数）
```

### 4. 溢出与回绕

```java
int max = Integer.MAX_VALUE;  // 01111111...11111111 = 2147483647
int overflow = max + 1;       // 10000000...00000000 = -2147483648
System.out.println(overflow); // -2147483648  ⚠️ 溢出回绕到最小值
```

## 七、常见陷阱

### 1. 最小值的特殊性

```java
// Integer.MIN_VALUE 的补码：10000000 00000000 00000000 00000000
// 它没有对应的原码和反码！

int min = Integer.MIN_VALUE;
System.out.println(-min);              // -2147483648  ⚠️ 取负后还是自己！
System.out.println(Math.abs(min));     // -2147483648  ⚠️ abs 也无法取正

// 原因：+2147483648 超出了 int 最大值（2147483647），无法表示
```

### 2. 取反公式

```java
// 对任意整数 x：~x = -x - 1
System.out.println(~5);     // -6 = -5 - 1
System.out.println(~0);     // -1 = -0 - 1
System.out.println(~-1);    // 0  = -(-1) - 1

// 应用：快速取相反数的相反数
int x = 42;
System.out.println(~(~x));  // 42
```

### 3. 位运算与逻辑运算的区别

```java
int a = 5;
int b = 3;

// 位运算：对补码的每一位操作
System.out.println(a & b);  // 1  （按位与）
System.out.println(a | b);  // 7  （按位或）
System.out.println(a ^ b);  // 6  （按位异或）
System.out.println(~a);     // -6 （按位取反）

// 注意：位运算的结果仍然是补码，直接解释为有符号整数
```

### 4. byte 的类型提升

```java
byte b = -1;            // 补码：11111111
int i = b;              // 符号扩展：11111111 11111111 11111111 11111111 = -1
int j = b & 0xFF;       // 零扩展：00000000 00000000 00000000 11111111 = 255

System.out.println(i);  // -1
System.out.println(j);  // 255  ✅ 获取无符号值
```

## 九、总结

### 核心要点

1. **原码**：最高位符号位 + 绝对值。直观但运算复杂，加减法需要判断符号。
2. **反码**：正数不变，负数符号位不变其余取反。统一了加减法，但存在 ±0 问题。
3. **补码**：正数不变，负数反码 + 1。**统一了加减法，消除了 ±0，是现代计算机的标准**。

### 为什么用补码？

| 优势 | 说明 |
| --- | --- |
| **统一运算** | 减法变加法：`A - B = A + (-B)`，一套加法电路搞定 |
| **零唯一** | 只有一种 0 的表示（`000...0`），没有 ±0 歧义 |
| **符号位参与运算** | 符号位不需要特殊处理，直接参与加法 |
| **范围对称** | 负数比正数多一个（多出的是最小值） |

### Java 相关记忆

- Java 整数**全部用补码**存储
- `~x = -x - 1`（按位取反等于取负减一）
- 负数补码的补码 = 原数的绝对值
- `Integer.MIN_VALUE` 没有对应的原码
- `byte` 转无符号用 `b & 0xFF`
