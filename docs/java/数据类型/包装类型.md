# 包装类型（Wrapper Classes）

> 📖 [Java API — `java.lang` Package](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/package-summary.html)

## 一、概述

Java 为每种基本类型提供了对应的**包装类**（Wrapper Class），将基本类型"包装"成对象，使其可以用于泛型、集合等需要对象的场景。

| 基本类型 | 包装类 | 父类 | 缓存池范围 |
| --- | --- | --- | --- |
| `byte` | `Byte` | `Number` | -128 ~ 127 |
| `short` | `Short` | `Number` | -128 ~ 127 |
| `int` | `Integer` | `Number` | -128 ~ 127（可配置） |
| `long` | `Long` | `Number` | -128 ~ 127 |
| `float` | `Float` | `Number` | 无 |
| `double` | `Double` | `Number` | 无 |
| `char` | `Character` | `Object` | 0 ~ 127 |
| `boolean` | `Boolean` | `Object` | `true` 和 `false` |

> 💡 **记忆要点：** 除了 `Integer` 和 `Character`，其他包装类名就是基本类型名首字母大写。

## 二、为什么需要包装类？

### 1. 基本类型的局限

基本类型**不是对象**，存在以下限制：

```java
// ❌ 基本类型不能用于泛型
// List<int> list = new ArrayList<>();  // 编译错误

// ❌ 基本类型不能放入集合
// Set<int> set = new HashSet<>();      // 编译错误

// ❌ 基本类型不能为 null
// int x = null;                        // 编译错误

// ❌ 基本类型没有方法
// int y = 123;
// y.toString();                        // 编译错误
```

### 2. 包装类解决了这些问题

```java
// ✅ 包装类可以用于泛型
List<Integer> list = new ArrayList<>();
list.add(1);
list.add(2);

// ✅ 包装类可以为 null（表示"未知"或"未设置"）
Integer age = null;

// ✅ 包装类有方法
String str = Integer.toString(123);     // "123"
int max = Integer.MAX_VALUE;            // 2147483647
```

## 三、自动装箱与自动拆箱

Java 5 引入了**自动装箱**（Autoboxing）和**自动拆箱**（Unboxing），编译器自动在基本类型和包装类之间转换。

### 1. 自动装箱（基本类型 → 包装类）

```java
// 手动装箱（Java 5 之前）
Integer old = new Integer(100);     // 已过时，不推荐
Integer old2 = Integer.valueOf(100);

// 自动装箱（Java 5+）
Integer autoboxed = 100;            // 编译器自动调用 Integer.valueOf(100)
```

### 2. 自动拆箱（包装类 → 基本类型）

```java
Integer obj = 100;

// 手动拆箱
int manual = obj.intValue();

// 自动拆箱
int auto = obj;                     // 编译器自动调用 obj.intValue()
```

### 3. 自动装箱/拆箱的应用场景

```java
// 集合操作
List<Integer> list = new ArrayList<>();
list.add(42);                       // 自动装箱：int → Integer
int value = list.get(0);            // 自动拆箱：Integer → int

// 算术运算
Integer a = 10;
Integer b = 20;
int sum = a + b;                    // 自动拆箱后运算

// 比较
Integer x = 100;
if (x > 50) {                       // 自动拆箱后比较
    System.out.println("大于 50");
}
```

## 四、缓存池机制

### 1. 缓存池原理

为了节省内存和提高性能，Java 对部分包装类使用了**缓存池**（Integer Cache）。使用 `valueOf()` 方法时，如果值在缓存范围内，会返回缓存对象而非新建对象。

```java
// 使用 valueOf()（推荐）
Integer a = Integer.valueOf(127);   // 从缓存池获取
Integer b = Integer.valueOf(127);   // 从缓存池获取（同一个对象）
System.out.println(a == b);         // true  ✅ 同一对象

// 自动装箱底层就是 valueOf()
Integer c = 127;                    // 等价于 Integer.valueOf(127)
Integer d = 127;
System.out.println(c == d);         // true  ✅

// 超出缓存范围
Integer e = 128;                    // 新建对象
Integer f = 128;                    // 新建对象（不同对象）
System.out.println(e == f);         // false  ❌ 不同对象
System.out.println(e.equals(f));    // true   ✅ 值相等
```

### 2. 各类型缓存池范围

| 包装类 | 缓存范围 | 说明 |
| --- | --- | --- |
| `Integer` | -128 ~ 127 | 可通过 `-XX:AutoBoxCacheMax` 调整上限 |
| `Short` | -128 ~ 127 | 固定 |
| `Long` | -128 ~ 127 | 固定 |
| `Byte` | -128 ~ 127 | 全部缓存（范围就是 -128~127） |
| `Character` | 0 ~ 127 | 固定 |
| `Boolean` | `true`、`false` | 全部缓存 |
| `Float` | 无缓存 | 浮点数不适合缓存 |
| `Double` | 无缓存 | 浮点数不适合缓存 |

### 3. 缓存池的 JVM 参数

```bash
# 调整 Integer 缓存池上限为 1024
java -XX:AutoBoxCacheMax=1024 MyApp
```

## 五、包装类常用方法

### 1. 类型转换方法

```java
// 字符串 → 基本类型
int i = Integer.parseInt("123");
double d = Double.parseDouble("3.14");
boolean b = Boolean.parseBoolean("true");

// 基本类型 → 字符串
String s1 = Integer.toString(123);       // "123"
String s2 = Integer.toBinaryString(10);  // "1010"
String s3 = Integer.toHexString(255);    // "ff"
String s4 = Integer.toOctalString(8);    // "10"

// 进制转换
String binary = Integer.toString(10, 2);  // "1010"
String hex = Integer.toString(255, 16);   // "ff"
```

### 2. 常量字段

```java
System.out.println(Integer.SIZE);        // 32（位数）
System.out.println(Integer.BYTES);       // 4（字节数）
System.out.println(Integer.MIN_VALUE);   // -2147483648
System.out.println(Integer.MAX_VALUE);   // 2147483647

System.out.println(Double.POSITIVE_INFINITY);  // Infinity
System.out.println(Double.NaN);                // NaN
```

### 3. 比较方法

```java
// 包装类之间的比较（推荐）
Integer a = 100;
Integer b = 200;
System.out.println(a.compareTo(b));  // -1（a < b）

// 无符号比较
Integer.compareUnsigned(-1, 1);      // 1（无符号时 -1 很大）

// 判断
Double.isNaN(Double.NaN);            // true
Double.isInfinite(1.0 / 0.0);        // true
Double.isFinite(3.14);               // true
```

## 六、常见陷阱

### 1. == 与 equals 的陷阱 ⭐ 高频考点

```java
// 缓存池内：== 返回 true
Integer a = 100;
Integer b = 100;
System.out.println(a == b);      // true

// 缓存池外：== 返回 false
Integer c = 200;
Integer d = 200;
System.out.println(c == d);      // false  ⚠️
System.out.println(c.equals(d)); // true   ✅

// 混合比较：自动拆箱
Integer e = 200;
int f = 200;
System.out.println(e == f);      // true  ✅ e 自动拆箱为 int

Integer g = 200;
long h = 200;
// System.out.println(g == h);   // g 自动拆箱为 int，然后提升为 long → true
```

> ⚠️ **最佳实践：** 包装类比较**始终使用 `equals()`**，不要用 `==`。

### 2. null 拆箱导致 NullPointerException

```java
Integer count = null;
// int value = count;            // ❌ NullPointerException！拆箱时调用 null.intValue()

// ✅ 安全做法
if (count != null) {
    int value = count;
}

// ✅ 或提供默认值
int safe = (count != null) ? count : 0;
```

### 3. 性能问题

自动装箱/拆箱虽然方便，但在**循环和大量数据**场景下会产生性能开销：

```java
// ❌ 性能差：每次循环都装箱/拆箱
Integer sum = 0;
for (int i = 0; i `  10000; i++) {
    sum += i;  // 拆箱 → 运算 → 装箱，每次循环都创建 Integer 对象
}

// ✅ 性能好：全程使用基本类型
int sum2 = 0;
for (int i = 0; i `  10000; i++) {
    sum2 += i;
}
```

### 4. 构造函数已过时

```java
// ❌ 过时写法（Java 9+ 标记为 @Deprecated）
Integer old = new Integer(100);

// ✅ 推荐写法
Integer modern = Integer.valueOf(100);
Integer autoboxed = 100;  // 自动装箱，底层调用 valueOf()
```

> 💡 **为什么推荐 `valueOf()`？** 因为 `valueOf()` 会利用缓存池，`new Integer()` 总是创建新对象。

## 七、包装类与集合

包装类最常见的用途就是配合集合和泛型使用：

```java
// List 存储整数
List<Integer> numbers = Arrays.asList(1, 2, 3, 4, 5);
int sum = 0;
for (int n : numbers) {  // 自动拆箱
    sum += n;
}

// Map 存储键值对
Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 95);
scores.put("Bob", 87);
int aliceScore = scores.get("Alice");  // 自动拆箱

// Set 去重
Set<Integer> unique = new HashSet<>(Arrays.asList(1, 2, 2, 3));
System.out.println(unique);  // [1, 2, 3]
```

## 八、包装类与数据库

在 ORM 框架（如 MyBatis、JPA）中，包装类常用于表示**可能为 NULL 的数据库字段**：

```java
public class User {
    private Integer age;        // 包装类，可以为 null（数据库字段可能为空）
    private String name;

    // 如果用 int，数据库 NULL 会被转为 0，无法区分"未填写"和"年龄为 0"
}
```

> 💡 **最佳实践：** 数据库实体类的字段类型优先使用包装类，因为数据库字段可能为 NULL，而基本类型不能为 null。

## 九、总结

| 要点 | 说明 |
| --- | --- |
| **为什么需要** | 基本类型不能用于泛型、集合，不能为 null |
| **自动装箱** | 基本类型 → 包装类，编译器自动调用 `valueOf()` |
| **自动拆箱** | 包装类 → 基本类型，编译器自动调用 `xxxValue()` |
| **缓存池** | `Integer` 缓存 -128~127，`Byte`/`Boolean` 全部缓存 |
| **比较用 equals** | 包装类不要用 `==`，用 `equals()` |
| **null 拆箱** | 包装类为 null 时拆箱会抛 `NullPointerException` |
| **性能敏感场景** | 大量数据运算用基本类型，避免装箱/拆箱开销 |
| **数据库字段** | 实体类优先用包装类，支持 NULL 语义 |
