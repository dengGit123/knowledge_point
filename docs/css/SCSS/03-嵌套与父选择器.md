# SCSS 嵌套与父选择器

> 📖 官方文档：[Sass Style Rules](https://sass-lang.com/documentation/style-rules/)
>
> 📖 官方文档：[Sass Parent Selector](https://sass-lang.com/documentation/style-rules/parent-selector/)

### 一、概述

**嵌套是 SCSS 最直观的提效特性**：把子选择器写在父选择器内部，编译时自动拼接成完整选择器。它让 CSS 结构和 HTML 结构保持一致，不再需要一遍遍重复 `.nav ul li a` 这样的前缀。

配合**父选择器 `&`**，还能优雅地处理伪类、BEM 命名等场景。

### 二、选择器嵌套

#### 1. 基本嵌套

```scss
// SCSS 写法
nav {
  ul {
    margin: 0;
    padding: 0;
    list-style: none;
  }
  li {
    display: inline-block;
  }
  a {
    display: block;
    padding: 6px 12px;
    text-decoration: none;
  }
}
```

编译结果：

```css
nav ul {
  margin: 0;
  padding: 0;
  list-style: none;
}
nav li {
  display: inline-block;
}
nav a {
  display: block;
  padding: 6px 12px;
  text-decoration: none;
}
```

> 💡 **提示：** 嵌套默认用**后代选择器**（空格）连接内外选择器。

#### 2. 选择器列表（逗号分隔）

外层或内层是逗号分隔的选择器列表时，编译会做**两两组合**：

```scss
.alert, .warning {
  ul, p {
    margin: 0;
  }
}
```

```css
/* 编译结果：4 个组合 */
.alert ul, .alert p, .warning ul, .warning p {
  margin: 0;
}
```

#### 3. 组合器（`>`、`+`、`~`）的嵌套

子选择器、相邻兄弟、通用兄弟组合器可以写在内层开头，也可以挂在中间：

```scss
ul > {
  li {
    list-style: none;
  }
}

h2 {
  + p {           /* h2 的下一个相邻兄弟 p */
    border-top: 1px solid gray;
  }
}

p {
  ~ {
    span {        /* p 之后的所有同级 span */
      opacity: 0.8;
    }
  }
}
```

> 💡 **提示：** 实际开发中推荐只把组合器写在**内层选择器的开头**（如 `> li { }`），可读性最好。

#### 4. 属性嵌套

同一前缀的属性（`font-family`、`font-size`…）可以嵌套省略公共前缀，**属性名后跟冒号**即开启嵌套：

```scss
.enlarge {
  font: {
    family: "Raleway", sans-serif; // → font-family
    size: 14px;                    // → font-size
    weight: bold;                  // → font-weight
  }
  border: 1px solid red {
    left: none;    // → border-left: none（先输出简写再输出具体项）
    radius: 5px;   // → border-radius: 5px
  }
}
```

```css
.enlarge {
  font-family: "Raleway", sans-serif;
  font-size: 14px;
  font-weight: bold;
  border: 1px solid red;
  border-left: none;
  border-radius: 5px;
}
```

> ⚠️ **注意：** 属性嵌套语法（`font: { ... }`）在 Dart Sass 新版本中属于**已废弃特性**（现代 CSS 嵌套不支持它），官方迁移工具会把它转换为完整属性名写法。老代码能看到、能认得即可，**新代码不要再写**，直接写全名更稳妥。

### 三、父选择器 `&`

`&` 代表**外层（父级）选择器**，编译时会被替换成父选择器的完整内容。

#### 1. 基本用法：伪类/伪元素

```scss
.button {
  color: blue;
  &:hover {           // → .button:hover
    color: red;
  }
  &::before {         // → .button::before
    content: "";
  }
}
```

#### 2. `&` 不在最前面：限定上下文

`&` 不必总写在开头，它可以出现在内层选择器的**中间或末尾**，实现"给父级套一层上下文"：

```scss
.button {
  .sidebar & {          // → .sidebar .button（侧边栏内的按钮）
    font-size: 12px;
  }
  &.is-disabled {       // → .button.is-disabled（同一元素双类）
    opacity: 0.5;
  }
}
```

官方文档的经典示例——三种位置一次看全：

```scss
.alert {
  // 伪类
  &:hover {
    font-weight: bold;        // → .alert:hover
  }
  // 父级出现在复合选择器中间（限定祖先）
  [dir=rtl] & {
    margin-left: 0;           // → [dir=rtl] .alert
    margin-right: 10px;
  }
  // & 作为伪类的参数
  :not(&) {
    opacity: 0.8;             // → :not(.alert)
  }
}
```

> ⚠️ **注意：** `&` 只能出现在**复合选择器允许放类型选择器的位置**（因为 `&` 可能被替换成 `h1` 这样的类型选择器）。也就是说 `span&`（标签紧跟 `&`）是不允许的写法。想表达各种组合关系，参考下面：

- `.alert` 内写 `span { }` → 输出 `.alert span`（后代）
- `&.is-active` → 输出 `.alert.is-active`（同元素复合，`&` 在最前 ✅）
- 想生成 `.alert span` 这种"类 + 标签"的**合并复合选择器** → 用 `@at-root` + `selector.unify()`（见 [10-插值与@at-root](./10-插值与@at-root.md)）

#### 3. BEM 后缀（最实用的场景）

`&` 后面可以直接**拼接文本**，生成 `.block__element`、`.block--modifier`：

```scss
.accordion {
  width: 90%;

  &__copy {           // → .accordion__copy
    color: gray;
    display: none;

    &--open {         // → .accordion__copy--open（嵌套中的 & 指向最近一层）
      display: block;
    }
  }
}
```

> ⚠️ **注意：** 后缀拼接要求**外层选择器以字母或数字结尾**（类名、ID、标签名可以；`[attr]`、伪类结尾的不行）。另外 `&` 一次只能指代**最近一层**父选择器。

#### 4. `&` 在 SassScript 中（进阶）

`&` 也可以作为表达式使用，返回当前父选择器（列表结构）；在样式规则外使用时返回 `null`。配合 `@at-root` 和选择器函数可以动态生成选择器：

```scss
@use "sass:selector";

// 用 mixin 生成 ".wrapper input.field" 这样的统一选择器
@mixin unify-parent($child) {
  @at-root #{selector.unify(&, $child)} {
    @content;
  }
}

.wrapper .field {
  @include unify-parent("input") { /* 样式 */ } // → .wrapper input.field
}
```

此用法较少，知道即可，详见 [06-控制指令(@if,@each,@for)](./06-控制指令%28@if,@each,@for,@while%29.md) 与官方 selector 模块文档。

#### 5. 顶层裸用 `&`

Dart Sass 1.100.0 起支持在**非嵌套**位置写 `&`，它会被原样输出为 CSS 原生嵌套的作用域根（配合 CSS 原生嵌套使用），日常项目用得少。

### 四、占位符选择器 `%`

以 `%` 开头的选择器叫**占位符选择器**，本身**不会输出到 CSS**，只有被 `@extend` 继承时其样式才会生效：

```scss
%button-base {
  padding: 8px 16px;
  border: none;
  cursor: pointer;
}

.button-primary { @extend %button-base; background: blue; }
.button-danger  { @extend %button-base; background: red; }
```

```css
/* 编译结果：%button-base 本身不输出，两个类共享一份样式 */
.button-primary, .button-danger {
  padding: 8px 16px;
  border: none;
  cursor: pointer;
}
.button-primary { background: blue; }
.button-danger { background: red; }
```

详见 [05-继承(@extend)与占位符](./05-继承%28@extend%29与占位符.md)。

### 五、实际应用场景

```scss
// 场景一：组件内部状态全覆盖
.card {
  background: #fff;
  &:hover { box-shadow: 0 2px 8px rgba(0, 0, 0, 0.15); }
  &:active { transform: scale(0.98); }
  &:focus-visible { outline: 2px solid blue; }
  &.is-disabled { opacity: 0.5; pointer-events: none; }
}

// 场景二：BEM 命名规范
.block {
  &__element { ... }
  &--modifier { ... }
}

// 场景三：主题上下文
.button {
  .dark-theme & { background: #333; } // 深色主题下的按钮
  [data-rtl] & { direction: rtl; }    // RTL 布局下
}
```

### 六、常见问题与注意事项

1. **不要过度嵌套（最重要）**：嵌套越深，生成的选择器越长，浏览器匹配开销越大，样式也越难被覆盖。**建议不超过 3~4 层**。

   ```scss
   // ❌ 反面教材：生成 .nav ul li a span 这样脆弱的选择器
   .nav { ul { li { a { span { ... } } } } }

   // ✅ 好的实践：拍平
   .nav { li a span { ... } }
   ```

2. **嵌套可能"锁死"选择器优先级**：长选择器特异性高，后期想覆盖得写更长的选择器或上 `!important`，形成恶性循环。

3. **`&` 与 BEM 拼接时注意空格**：`&__copy`（无空格）是拼接，`& __copy`（有空格）是嵌套子元素，含义完全不同。

4. **同名嵌套冲突**：如果内层选择器和外层生成了相同选择器（如 `.a { .a { ... } }`），编译为 `.a .a`——注意这不是覆盖而是后代选择器。

5. **选择器中的插值**：`#{}` 可以用在选择器里动态生成类名（常见于 mixin），Sass 会在插值解析后再解析整个选择器。

### 七、总结

- 嵌套自动拼接选择器，默认是后代选择器；组合器（`>` `+` `~`）可显式控制关系
- `&` = 父选择器：伪类伪元素（`&:hover`）、BEM 拼接（`&__elem`）、上下文限定（`.dark &`）
- 属性嵌套（`font: { ... }`）已废弃，新代码写全名
- `%` 占位符选择器不输出 CSS，专供 `@extend` 使用
- 核心纪律：**保持选择器浅显**，嵌套是手段不是目的
