# SCSS 最佳实践与常见坑

> 📖 官方文档：[Sass Documentation](https://sass-lang.com/documentation/)
>
> 📖 官方迁移指南：[Sass Migrator](https://sass-lang.com/documentation/cli/migrator/)

### 一、概述

前面各篇讲了语法，本篇汇总**工程实战角度**的经验：目录组织、7-1 架构、命名约定、性能与体积意识、以及新手最容易踩的坑。可作为写 SCSS 时的"code review 清单"使用。

### 二、目录组织：7-1 架构

社区广泛采用的 SCSS 目录结构（数字前缀保证编译顺序）：

```
styles/
├── abstracts/              # ① 抽象层：不输出任何 CSS
│   ├── _variables.scss     #    变量
│   ├── _mixins.scss        #    混入
│   ├── _functions.scss     #    函数
│   └── _index.scss         #    @forward 统一导出
├── vendors/                # ② 第三方库样式覆盖
│   └── _element-plus.scss
├── base/                   # ③ 基础层：reset、全局基础样式
│   ├── _reset.scss
│   ├── _typography.scss
│   └── _animations.scss
├── layout/                 # ④ 布局：页面骨架
│   ├── _header.scss
│   ├── _footer.scss
│   └── _grid.scss
├── components/             # ⑤ 组件：与 UI 组件对应
│   ├── _button.scss
│   └── _card.scss
├── pages/                  # ⑥ 页面：页面级专属样式
│   └── _home.scss
├── themes/                 # ⑦ 主题
│   └── _dark.scss
└── main.scss               # 入口：只做 @use，不放具体样式
```

```scss
// main.scss —— 入口只负责组装
@use "abstracts";      // 变量、mixin（供下游使用）
@use "base";
@use "layout";
@use "components";
@use "pages";
@use "themes";
```

> 💡 **提示：** 小项目不必教条套 7 层，合并成 `abstracts / base / components` 三层即可；关键是**"不产 CSS 的"和"产 CSS 的"文件分开放**，入口只做组装。

### 三、最佳实践清单

#### 1. 变量：语义化命名 + 分层管理

```scss
// ✅ 语义化：看名字知道用途
$color-primary: #409eff;
$color-text-secondary: #909399;
$spacing-card-padding: 16px;

// ❌ 具体值命名：换主题时要改所有变量
$blue: #409eff;
$gray-3: #909399;
```

变量一律加 `!default`（尤其库和公共配置），方便下游覆盖：

```scss
$color-primary: #409eff !default;
```

#### 2. 嵌套：保持浅层

```scss
// ✅ 推荐：2~3 层封顶
.card {
  .title { ... }
  &:hover { ... }
}

// ❌ 危险：生成 .nav > ul li a span.active，特异性高、难覆盖
.nav {
  > ul {
    li {
      a {
        span.active { ... }
      }
    }
  }
}
```

#### 3. mixin / extend / 函数的选择

| 需求 | 选择 |
| --- | --- |
| 复用一段可配置的样式 | mixin |
| 表达"X 是一种 Y"的语义继承 | `@extend` + `%placeholder` |
| 计算并返回一个值 | `@function` |
| 批量生成类名 | `@each`/`@for` + mixin |

#### 4. 用 map 集中管理配置

```scss
// 所有"枚举式"的值都收进 map，配 @each 批量生成
$z-index: ("modal": 400, "overlay": 300, "dropdown": 100);
$breakpoints: ("sm": 640px, "md": 960px, "lg": 1280px);
$font-weights: ("regular": 400, "bold": 700);
```

好处：加一档配置 = 加一行；所有同类的值集中可见，避免散落各处的魔法数字。

#### 5. 统一用新语法（2026 年的现代标准）

| 废弃写法 | 现代写法 |
| --- | --- |
| `@import 'x'` | `@use 'x'` / `@forward 'x'` |
| `$a / $b` | `math.div($a, $b)` |
| `lighten($c, 10%)` / `darken($c, 10%)` | `color.adjust($c, $lightness: 10%)` |
| `map-get($m, $k)` | `map.get($m, $k)` |
| `nth($l, $i)` | `list.nth($l, $i)` |
| `font: { size: 14px }`（属性嵌套） | 直接写 `font-size: 14px` |

### 四、常见坑（高频翻车点）

#### 坑 1：把会输出 CSS 的文件注入 additionalData

```scss
// ❌ global.scss 里有普通样式规则
$primary: red;
body { margin: 0; } // 每个组件都会复制一份 body 规则！

// ✅ 注入文件只放变量、mixin、函数
$primary: red;
@mixin card { ... }
```

#### 坑 2：用插值给数字拼单位

```scss
$num: 16;
// ❌ #{$num}px 是字符串，不能运算
// ✅
$num * 1px;
```

#### 坑 3：`0` 当假值用

```scss
$level: 0;
// ❌ Sass 里 0 是 truthy，@if $level 不会跳过
@if $level != 0 { ... } // ✅ 显式比较
```

#### 坑 4：mixin 与 CSS `min()`/`max()` 撞名

自定义了 `@function min(...)` 后，CSS 的 `min()` 会被 Sass 拦截改写，可能破坏原意。**自定义函数名加项目前缀**（如 `tu-min`）。

#### 坑 5：`@extend` 的级联位置

```scss
.a { color: red; }        // 被扩展的规则在这里
.b { @extend .a; }        // b 的样式来自上面那条规则的位置
.c { color: red; }        // 想覆盖 .b 的 color？取决于 .c 和 .a 的先后
```

`@extend` 合并的选择器优先级按**被扩展规则的位置**算，覆盖样式时容易出乎意料——这也是"mixin 优先"的理由之一。

#### 坑 6：循环生成海量 CSS

```scss
// ❌ 1000 个类、每个 5 条规则
@for $i from 1 through 1000 {
  .mt-#{$i} { margin-top: $i * 1px; }
}
```

产物体积与编译时间都会膨胀。工具类按需生成常用档位（如 4/8/12/16/24），或考虑运行时方案（CSS 变量 + `style` 属性）。

#### 坑 7：@use 写在样式规则后面

```scss
.card { ... }
@use "variables"; // ❌ 报错：@use 必须在文件最前（@forward 除外）
```

#### 坑 8：URL 大小写不一致导致重复加载

`@use "Variables"` 与 `@use "variables"` 被视为两个模块，样式输出两份。保持与文件名一致。

### 五、性能与体积意识

1. **产物体积**：`@include` 是复制、`@extend` 是合并选择器，但 gzip 之后差异微乎其微——**按可维护性选型**，不为省字节牺牲清晰度。
2. **编译速度**：巨型 `@mixin` + 深循环会拖慢编译；Vite 下 SCSS 是同步编译的，大项目可拆分入口按需编译。
3. **运行时性能**：选择器越短越通用，浏览器匹配越快；避免生成 `.a .b .c .d .e` 长链。
4. **sourcemap**：开发环境开启 sourcemap，定位样式来源事半功倍（Vite 默认开启）。

### 六、Code Review 自查清单

- [ ] 嵌套是否 ≤ 3 层？有没有生成超长选择器？
- [ ] 变量是否语义化命名？公共变量是否加了 `!default`？
- [ ] 是否还在用 `@import`、`/` 除法、`darken()` 等废弃语法？
- [ ] 魔法数字是否收进了 map 或变量？
- [ ] mixin 里是否有应该抽成 `@function` 的纯计算？
- [ ] `@use` 是否都在文件顶部？有没有循环依赖？
- [ ] 工具类是否被循环批量生成了过多冗余规则？
- [ ] 调试用的 `@debug` 是否已删除？

### 七、总结

- 目录上"抽象与产出分离"，入口只做组装；小项目三层足够
- 命名语义化、配置 map 化、语法现代化（`@use`/`math.div`/`color.adjust`）
- 高频坑集中在：插值拼单位、`0` 的真值、extend 级联、注入文件带产出、循环生成海量类
- 把"可维护性"放在"产物体积"之前——gzip 会平掉大部分复制差异
