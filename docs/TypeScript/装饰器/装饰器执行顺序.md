# 装饰器执行顺序

## 一、概述

当多个装饰器应用于同一个声明，或者同一个类上有多个装饰器时，理解执行顺序至关重要。装饰器的执行遵循特定的规则。

## 二、同一声明的多个装饰器

当多个装饰器应用于同一个方法、属性或类时，执行顺序遵循：

> **工厂函数从上到下，装饰器函数从下到上**

### 示例

```typescript
function First() {
  console.log('First: 工厂函数');
  return function (target: any, propertyKey: string, descriptor?: PropertyDescriptor) {
    console.log('First: 装饰器函数');
  };
}

function Second() {
  console.log('Second: 工厂函数');
  return function (target: any, propertyKey: string, descriptor?: PropertyDescriptor) {
    console.log('Second: 装饰器函数');
  };
}

function Third() {
  console.log('Third: 工厂函数');
  return function (target: any, propertyKey: string, descriptor?: PropertyDescriptor) {
    console.log('Third: 装饰器函数');
  };
}

class Example {
  @First()
  @Second()
  @Third()
  method() {}
}
```

### 输出结果

```
First: 工厂函数
Second: 工厂函数
Third: 工厂函数
Third: 装饰器函数
Second: 装饰器函数
First: 装饰器函数
```

### 图解

```
@First()     ← 工厂函数最先调用 ← 装饰器函数最后调用
@Second()    ← 工厂函数第二调用 ← 装饰器函数第二调用
@Third()     ← 工厂函数最后调用 ← 装饰器函数最先调用
method() {}
```

这类似于**函数组合**（function composition）或**洋葱模型**——先进后出。

## 三、同一类的不同类型装饰器

当一个类及其成员都有装饰器时，执行顺序遵循：

> **参数装饰器 → 方法/属性/访问符装饰器 → 类装饰器**

### 示例

```typescript
function ClassDecorator(constructor: Function) {
  console.log('类装饰器');
}

function MethodDecorator(target: any, key: string, descriptor: PropertyDescriptor) {
  console.log('方法装饰器');
}

function PropertyDecorator(target: any, key: string) {
  console.log('属性装饰器');
}

function AccessorDecorator(target: any, key: string, descriptor: PropertyDescriptor) {
  console.log('访问符装饰器');
}

function ParameterDecorator(target: any, key: string, index: number) {
  console.log(`参数装饰器 (索引: ${index})`);
}

@ClassDecorator
class Example {
  @PropertyDecorator
  prop!: string;

  @AccessorDecorator
  get value() { return 1; }

  @MethodDecorator
  method(@ParameterDecorator a: string, @ParameterDecorator b: number) {}
}
```

### 输出顺序

```
参数装饰器 (索引: 1)  ← 参数的装饰器，从后往前
参数装饰器 (索引: 0)  ← 参数的装饰器，从后往前
属性装饰器           ← 属性装饰器
访问符装饰器         ← 访问符装饰器
方法装饰器           ← 方法装饰器
类装饰器             ← 类装饰器最后执行
```

### 完整执行顺序规则

```
1. 参数装饰器（Parameter Decorator）：从最后一个参数到第一个参数
2. 属性装饰器（Property Decorator）
3. 访问符装饰器（Accessor Decorator）
4. 方法装饰器（Method Decorator）
5. 类装饰器（Class Decorator）
```

## 四、综合示例

```typescript
function Log(name: string) {
  console.log(`[工厂] ${name}`);
  return function (...args: any[]) {
    console.log(`[装饰器] ${name}`);
  };
}

@Log('类')
class MyClass {
  @Log('静态属性')
  static staticProp: string = '';

  @Log('实例属性')
  instanceProp: string = '';

  @Log('静态访问符')
  static get staticAccessor() { return 1; }

  @Log('实例访问符')
  get instanceAccessor() { return 1; }

  constructor(@Log('构造参数') x: number) {}

  @Log('静态方法')
  static staticMethod(@Log('静态方法参数') x: string) {}

  @Log('实例方法')
  instanceMethod(@Log('实例方法参数1') x: string, @Log('实例方法参数2') y: number) {}
}
```

### 输出结果

```
[工厂] 类
[工厂] 静态属性
[工厂] 实例属性
[工厂] 静态访问符
[工厂] 实例访问符
[工厂] 构造参数
[工厂] 静态方法
[工厂] 静态方法参数
[工厂] 实例方法
[工厂] 实例方法参数2
[工厂] 实例方法参数1
[装饰器] 实例方法参数1
[装饰器] 实例方法参数2
[装饰器] 实例方法
[装饰器] 静态方法参数
[装饰器] 静态方法
[装饰器] 构造参数
[装饰器] 实例访问符
[装饰器] 静态访问符
[装饰器] 实例属性
[装饰器] 静态属性
[装饰器] 类
```

### 分析

1. **工厂函数阶段**：从上到下依次调用所有装饰器的工厂函数
2. **装饰器函数阶段**：从下到上依次调用所有装饰器的装饰器函数
3. 同一方法内的参数装饰器：从右到左（从后往前）

## 五、为什么是这个顺序？

### 1. 工厂函数从上到下

工厂函数只是"准备"装饰器，不涉及实际的目标对象操作，所以按照书写顺序执行：

```typescript
@First()  // 先准备 First 装饰器
@Second() // 再准备 Second 装饰器
method() {}
```

### 2. 装饰器函数从下到上

装饰器函数从下到上执行，确保**最内层的装饰器最先应用**，外层装饰器包裹内层：

```typescript
@A()  // 外层：最后应用，最先执行
@B()  // 内层：最先应用，最后执行
method() {}

// 执行顺序：B 装饰器 → A 装饰器
// 效果：A(B(method))
```

### 3. 参数装饰器从后往前

参数装饰器从最后一个参数开始，避免索引变化的影响：

```typescript
function deco(target: any, key: string, index: number) {
  console.log(`参数索引: ${index}`);
}

class Example {
  method(
    @dec a: string,  // index: 0
    @dec b: number,  // index: 1
    @dec c: boolean  // index: 2
  ) {}
}
// 输出：2, 1, 0（从后往前）
```

## 六、实际应用中的顺序影响

### 1. 权限验证 + 日志

```typescript
function RequireAuth(role: string) {
  return function (target: any, key: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = function (...args: any[]) {
      // 先执行权限检查
      if (!checkPermission(role)) {
        throw new Error('无权限');
      }
      return original.apply(this, args);
    };
  };
}

function Log(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`调用 ${key}`);
    return original.apply(this, args);
  };
}

class AdminService {
  @RequireAuth('admin')  // 外层：最后应用
  @Log                   // 内层：最先应用
  deleteUser(userId: string) {
    return `删除用户 ${userId}`;
  }
}

// 执行流程：
// 1. 先应用 @Log（内层）
// 2. 再应用 @RequireAuth（外层）
// 3. 调用时：先检查权限 → 记录日志 → 执行方法
```

### 2. 缓存 + 验证

```typescript
function Validate(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    // 先验证参数
    if (!args[0]) throw new Error('参数无效');
    return original.apply(this, args);
  };
}

function Cache(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  const cache = new Map();
  descriptor.value = function (...args: any[]) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    // 验证会在执行 original 时触发
    const result = original.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

class DataService {
  @Cache     // 外层：最后应用
  @Validate  // 内层：最先应用
  fetchData(id: string) {
    return `数据 ${id}`;
  }
}

// 调用流程：
// 1. Cache 检查缓存
// 2. 未命中则调用原始方法（已被 Validate 包装）
// 3. Validate 验证参数
// 4. 执行原始方法
// 5. 缓存结果
```

## 七、静态成员 vs 实例成员

```typescript
function Log(name: string) {
  return function (...args: any[]) {
    console.log(name);
  };
}

@Log('类')
class Example {
  @Log('静态属性')
  static staticProp!: string;

  @Log('实例属性')
  instanceProp!: string;

  @Log('静态方法')
  static staticMethod() {}

  @Log('实例方法')
  instanceMethod() {}
}
```

### 执行顺序

```
实例属性      ← 实例成员先
实例方法      ←
静态属性      ← 静态成员后
静态方法      ←
类           ← 类装饰器最后
```

## 八、总结

### 执行顺序速记

| 场景 | 顺序 |
|-----|------|
| 同一声明的多个装饰器工厂 | 从上到下 |
| 同一声明的多个装饰器函数 | 从下到上 |
| 同一方法的多个参数装饰器 | 从右到左 |
| 不同类型装饰器（同一类） | 参数 → 属性/访问符/方法 → 类 |
| 实例成员 vs 静态成员 | 实例成员先，静态成员后 |

### 记忆口诀

> **工厂从上到下，装饰从下到上，参数从右到左，类装饰最后执行**
